# Частичные баллы ЕГЭ по физике

Статус: завершено локально. Без commit/push/deploy.

## Цель и границы

Явное правило в grading пакета v1 для соответствий и выбора утверждений; один серверный оценщик для preview и завершения попытки. Тип и правило видны в существующем disclosure «Источник и сведения». Старые пакеты/версии/назначения и завершённые результаты не переписываются, новых миграций не требуется.

## Контракт и решения

- grading.policy необязателен, без schema default: отсутствие остаётся отсутствием и не меняет прежний hash импорта. exact — прежнее поведение. ege_physics_matching_v1 / ege_physics_multiple_choice_v1 включаются только явно, имеют максимум 2 балла; matching требует две позиции, multiple_choice — 2 или 3 верных варианта.
- Правила сверены с демоверсией ФИПИ-2026, печатная стр. 19 ([PDF-копия](https://vpr-ege.ru/z6/ege26-fi-demo.pdf#page=10)), и [официальными рекомендациями ФИПИ-2026](https://doc.fipi.ru/navigator-podgotovki/navigator-ege/MR_fizika_ege_2026.pdf), стр. 11. Опубликованный проект 2027 не выдаётся за проверенную финальную норму.
- У matching сравниваются именованные позиции; пустая позиция в структурированном вводе приложения считается ошибочной позицией. Для набора утверждений одна замена, одно добавление или один пропуск дают 1; расстояние до набора = max(пропущено, лишних). Порядок не учитывается.
- Полностью верные / частичные / нулевые результаты различаются. partialCount выводится из числа автоматических задач и сохранённых correctCount/incorrectCount, без повторной оценки старых ответов. Баллы берутся из сохранённого points.
- Новый guide/example не импортируется автоматически в пользовательский банк; применение нового policy даёт новую версию при обычном импорте, старые work snapshots сохраняются.

## Порядок и проверки

1. Strict policy schema и ограничения, сохранность legacy JSON/hashes, матрица баллов.
2. Общий оценщик, классификация результата и read DTO без пересчёта завершённых попыток.
3. Банк/preview/student UI в существующих местах, без дополнительных переключателей ученику.
4. Образец ZIP и гайд агенту, docs; shared/API/web и HTTP/БД проверки pinned versions, повторов, экспорта/импорта и изоляции; desktop/mobile UI.

## Риски и откат

Нельзя включать policy по maxPoints, названию источника или номеру ЕГЭ. Нельзя вставлять default в сохранённые задания или пересчитывать прежние points/counters. Откат ограничен файлами этой работы, остальные локальные изменения сохраняются.

## Прогресс

- Добавлены необязательные versioned policy, общий серверный оценщик и совместимые DTO результата. Полные и нулевые ответы считаются отдельно; промежуточный результат не записывается как полностью верный. Новых миграций и пересчёта прежних попыток нет.
- По уточнению пользователя выводится только «Баллы: X из Y», без «Частично верно». Полный результат зелёный, промежуточный тёмно-янтарный, нулевой красный. Цвет сопровождает число и не заменяет его.
- Тип и правило находятся в прежнем «Источник и сведения». Обновлены SoR и гайд агенту; подготовлены исходники `examples/assessment-package/ege-v1/` и ZIP `output/assessment-package-ege-v1.zip`. Пользовательский банк автоматически не обновлялся.
- Проверено: shared 49 тестов, API unit 84, HTTP integration 22 (назначения, работы, фото); web 184. API typecheck/build в Docker; web typecheck и production build Webpack; boundaries, scoped ESLint и docs:check прошли.
- HTTP-проверка подтверждает: прежний завершённый результат и незавершённое старое назначение сохраняют exact; новый импорт создаёт v2 с policy; preview и новая попытка дают одинаковые частичные баллы; повторы завершения стабильны, экспорт/повторный импорт не меняют данные, студент не получает ключи и grading.
- Встроенный браузер: desktop 1280 и mobile 390, сведения помещаются без горизонтальной прокрутки. Пробная проверка реальной старой работы показывает зелёные 2 из 2 и красные 0 из 2 без записи ответов. Янтарный частичный результат покрыт component/API/HTTP-тестами; для его пользовательского просмотра нужен явный импорт нового пакета и новая версия работы.
