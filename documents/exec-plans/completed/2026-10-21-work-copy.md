# UX-06. Независимая копия работы

Статус: Completed (локально). Дата: 2026-10-21.

## Цель и границы

Одну работу по-прежнему можно назначать нескольким классам. Копия нужна только для отдельного изменения состава/порядка/инструкции. Добавить «Создать копию» в меню строки списка работ; открыть новый черновик сразу, без промежуточного диалога. Существующие несвязанные изменения working tree сохранить. Commit/push/deploy не входят.

## Решения

- Копируется текущий сохранённый черновик, не произвольная историческая редакция и не несохранённый ввод редактора. Точная ревизия передаётся из списка; устаревший список возвращает конфликт и обновляется.
- Копируются название с « — копия» (до 200 символов), параллель, инструкция, порядок и закреплённые версии задач. Новая работа имеет ревизию 1; версии, назначения, ответы, фото и рецензии не переносятся. Рисунки используют существующие защищённые версии банка, не дублируются в S3.
- По уточнению пользователя удалённые/отсутствующие в банке задачи пропускаются. Порядок оставшихся сохраняется; если не осталось ни одной, создаётся пустой черновик. В редакторе копии показано число пропущенных задач. Не подменять закреплённые версии актуальными.
- `POST /teacher/assessment-works/:id/copy`: строгий body `{ id, expectedRevision }`, teacher/owner/Origin. `id` — ID новой работы и ключ безопасного повтора. Nullable поля `copiedFromId`/`copiedFromRevision` сохраняют происхождение и проверку повтора даже после редактирования копии; `copySkippedTaskCount` сохраняет исходное число пропусков. Без FK: будущая очистка исходного черновика не должна удалять копию. Это аддитивная миграция без backfill.
- Блокировки преподавателя → источника согласованы с удалением банка и записью состава. Повтор возвращает ту же работу без нового исключения задач, конфликт ID/параметров не открывает чужие данные. При неизвестном результате UI повторяет прежний payload; во время запроса действие блокируется, ошибка остаётся у строки.
- Impeccable: существующее Radix-меню, белый плотный список и минимум акцентов; никаких новых вкладок или карточек.

## Шаги и приёмка

1. Shared-контракт, миграция и атомарный API: оригинал неизменен, порядок/версии/суммы сохранены, назначений у копии нет.
2. Действие `⋯`, loading/error/retry, переход в новый редактор; клавиатура и мобильная геометрия.
3. Тесты: права/Origin/body, конфликт ревизии/ID, конкурентный повтор, повтор после правки копии, удалённый банк, исторические версии/рисунки, пустая работа/длинное название. Component-тесты повторного запроса, блокировки, ошибки и перехода.
4. Shared/web tests, boundaries/typecheck/build, API tests/typecheck/build только Docker, docs generate/check и diff check. SoR и roadmap обновить после проверки.

## Риски и rollback

Не менять существующий create/update и UX-01. Провести локальную миграцию отдельно от API-запросов; production не трогать. Откат приложения не требует удаления скопированных работ или колонок; не откатывать данные разрушительной миграцией.

## Прогресс

- Реализованы shared-контракт, аддитивная миграция `20261021010000_assessment_work_copy`, атомарный API, действие в строке списка и сообщение о пропусках в новом черновике. Три поля происхождения/числа пропусков не меняют старые работы. Миграция применена только локально; reset/backfill и production-действий не было.
- По уточнению пользователя отказ от частичной копии заменён пропуском удалённых задач с явным счётчиком. Пустая копия разрешена. Копирование не является обязательным шагом назначения нескольким классам.
- Проверки: shared 41 тест; web 121 тест в 44 файлах; API 71 unit-тест и 11 HTTP integration-тестов работ/назначений с реальными PostgreSQL/MinIO/Better Auth. Typecheck shared/web и API в Docker, API build в Docker, production web build, boundary lint, docs generate/check и diff check прошли. Отдельно проверены пустой/частичный состав, неизменность оригинала и его получателей, точные версии/рисунки, отсутствие назначений у копии, конфликт и конкурентный повтор, повтор после правки оригинала/копии и после удаления задач, длинное название с emoji на границе сокращения.
- Полный lint без ошибок; прежние complexity warnings остаются, новых нет. WorkEditor сохранил complexity 28; уведомление выделено в короткий локальный компонент. Ponystack-contract: Lean already. Ship. Новых зависимостей, общей системы шаблонов или копирования файлов не добавлено.
- Во встроенном браузере проверены 1366×900 и 390×844: меню в плотной строке, клавиатура/Enter/Escape/возврат фокуса, создание и переход в новый редактор. Из исходных трёх задач скопированы две; оригинал сохранил три, копия показала сообщение об одном пропуске. Меню/текст не выходят за экран. Визуальные снимки временные, не источник истины.
- После QA удалены только созданные здесь данные: синтетический преподаватель, две его работы, шесть задач и импорт с изображениями MinIO. Пользовательские данные сохранены, вкладка проверки закрыта.
- Troubleshooting: первый HTTP-прогон выявил старый Prisma runtime в уже работающем ts-node-dev (`Unknown argument copiedFromId`) после генерации клиента. После перезапуска только локального `continuum-api-classes` оба повторных прогона прошли. Один component-тест ошибочно ожидал сырой текст generic Error вместо общего русского fallback; ожидание приведено к существующему `apiErrorMessage`, логика приложения не ослаблялась. Прежний jsdom `window.scrollBy` в drag-тесте не относится к копированию.
- Commit/push/deploy не выполнялись. Перед выпуском нужна штатная production-миграция и smoke по отдельной команде. UX-01 (уход преподавателя), архив и копирование произвольной исторической редакции не включались. Откат приложения сохраняет новые черновики и nullable-колонки; обратного удаления данных не требуется.
