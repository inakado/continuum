# CI и первый UX-пакет фотографий

Статус: Completed локально, 28.10.2026. Production-выпуск не выполнялся.

Обнаруженный ниже SEC-02 затем закрыт отдельным [обновлением auth и проверкой CI](2026-10-28-auth-security-update.md): high/critical отсутствуют, audit/Trivy прошли локально без исключений. Ниже сохранён результат именно UX-пакета до обновления зависимостей.

## Цель и границы

Исправить реальный security audit в CI; добавить независимый фильтр фото в отчёте, видимую очередь загрузки ученика и обновление открытых решений преподавателя. Существующие ответы, фото, ревизии, правила публикации и фоновые процессы не менять. Без миграций, новых UI-зависимостей и production-выпуска.

## Порядок

1. Проверить текущие контракты и официальные примеры Carbon, Classroom и TanStack Query.
2. Исправить команду audit; воспроизвести успешный audit, отказ для high и ошибки registry. Не скрывать advisory ради зелёного CI.
3. Фильтры: нет фото, частично, все фото, ожидают проверки; пересечение с классом/поиском/тестом, URL и пагинация.
4. Очередь: имя и состояние каждого файла, только подтверждённые приёмы, последовательная запись с прежним ID при повторе; не повторять успешные файлы.
5. Панель: автообновление только пока открыта и вкладка видима, ручной повтор, сохранение данных/фокуса при ошибке.
6. Релевантные тесты, desktop/mobile в браузере, скриншоты, SoR-документация.

## Решения и риски

- Адаптировать механику Carbon (список файлов и inline-состояния), а не импортировать библиотеку. Цвета, размеры и native WorkSelect остаются текущими.
- Для загрузки показывать этапы, без выдуманного процента передачи. Files остаются только в открытой вкладке; существующая защита ухода сохраняется.
- Auto-refresh через существующий TanStack Query, без WebSocket и ручного таймера. Не очищать принятые фото при сетевой ошибке.
- Security исключение допустимо только для конкретного неприменимого advisory с проверяемым условием; обновление auth на RC не входит в этот пакет.

## Проверки и прогресс

- Сверены [первичные компоненты и интеграции](../../research/2026-10-28-photo-ux-components.md): Carbon File uploader/Data table, Classroom и TanStack Query.
- CI теперь выполняет `pnpm audit --audit-level=high`; старый некорректный GHSA в `ignoreCves` удалён. Новых исключений нет. Точная обычная команда: живой registry с high/critical → exit 1, недоступный registry → exit 1, локальный fixture с только low → реальный запрос и exit 0. У pinned pnpm 10.11.1 `--json` возвращает exit по всем severity, поэтому для severity gate он не используется.
- Обнаружены обновившиеся advisory: 4 high / 2 critical / 1 moderate / 5 low occurrences. Gate работает, зависимости security-проверку **не прошли**. До выпуска нужен SEC-02; Trivy/GitHub Actions в этом локальном проходе не запускались. Auth не обновлялся и не ослаблялся.
- `report-photo-filters.ts` и `use-report-filters.ts`: независимые фото-фильтры, URL enum, пересечение с тестом/классом/поиском, счётчики и сброс страницы. `AssignmentReportScreen` и адаптивная сетка используют прежний `WorkSelect`.
- `use-solution-photos.ts` и `StudentPhotoQueue`: имена, четыре состояния, подтверждённые приёмы, сохранение UUID и File до подтверждения. Ошибки/действия рядом с очередью; верхний статус возвращает к нужной задаче. После ошибки перечитывания не запускается запись; при повторном входе также сначала перечитываются ревизии. Уборка незагруженных не вызывает удаления принятых фото.
- `StudentSolutionsPanel`: polling 10 секунд, без background interval, always refetch на mount/focus, ручной refresh, сохранение галереи/открытого снимка/фокуса.
- Web: **71 файл / 263 теста**, включая сохранённую проверку опубликованного нулевого балла/PDF, новые фильтры/очередь/polling. После уточнения regression assertion ревизий повторно прошли 8 queue-тестов.
- Локальный Docker HTTP/БД/S3: **12 integration tests** photos/reviewer; файлы, повторы, конкурентные ревизии, лимиты, изоляция и публикации.
- Прошли web typecheck, lint:boundaries, lint (0 ошибок, прежние 9 complexity warnings), build:web, docs:check и git diff --check. Backend production-код/контракты не менялись; новый backend image не собирался.
- Встроенный браузер, реальные отдельные QA-данные: смешанная работа, 2 принятых фото → повреждённый файл → следующий ждёт; повтор сохранил 2 принятых, «Убрать незагруженные» не удалило их. Переход к другой задаче и возврат к ошибке работает. При открытой teacher-панели добавлено третье фото через реальный API, оно появилось автоматически без закрытия; ручное обновление сохранило focus кнопки.
- Проверены desktop 1440, student 390/320, teacher report/panel 320: ширина документа равна viewport, panel на 320 занимает 280px. Screenshot-пруфы в `output/photo-ux-20261028/`: `teacher-photo-filter-desktop.jpg`, `student-queue-mobile.jpg`, `teacher-panel-refresh-desktop.jpg`, дополнительный mobile report. Это синтетические ученики/файлы, а не реальные ученические решения.
- Тестовый аккаунт выведен из сессии, вкладка закрыта, viewport override сброшен. Удалены только созданные 4 QA-пользователя, их работа/класс/банк и 6 фото из локальной БД/MinIO; временные файлы/credentials удалены. Реальные пользователи, назначения и фото не изменялись.
- Реальный телефон/камера и production-файловый сценарий остаются отдельной приёмкой, а не подтверждены изменением viewport.

## Откат

Только изменения этого пакета в перечисленных файлах; накопленный working tree сохраняется. Серверные данные не изменяются реализацией UI. QA создаёт только собственные временные fixtures, не меняет настоящие задания/учеников.

## Уточнение UI после просмотра пользователем

- Верхний уровень — «Тестовая часть» и «Развёрнутая часть». Ссылка в строке — «N из M заданий», соседняя колонка — «Проверка решений» / «Проверено». «Фото» осталось только в конкретной операции прикрепления/просмотра файла.
- Терминология согласована в назначениях, отчёте, панели, списке работ ученика и списке статистики. «Решения проверены» относится только к опубликованным проверкам развёрнутой части, без обещания завершённого теста.
- Убраны постоянные примечания о подсчёте файлов/задач и интервале обновления. При неудачном обновлении видны ошибка и сохранённые данные.
- BEM применён к локальному блоку report и элементам `report__solutions`, `report__open`, без смены CSS Modules и без привязки layout к русскому data-label. Основы — Classroom/Canvas и GetBEM в исследовании компонентов.
- Для новых скриншотов использован отдельный смешанный QA-пример с отсутствующим, частичным и полным набором решений. Повторные fixtures упирались в настоящий минутный rate limit Better Auth; защита не отключалась и не обходилась, незавершённые fixtures удалены. При вводе через browser fill не менялся disabled submit; штатный клавиатурный ввод сработал, login-компонент не изменялся.

Финальная приёмка уточнённого UI: 1440px desktop и 320px mobile, переполнения нет, mobile panel 280px. Скриншоты отчёта/панели обновлены; очередь файлов сохранена прежней, поскольку её названия описывают реальные вложения. Новый отдельный QA-пример удалён: 4 пользователя, работа/класс/банк и 3 фото; незавершённые предыдущие fixtures также удалены. Общий formatter подписи заданий согласован для обеих ролей, включая «из 1 задания / из 21 задания». Итоговый web suite: 72 файла / 268 тестов; повторены typecheck, boundaries, lint и build:web. Предыдущие 12 реальных HTTP/БД/S3 tests остаются применимы: backend и транспорт в уточнении не менялись.
