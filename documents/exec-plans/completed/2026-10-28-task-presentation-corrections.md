# Исправление условия в банке и назначенных работах

Статус: Completed. Реализовано и проверено локально; production не менялся.

## Цель и границы

Исправлять одну задачу через банк и ZIP с прежним stable ID. Исправление текста, рисунков, оформления вариантов/позиций применяется к совместимым старым версиям в работах. Ответы, фото, баллы, состояния и порядок не меняются. Изменение ключа, типа, баллов, ID/порядка вариантов, исходных метаданных и замена другой задачей вне этого действия.

## Причина и решения

- №16656: Pandoc сохранил `$$…$$` внутри абзаца. Блочный start Markdown-extension разрывал абзац, а одиночный `$` захватывал последующий русский текст. Синтаксическая проверка принимала дерево; MathJax проверял уже неверно извлечённые фрагменты. PDF использовал другой renderer и не выявлял проблему.
- Общий parser исправляет уже сохранённые условия без записи в production. Непарные разделители блокируют новый импорт с точным путём файла/поля.
- Отдельное действие «Исправить условие»: ZIP ровно с одной задачей, предпросмотр, явное «Сохранить в банке и работах». Проверки ответа не редактируются.
- Исправление — новая неизменяемая AssessmentTaskVersion с флагом isPresentationCorrection. Исходные снимки работ не переписываются; read-path накладывает последнее совместимое исправление отображения. Обычный импорт не получает этот флаг и сохраняет прежние правила.
- Сравниваются все поля task, кроме content вариантов/позиций. Только их ID/порядок остаются неизменными. Условие/решение/рисунки берутся из исправления. Совместимость не доказывает неизменность смысла: преподаватель подтверждает её при применении.
- Повтор того же importId возвращает сохранённый результат; смена режима или версии после подтверждения отклоняется. Коррекция атомарна с сохранением в банк.
- Продуктовый ориентир: [Moodle, After quiz has been attempted / Dealing with faulty questions](https://docs.moodle.org/501/en/Building_Quiz#After_quiz_has_been_attempted) различает небольшое исправление и изменения, влияющие на ответы/оценивание. Здесь выбран узкий режим оформления с прежними ключами, отдельный от пересчёта.

## Порядок

1. Воспроизвести дефект, исправить parser, добавить boundary/regression проверки.
2. Контракт, аддитивная миграция, атомарная коррекция и общий reader отображения.
3. Подключить reader к учительскому/ученическому условию, рисункам, статистике и reviewer.
4. UI банка, обновление условия в открытой ученической работе без переинициализации ответов.
5. Подробный гайд подготовки, сверка формул исходник → дерево → MathJax, тесты PostgreSQL и UI desktop/mobile.

## Риски и откат

Смысл текстового/графического исправления проверяет преподаватель; иной правильный ответ требует другого сценария. Выполненные ответы не пересчитываются. Откат содержимого — новым исправлением из прежнего ZIP; исходные версии сохранены. Production не меняется без отдельного деплоя. Nullable-free флаг с default false безопасен для старых версий; откат приложения оставляет старое отображение.

## Критерии и проверки

- №16656 сохраняет семь исходных формул; русский текст остаётся текстом.
- Неверные $, unsafe TeX/HTML и отсутствующие рисунки не проходят импорт.
- Коррекция одного stable ID; чужие/удалённые задачи, устаревшая версия, другой ключ/структура и многозадачный ZIP отклоняются до записи.
- Начатая/законченная попытка: прежние answers/revision/points/completedAt, исходный снимок и фото; новое условие/рисунок во всех read-path.
- Повтор, concurrent correction и обычный импорт не обходят правила.
- Shared/API/web тесты, PostgreSQL, Docker backend typecheck, boundaries, web typecheck, docs:check, браузер desktop/mobile.

## Результат и проверка

- Исправлен общий parser и проверка непарных разделителей с точным путём файла/поля. Регрессионный №16656 содержит все семь исходных формул; русский текст остаётся текстом.
- Добавлены аддитивная миграция с default false, строгий контракт, атомарный correction confirm/receipt и экспорт одной задачи. Обычный импорт не накладывает исправления на работы.
- Общий reader применяется в черновике/версии, ответах write-сервисов конструктора, student detail/images, подробной статистике и reviewer. Попытки, снимки, баллы, фото и рецензии не переписываются.
- Диалог: скачать одну задачу → загрузить один ZIP → сравнение → подтверждение смысла → сохранение. Desktop — две колонки; mobile — переключатель. Кнопки сохранения остаются видимыми при прокрутке условия. Состояние диалога принадлежит TeacherBankScreen и сохраняется, если исправленная задача исчезает из текущего поиска.
- Shared: 69 тестов; API unit: 94 теста. PostgreSQL: 4 новых сценария коррекции, 3 сценария существующего import-to-work; HTTP статистики через временный настоящий локальный API: 6 тестов. В коррекциях storage — контролируемая память, не production S3. Проверены открытая/завершённая попытки, точное сохранение DB-строк/снимка, права, несовместимые ключи, устаревшая версия, удаление, повтор/параллельный запрос, обычный импорт, изображения после очистки preview, extended/reviewer и прежние фото/sourceRevision.
- Web: 159 тестов в 37 файлах bank/works/student/assessment, включая сохранение локального ввода/фокуса при коррекции, отсутствие цикла запросов при старом availability и сохранение диалога после исчезновения задачи из поиска. Typecheck shared/web/API (последний Docker), backend build Docker, boundaries, diff --check и docs:check прошли.
- В браузере проверены реальные production React-компоненты с изолированным HTTP: меню, upload ZIP, сравнение/checkbox, успех, desktop 1280 и mobile 375. Все 30 задач с условиями/вариантами/решениями отрисованы; 21/21 изображение загружено, 219 math-узлов с повторяющимися учительскими ключами, 0 MathJax ошибок, ширина страницы не превышает viewport. PDF 31 A4 страницы просмотрен заново; review-verification.json связывает ручную проверку с SHA-256 ZIP/PDF, поэтому будущий rebuild не наследует прежний статус просмотра автоматически.

## Troubleshooting

HTTP integration-набор статистики требует API на localhost:3000 внутри тестового контейнера. Первый запуск в одноразовом контейнере без API дал ECONNREFUSED; повтор с временно запущенным compiled API прошёл. Сервисные PostgreSQL-наборы запускаются без HTTP-сервера. Временный Vite harness использует alias shared → src/index.ts; прямой импорт CommonJS dist не поддерживает именованные ESM exports.
