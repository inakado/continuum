# UX-03. Удаление ошибочного назначения классу

Статус: Completed (локально). Дата: 2026-10-21. Production не обновлялся.

## Цель и принятое решение

По уточнению пользователя отзыв — необратимое удаление выбранного назначения, даже если ученики начали или завершили работу. Прежнее предложение сохранять историю отменено. Работа, банк и назначения другим классам сохраняются. Удаляются именно получатели исходного назначения, а не все ученики текущего класса; перевод не меняет границу удаления. Повторное назначение создаёт новые попытки.

## Контракт и границы

- В отчёте версии работы — компактный список назначенных классов с действием «Убрать назначение». Отдельное подтверждение с названием, классом, числом получателей/начавших/завершивших и явным предупреждением об удалении ответов, фото и проверок. Без массового удаления и скрытого destructive checkbox.
- Preview выдаёт hash ID получателей. DELETE сверяет hash под общей с назначением блокировкой работы; изменение ответов не мешает отзыву, добавление получателей требует заново проверить подтверждение. Затем блокируются получатели, что сериализует отзыв с сохранением/фото/публикацией.
- Ответы, фото-метаданные, рецензии/PDF-метаданные и reviewer receipts удаляются транзакционно; S3-ключи попадают в постоянную очередь очистки с повторами. Банк/снимок версии не удаляются. Техническая квитанция без ответов сохраняет ID отзыва для безопасного повторного DELETE; новый ID назначения не затрагивается старым повтором.
- Старые запросы назначения после отзыва получают конфликт, а не возвращают прежний успех или восстанавливают данные. Для простоты инвалидируются прежние request receipts всей работы; новые запросы с актуальным составом разрешены.
- Ученический список обновляет доступность; открытая вкладка проверяет дешёвый endpoint раз в 10 секунд и при возврате/восстановлении сети. После обнаружения недоступности player размонтируется, данные cache очищаются, вместо условия показана ссылка к работам. Сервер отклоняет все дальнейшие обращения немедленно, включая агентские. Уже полученный клиентом файл невозможно отозвать задним числом.
- Local only; существующий dirty tree сохраняется; commit/push/deploy отдельно. Не менять общую систему UI или другие UX-пункты.

## Шаги и приёмка

1. Аддитивная миграция, strict shared-схемы, preview/delete, технические квитанции и очередь файлов.
2. Teacher-подтверждение/ошибки/фокус и student disappearance без замены неподтверждённого ввода обычным polling.
3. Тесты owner/Origin/body, изменившихся получателей, начатой/завершённой работы, двух классов, фото/PDF, конкурентной записи, идемпотентности/повторного назначения; retry очистки S3 и component states.
4. Typecheck/boundaries/tests/build (API Docker), desktop/mobile, docs generate/check. Обновить SoR/roadmap, зафиксировать результаты.

## Риски и rollback

Удалённые ответы через UI не восстанавливаются. Физическая очистка S3 может завершиться позже отзыва при недоступном хранилище; очередь не теряется. Старые backup-файлы не очищаются этим сценарием. Откат кода не восстанавливает удалённое и требует оценки новых технических таблиц.

## Прогресс

- Проверены текущие границы назначения и блокировки recipient в student/reviewer writes; минимальный сценарий согласован пользователем.
- Добавлена и применена только локально миграция `20261021030000_assignment_revocation`; Prisma client обновлён, локальный API перезапущен. Shared transport, preview/delete, техническая квитанция, invalidatedAt старых assignment requests и независимый outbox S3 реализованы.
- Teacher: раскрываемые назначенные классы, компактный Radix dialog с неизменяемым snapshot hash, безопасным фокусом/повтором/ошибкой. Mutation убирает класс и получателей из report cache, инвалидирует prepare/списки; последнее назначение возвращает к списку.
- Student: отдельный дешёвый availability-query, обновление списка, удаление player/cache после 404 и сообщение с фокусом на заголовке/ссылкой к работам. Обычная ошибка сети ввод не скрывает. Затронуты обе роли по общей причине отзыва доступа; cross-role imports и общий shell не изменялись.
- Обновлены ASSESSMENTS, FRONTEND, ARCHITECTURE, SECURITY, REVIEWER-CLIENT, generated schema/routes, индекс и дорожные карты. Адресный отзыв отдельного ученика и новый этап статистики не добавлялись.

## Task-specific troubleshooting

- Первый student-тест выявил повторное наполнение detail cache: удаление активного query при enabled=true создавало его снова. Availability поднята перед detail-query; terminal state отключает detail до очистки. Прежний ввод при обычной ошибке сети сохраняется; тест теперь проходит.
- Два клика до обновления `mutation.isPending` создавали два запроса. Синхронный ref-guard блокирует повтор и закрытие сразу; onSettled снимает блокировку. Pending/ошибка/отмена проверены отдельно.
- В первой HTTP-фикстуре не был передан обязательный client-assigned ID работы; исправлена только фикстура. При подготовке визуального набора provisioner вернул сокращённый user без имени; набор завершён с чтением фактического User, без дублирования записей, затем полностью очищен.
- Сразу после смены viewport первая картинка могла отражать прежнюю геометрию. Повторное наблюдение после перерисовки подтвердило нормальный responsive layout; код под переходный screenshot не менялся.
