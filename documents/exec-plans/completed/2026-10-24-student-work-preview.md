# UX-08. Просмотр работы глазами ученика

Статус: реализовано и проверено локально 2026-10-24. Без commit/push/deploy.

## Цель и границы

Заменить существующий просмотр работы одной задачей с навигатором и пробными ответами. Не добавлять вторую кнопку/вкладку. Использовать тот же renderer, поля и layout, что у ученика; не импортировать student feature в teacher. Пробный ввод не создаёт назначения/попытки, не записывается в БД, статистику или browser storage. По уточнению пользователя ответ можно явно проверить на бэкенде без записи. Фото, если выбраны для пробы, остаются локальными и освобождаются при выходе.

## Порядок и приёмка

1. Вынести поля и представление задачи/номеров в role-neutral components, сохранив ученическую orchestration/storage без изменения.
2. В существующем WorkPreview дать интерактивный локальный просмотр черновика и сохранённой версии. Сохранение версии остаётся отдельным прежним действием; ключи/разбор не рендерятся.
3. Проверить переключение, несколько типов ответов, соответствие, очистку пробного ввода при закрытии/смене работы, отсутствие серверных записей и очистку локальных фото.
4. Web regression, typecheck, boundaries, сборка, docs и desktop/mobile QA.

## Решения и риски

- Общий UI оправдан одинаковым сценарием двух ролей; существующий student wrapper сохраняет API, позицию в sessionStorage, requested-task и состояния опубликованных решений.
- По дополнительному поручению пользователя добавлен read-only `POST :id/check-answer` с явным source draft/version и существующим общим серверным оценщиком. Нет копии оценивания в браузере, ученических попыток или пробной публикации. Ключи не нужны общему представлению. Учительские данные остаются в teacher query cache.
- Черновик работы продолжает сохраняться своим существующим механизмом, пробные ответы от него отделены.
- Откат ограничен файлами этой задачи, остальной working tree сохраняется.

## Проверки и прогресс

Исходный WorkPreview рендерит все задания через BankTaskPreview. StudentAnswerInput и StudentWorkQuestions уже содержат нужную типографику, поля и адаптивный навигатор; их визуальная часть переиспользуется.

- Поля и workspace перенесены в `components/assessment`, старый неиспользуемый StudentAnswerInput удалён, его тесты перенесены вместе с реализацией. Student wrapper сохранил позицию, requested task и фото-состояния; существующие regressions прошли.
- В WorkPreview пять типов автоматических ответов, частичное соответствие, возврат к пробному вводу, локальные фото с проверкой лимитов/удалением/viewer. Keyed scope очищается при смене работы/версии/набора задач. URL освобождаются при remove/unmount. Исходная кнопка просмотра не дублируется; сохранение версии остаётся отдельным действием.
- Пользователь отдельно запросил серверную проверку. Оценщик и валидация перенесены из Assignments в `common/assessment-grading`; прежний неиспользуемый shim удалён. `AssessmentWorksReadService.checkAnswer` выполняет только чтение и вычисление; strict shared DTO, teacher/owner/Origin/no-store, draft revision и immutable source. Нет нового доступа для student/reviewer.
- Контракты/HTTP покрывают корректные/пустые/некорректные ответы, отсутствующие варианты/задачи/версии, роли и чужого владельца, Origin, устаревший draft, параллельный повтор и сохранённую версию после изменения состава черновика. Сравнение строк БД/счётчиков подтвердило отсутствие изменений работы и создания версий/назначений/получателей проверкой.
- Проверки: web 181/181 (55 файлов), shared 47/47, API unit 82/82 (Docker), релевантные API integration 18/18 (Works + Assignments, Docker). API typecheck/build (Docker), web typecheck/build, boundaries и scoped ESLint прошли. Общий web ESLint: 0 ошибок, 8 прежних complexity warnings; новые функции ниже порога. Финальный перенос unit-импорта оценщика перепроверен отдельно.
- Во встроенном браузере: прежний просмотр конструктора и существующая readonly-страница работают. Через реальный API `300,0` и `300.0` — верно, `301` — неверно; правка скрывает предыдущую отметку. Desktop 1280 px и mobile 390×844: один общий renderer, поля 20×20 для выбора, компактный раскрываемый навигатор, собственная прокрутка таблиц, без горизонтального переполнения документа. Временная QA-вкладка закрыта, viewport сброшен, исходная пользовательская вкладка оставлена.
- Ограничения QA: реальный набор в браузере содержит три автоматические задачи; 20/30 номеров, остальные типы и локальные фото проверены компонентными тестами. Фото не отправлялись в S3. Полный production/mobile-device acceptance не заявляется.
- Contract gate: удалены неиспользуемые compatibility shims, общий renderer/оценщик заменяют копирование; отдельного режима роли, попытки, storage, worker или dependency не добавлено. Оставлены только transient-state и защита от stale feedback/утечек URL.
