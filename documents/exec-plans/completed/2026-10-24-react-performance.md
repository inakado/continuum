## Порядок и критерии

1. Зафиксировать версию React Doctor, выключить score/telemetry и supply-chain обращения, сохранить локальный отчёт. Не добавлять runtime-зависимость и не применять автоисправления.
2. Снять граф Next analyzer до изменений и профиль production-сборки с React profiling. Проверить ввод/автосохранение, переключение 30 заданий, поиск банка и матрицу 30/90×30; отделить API, JavaScript и React commits. Реальные фотографии/слабая сеть остаются отдельным замером PERF-01.
3. Изменять только подтверждённые затраты. Повторить тот же сценарий, проверить функциональные регрессии, boundaries/typecheck/test/build и документацию.

Без глобальных memo, React Compiler, смены состояния, API-пагинации и новых кешей. Локальные QA-артефакты — `output/`; временные fixtures удаляются после проверки.

## Решения и риски

- Изолированный тестовый браузер и локальный production-сервер; dev-сервер пользователя не останавливать. Любые тестовые transport-переходники и их влияние на timings описать отдельно.
- Прежде чем менять shared exports, сверить browser alias: web уже читает ESM `packages/shared/src/index.ts`, хотя API использует CJS dist. Не переводить backend на ESM ради клиентского bundle.
- Rollback — только новые изменения этой задачи, без reset/revert чужого working tree; данных/миграций нет.

## Task-specific troubleshooting

- Обычный npm exec начал разрешать большой граф необязательных peer-пакетов; собственные процессы остановлены. Отдельная установка в `/tmp` с `--legacy-peer-deps --ignore-scripts --no-audit --no-fund --package-lock=false` ограничилась 122 пакетами и не затронула репозиторий.
- Для сравнения payload profiling-сборка не подходит: debug-флаги меняют размер. Сняты две обычные сборки с одинаковой шапкой и единственным переключением metadata shared; итоговая `.next` также обычная production.
- При первом снимке MathJax ещё завершал initial typesetting; после ожидания всех формул и шрифтов снимок перезаписан. В первом after typing образце хвост initial math-вызовов сохранён в raw; тёплый протокол повторён отдельно.
- Очистка fixture первоначально встретила `Restrict` внешнего ключа work/version. Исправлен только временный cleanup: recipients → assignments → version → work → ученики → преподаватель; повтор подтвердил нулевой остаток. Это не ошибка приложения.

## Адресная проверка единственного error, 25.10.2026

Отдельное поручение пользователя после performance-прохода: проверить `no-ref-current-in-render` в `RevokeAssignmentDialog`. Воспроизведена проблема на компонентной границе с настоящими React transition/Suspense и управляемым read-hook: прерванный render сохранял в ref preview A на 20 учеников; следующий успешный render с B на 21 всё ещё показывал A. Новая регрессия сначала упала на старом коде. Production-инцидент не моделируется как установленный факт; server membership hash по-прежнему предотвращает удаление по несовпавшему составу.

Минимальное исправление: local state с фиксацией в effect после commit. В прерванном render нет фиксации, до неё кнопка disabled; последующий фон C на 22 не заменяет первый подтверждённый B. Hash/CAS, синхронный busy guard и API не менялись. Регрессия проверяет и показанное число, и отправку hash B.

Проверки: 4/4 теста диалога, **227/227 web**, boundaries/typecheck/production build. React Doctor повторно: **0 errors/88 warnings** без suppressions, complete scan. Локальный teacher browser 1280×900 и 390×844 — загрузка, фокус отмены, размеры и закрытие; запись заблокирована на уровне тестового браузера, 0 write requests. Стили не менялись, данные не удалялись. Подробности/артефакты — в [отчёте](../../research/2026-10-25-react-performance.md). Production не менялся.
