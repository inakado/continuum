# UX-10 — отмена удаления из банка

Статус: completed — реализовано и проверено локально. Scope: Assessment Bank, teacher UI, shared contracts; без production deploy.

## Контракт

- После подтверждённого удаления — компактная строка с названием и «Отменить», без новой вкладки, таймера или корзины. Несколько удалений не заменяют уведомления друг друга. Состояние живёт только на открытом экране банка; закрытое уведомление/уход не удаляют исторические данные, восстановление повторным импортом сохраняется.
- Restore возвращает ту же запись/версию/рисунки. Снимки работ и файлы не переписываются.
- Аддитивный `AssessmentBankTask.lifecycleRevision` меняется при удалении, восстановлении и изменяющем запись импорте. DELETE требует версию и исходную lifecycle revision; результат даёт deletion revision. Restore требует именно её и версию.
- Повтор DELETE/restore без нового изменения идемпотентен; старые запросы после следующего цикла или изменившегося импорта дают 409 и ничего не меняют. Все операции используют существующую блокировку владельца.
- Права владельца, teacher-only, Origin, no-store, строгие Zod-контракты сохраняются. Нет серверного таймера/физического удаления.

## Этапы и приёмка

1. Shared-контракт, поле/миграция, API; проверить изоляцию и concurrency import/delete/restore.
2. Teacher-only строка восстановления, pending/error/retry; вернуть прежние фильтры/страницу/выбор задачи.
3. Shared/API/web tests, typecheck/build API только в Docker, boundaries, docs checks.
4. Desktop/mobile QA только на изолированных тестовых данных; обновить SoR/roadmap.

## Риски и откат

- Старый DELETE больше не принимается без lifecycle revision: API/web выпускаются совместно после аддитивной миграции. Preview импорта не меняет контракт пакета v1.
- Обрыв restore не теряет receipt; повтор безопасен. Неизвестный/чужой ID не раскрывается.
- Откат кода не требует удаления колонки/истории; пользовательский dirty working tree не затрагивается.
