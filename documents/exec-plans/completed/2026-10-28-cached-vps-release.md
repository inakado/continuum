# Git-доставка и кеш VPS

## Цель и границы

По решению владельца убрать передачу полного Docker-архива через Mac. Доставлять исходники Git и собирать runtime с кешем VPS. Сохранить полный quality/security CI, исключить повтор тяжёлого quality на main, хранить текущий runtime и один откат. Бэкапы и S3 не трогать.

## Порядок и критерии завершения

1. CI публикует только отметку проверенного fingerprint; provenance обоих успешных gates и свежий main CI обязательны.
2. VPS проверяет миграции, собирает API через BuildKit и web в отдельном source-каталоге, сохраняет standalone. Старый runtime работает до переключения.
3. Проверить локальные тесты миграций/подготовленной сборки/retention и настоящий CI; слить PR и выпустить точный main revision.
4. Проверить standalone staging, активацию, readiness, auth boundary, неизменный uptime PostgreSQL; удалить только созданный неактивированный входящий image-пакет и лишний image. Замерить подготовку и переключение отдельно.

## Решения и риски

- API quality build в CI нужен для тестов, production build выполняется отдельно с кешем VPS. Это честный компромисс вместо медленной передачи 457 МБ.
- Изолированный `git archive` и отдельный Next cache сохраняют работающий `.next`; после успеха исходники/node_modules удаляются.
- Сборка до переключения не меняет работающие сервисы. Неудачная активация возвращает API/web, без отката пользовательских данных.
- Новые миграции по-прежнему требуют отдельного разрешения; текущая схема не меняется.
