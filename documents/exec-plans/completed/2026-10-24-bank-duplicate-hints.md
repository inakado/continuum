# UX-15.A: неблокирующие совпадения задач

Статус: завершено локально. Без commit/push/deploy; миграция применена только локально.

## Сценарий и границы

Пользователь уточнил: не запрещать добавление, показывать возможное совпадение для ручного сравнения. После обычного preview отдельный read-query ищет источник+внешний номер и одинаковый текст условия в своём банке/ZIP. Никакого объединения, удаления, запрета или изменения confirm. Не делать приблизительный/нейросетевой поиск.

## Контракт и скорость

GET preview duplicates запускается независимо от кнопки добавления. Два неуникальных expression index по нормализованным provider/externalId и хешу нормализованного statement охватывают старые JSON без их перезаписи. Индексный пакетный SQL, текущие неудалённые версии своего банка, исключение same stableId; совпадения внутри ZIP тоже исключают себя. Не больше 5 вариантов на задачу, hasMore при усечении. Query имеет отдельный ограниченный timeout: сбой предупреждений не блокирует импорт. Причина «Текст условия совпадает» не означает одинаковые рисунки/варианты/ключи, это явно указано в UI и гайде.

SQL нормализует NFC и внешние пробелы/регистр источника/номера; у текста только NFC и серии whitespace, без удаления чисел/знаков/TeX. MD5 — индексный фильтр кандидатов; равенство нормализованного текста дополнительно проверяется, чтобы коллизия не считалась совпадением. Статистика и версии назначенных работ не меняются.

## UI

Метка и число задач с возможными дублями в preview, предупреждение у выбранного задания. «Сравнить» открывает существующий Dialog с двумя условиями и метаданными, на телефоне одно под другим. Банковский кандидат читается по закреплённой версии; пакетный — по preview stableId. Ошибка сравнения имеет read retry. Закрытие возвращает фокус на «Сравнить».

## Проверки

Shared DTO, API реальные HTTP/БД: внутри ZIP/банк, разные ID, нормализация, changed/unchanged IDs без ложных предупреждений, приватность, удалённые/история, лимиты, nonblocking confirm, benchmark на 500 задач и EXPLAIN использования индекса. UI pending/error/compare/confirm, типы/границы/сборки/документация; desktop/mobile.

## Риски и откат

Информация advisory на момент read; concurrent импорт может изменить банк. Same ID остаётся обычным version update. Отсутствующие ID/номера не доказывают уникальность. Откат только этой работы; индексы не UNIQUE и не меняют содержимое задач. Production не трогать.

## Результат и QA

- Отдельный GET с typed bounded DTO, timeout/fallback, текущими своими версиями и пакетными совпадениями реализован. Добавление не ждёт query и не требует подтверждения предупреждений. Контракт confirm и хеши версий не менялись. Источник/номер и текст — признаки, не доказательство полной эквивалентности рисунков/вариантов/проверки; это отражено в UI/гайде.
- Аддитивная миграция успешно построила два неуникальных индекса по существующим JSON без backfill. Нормализация сверена с [PostgreSQL string functions](https://www.postgresql.org/docs/current/functions-string.html), подход — с [expression indexes](https://www.postgresql.org/docs/current/indexes-expressional.html). SQL builder общий для runtime и EXPLAIN-теста; параметры связаны Prisma.sql.
- Shared 53/53, web 203/203, API unit 86/86, bank HTTP integration 12/12 прошли. Проверены source+номер, текст/whitespace, пакетные совпадения, исключение same ID, доступ к preview, student 403, удалённый кандидат, ограничение 5/hasMore и confirm при совпадениях. Component tests: pending не блокирует кнопку, compare по pinned версии/пакету, error retry и Escape/focus. Unit деградации lookup и настоящих permission errors прошли.
- Performance fixture: 500 входящих задач, 2000 дополнительных тестовых записей банка. Полный HTTP lookup 738–747 мс локально; это замер, не production SLA. EXPLAIN именно полного runtime SQL и отдельного индексного предиката подтверждает оба индекса. Не менее восьми пакетных задач имели >5 совпадений, усечение корректно. Fixtures изолированы и удалены тестом.
- API typecheck/build в Docker, web typecheck/build Webpack, boundaries, scoped ESLint, docs:generate/check и diff check выполнены. BankImportReview выделен из панели: новая функциональность не увеличила её прежний complexity 21; остальные новые компоненты/сервис проходят scoped lint без предупреждений.
- Встроенный браузер: ZIP из двух копий реальной задачи загружен только в preview, найден банк и второй элемент пакета. Desktop 1280: compare width 1248, колонки по 587; mobile 390: dialog width 358, вертикальная прокрутка без горизонтального overflow. Оба вида сравнения показывают реальные условия/метаданные/ключи. Escape возвращает фокус, «Добавить в банк» enabled. Probe preview закрыт/удалён штатной отменой; пользовательский банк остался из 6 задач, QA-идентификаторов нет. Исходная вкладка сохранена.
- Visual QA выявила конфликт ширины общего Dialog (720) и override сравнения: selector уточнён до role, итоговые размеры проверены повторно. Ошибки сети в браузере специально не вызывались; error/pending покрыты тестами. Safari/Firefox и production отдельно не проверялись.
- Обновлены SoR, гайд агенту и UX-15.A: старое предложение строгого предотвращения заменено уточнённым неблокирующим сценарием. UX-15.B/структурное сравнение изображений/вариантов не реализовывались.
- Ponystack-contract: индексы вместо новых таблиц/дублирующих колонок/backfill, одно read API и существующие renderer/dialog/query primitives. Нет нейросети, worker, polling или расширения confirm. Lean already. Ship.
