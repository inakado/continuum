# Удаление заданий и светлое поле предпросмотра

Статус: Completed (локальная реализация); выпуск ожидает отдельной команды. Scope: банк преподавателя, API удаления, сохранность работ, ограниченная правка темы preview. Production не менялся.

## Решения

- Причина чёрного input: theme-init выбирает системную тёмную тему, глобальный `color-scheme: dark` наследуется нативным input без собственного фона. Каталог при этом белый. Исправление локально в teacher-bank/preview, без изменения student и общей темы.
- Меню «Действия с заданием» в панели предпросмотра, один пункт «Удалить из банка», затем компактное белое подтверждение с фокусом отмены. Меню доступно и на телефоне; строки банка не нагружаются кнопками.
- `AssessmentBankTask.deletedAt` скрывает задачу из списка, тем, экспорта и нового выбора. Версии/рисунки сохраняются: иначе сломаются уже собранные черновики и снимки работ.
- Повторный импорт возвращает удалённую задачу под прежним stableId/ID; одинаковое содержимое не создаёт лишней версии. Предпросмотр импорта учитывает удалённое состояние в baseline, не отменяет последующее удаление незаметно.
- Удаление и импорт сериализуются блокировкой владельца. `expectedVersion` отклоняет устаревшее подтверждение. Новые ссылки на удалённые задания запрещены; существующие ссылки в работе остаются читаемыми/переставляемыми.

## Порядок, проверки и готовность

1. Воспроизвести поле и написать failing HTTP-тесты удаления/владения/конфликтов/сохранности работ.
2. Аддитивная миграция, shared-контракты, read/write, импорт и ограничение добавления в работу.
3. Меню/подтверждение, светлый preview, сброс выбранного задания и корректная пагинация.
4. Unit/component/HTTP tests, API Docker typecheck/build, web typecheck/build, boundaries, docs; desktop/mobile и тёмная системная тема.

Готово после локальных проверок и обновления SoR; commit/push/deploy — отдельная команда.

## Риски и rollback

- Это удаление из банка, не уничтожение исторических файлов; UI прямо сообщает сохранность работ. Очистка исторического S3 вне scope.
- Старая версия приложения не фильтрует deletedAt: откат кода снова покажет эти задачи. Таблицы/версии не удаляются.

## Прогресс

- Реализованы аддитивная миграция, soft-delete, ограничения выбора и восстановление импортом; shared-контракт, меню и подтверждение. Failing HTTP-регрессия до реализации возвращала 404 вместо ожидаемого 401; после реализации сценарий проходит.
- Причина темы воспроизведена локальным временным маршрутом с `color-scheme: dark`: необработанный input — `rgb(59,59,59)`, настоящий BankTaskPreview — белый `rgb(255,255,255)` с `color-scheme: light`. Временный маршрут удалён. После удаления также очищен его устаревший generated type из `.next/dev/types`, мешавший сборке; повторная production-сборка успешна.
- Встроенный браузер: 1280 px и 390×844, меню, диалог, фокус отмены и возврат фокуса. На телефоне scrollWidth = viewport = 390; переполнения диалога нет. QA использует отдельного синтетического локального преподавателя, не production-аккаунт.
- Проверки: web 106/106, shared 40/40, API unit 71/71; релевантные HTTP bank/works 9/9. API typecheck/build выполнены в Docker; web typecheck/build, boundaries, lint и docs checks успешны. Новых lint warnings нет, существующие complexity warnings не менялись.
- Общий HTTP-прогон: 33/34. Старый сценарий конкурентного создания учеников падает с Prisma P2034 и при одном worker; код этого сценария не менялся. Дефект вынесен в tech-debt-tracker, общий прогон не считается успешным.
- SoR и generated API/DB документы обновлены. Commit/push/deploy не выполнялись; перед выпуском нужна миграция БД вместе с новым API.
- Синтетический QA-преподаватель, его тестовый банк и четыре локальных S3-файла удалены; пользовательские данные не затрагивались. Скриншоты проверки сохранены в `/private/tmp/continuum-bank-delete-{desktop,mobile}.png`.
