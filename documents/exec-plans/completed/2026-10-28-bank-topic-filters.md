# Иерархические фильтры банка

Статус: Completed. Локальная реализация завершена; production не менялся. Пользователь согласовал временный интерактивный прототип и разрешил реализацию 28.10.2026.

## Цель и scope

Teacher bank и выбор из банка в работе: один выбор темы по пути 1–5 уровней, выбор всей ветки, поиск по путям, компактные дополнительные фильтры. Student, импорт, источники метаданных и production вне scope.

## Порядок

1. Добавить полный путь в query и facets API, сохранить существующие URL и transport-поля.
2. Реализовать общий teacher-фильтр: две колонки desktop, один список с возвратом mobile; независимые просмотр и выбор.
3. Проверить contracts, точность префикса, URL, оба teacher-экрана, desktop/mobile.
4. Обновить SoR и удалить согласованный временный прототип, остановить его сервер.

## Решения

- `topicPath` — отдельный типизированный query-параметр; HTTP/URL кодируют массив JSON. Старый `topic` продолжает обслуживать существующие ссылки. Новый выбор очищает его.
- API добавляет полные `topicPaths`, сохраняет плоский `topics` для существующих клиентов. Путь выбирается целиком, одноимённые узлы разных родителей не смешиваются.
- Prisma не поддерживает префикс scalar array: из distinct текущих путей владельца выбираются точные потомки и строится OR равенств. Без миграции, SQL-конкатенации и перечисления ID задач.
- Новых зависимостей нет. Используются существующие Radix Dialog и токены каталога; production-код пишется отдельно от демонстрационного HTML.

## Риски и откат

Размер OR зависит от числа уникальных путей, а не числа задач. При очень большой таксономии понадобится отдельная оптимизация запроса, сейчас новые индекс/таблица не вводятся. Возврат UI к старому фильтру возможен без изменения БД.

## Готовность и проверки

Одинаковый путь означает одинаковое поддерево в списке и экспорте; родитель включает собственные задачи. Проверены пустая выдача, повторяющиеся названия, URL и глубина 5. Обязательны boundaries, web typecheck и релевантные тесты; backend typecheck только Docker. Прототип удаляется после завершения реализации.

## Результат

- Реализованы общий teacher-фильтр и полный путь в API/URL/экспорте, без миграции и новых зависимостей. Старые CSS плоской панели удалены.
- Проверки: 96 web-тестов банка/работ, 54 shared-теста, 2 unit-теста экспорта, реальный PostgreSQL integration-test (родитель, потомки, глубина 5, одноимённые ветки, отсутствие ветки, параллель, owner isolation, экспорт). Web и Docker backend typecheck, boundaries и docs:check прошли.
- Реальные React-компоненты просмотрены в браузере на desktop и iframe viewport 375/320 px: переходы до 5 уровней, выбор, фокус после закрытия, совместное применение ЕГЭ и источника. Это компонентная браузерная проверка, не авторизованный production-сценарий.
- Тест PostgreSQL выявил поведение пустого OR: пустая ветка могла не ограничивать выдачу. Предикат теперь всегда содержит точное равенство выбранному пути; отрицательный сценарий проходит.
- Согласованный временный HTML-прототип удалён из каталога визуализаций; оба временных сервера остановлены, временный React harness удалён.
