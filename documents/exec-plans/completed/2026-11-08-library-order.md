# Порядок разделов и занятий

Статус: Completed. Реализовано и проверено локально 08.11.2026; production deploy отдельно.

## Цель и границы

Преподаватель меняет порядок разделов внутри GradeBand и занятий внутри Section. Порядок сохраняется для обоих преподавателей и ученического каталога. Схема уже содержит sortOrder; миграция не нужна. Перенос между разделами/параллелями и изменение student UI вне scope.

## Решение

- Строгий shared-контракт: ожидаемый полный порядок ID и требуемая перестановка того же набора.
- Транзакционная запись под общей блокировкой с созданием/удалением соседей. Устаревший список — 409, без частичных изменений.
- Учительский UI: ручка перетаскивания, линия вставки, клавиатура и меню выше/ниже/в начало/в конец для touch. Нативный drag соответствует существующему конструктору работ, новых зависимостей нет.
- Временная проекция pending mutation поверх React Query; исходный query snapshot не перезаписывается. Выбранное занятие сохраняется по ID; ошибка обновляет список.

## Риски

Два преподавателя могут одновременно менять общий список; сравнение expectedIds защищает от тихого перезаписывания. Запросы не принимают чужие ID и не переносят сущности в другой scope. Production этого изменения требует отдельной команды на deploy согласно ARCHITECTURE.
