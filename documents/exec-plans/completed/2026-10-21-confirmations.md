# UX-14 — подтверждения без системных окон

Статус: completed локально 2026-10-21. Область: web, обе роли; API и доменные правила не меняются. Commit/push/deploy не выполнялись.

## Контракт и границы

- Переиспользовать существующий `AlertDialog` на Radix: компактный белый диалог, безопасный начальный фокус, понятное действие, возврат фокуса.
- Заменить `window.confirm` в учениках/классах/доступах, отзыве ключа, конфликтах редактора/ученической работы, удалении фото и обычном уходе из редактора по ссылке/кнопке.
- Во время асинхронного действия блокировать повтор и закрытие; ошибка остаётся внутри диалога, повтор использует исходную цель/ключ запроса.
- Не добавлять подтверждения к обычным действиям. Существующие специальные диалоги удаления работ/назначений/материалов не переписывать.
- Native `beforeunload` сохраняется: браузерное закрытие нельзя заменить произвольной модалкой. Ожидание автосохранения, Browser Back/Forward, logout и повторный вход преподавателя остаются UX-01, не объявляются реализованными.

## Порядок

1. Общий UI-примитив и локальный hook подтверждения без глобального провайдера.
2. Перевод существующих вызовов, сохранение безопасных повторов и секретов только в памяти.
3. Тесты отмены/фокуса/pending/error/retry и ролевых сценариев; typecheck, boundaries, build.
4. Desktop/mobile QA без удаления пользовательских записей; обновление SoR и roadmap.

## Риски и откат

- Async-диалог не должен незаметно потерять запрос, выбрать другой объект или закрыться при ошибке.
- Общий компонент проверяется в обеих ролях. БД/S3/ключи при визуальной QA не меняются.
- Откат — только правки этого среза; большой исходный dirty working tree сохраняется.

## Готовность

- В прикладном UI больше нет `window.confirm`; подтверждаемые действия по-прежнему требуют явного согласия.
- Фокус, Escape, pending, ошибка и повтор покрыты тестами; layout проверен на телефоне/desktop.
- UX-01 и пользовательская приёмка не подменены локальными проверками.

## Журнал

- 2026-10-21: существующий AlertDialog не использовался и закрывал Action сразу, не поддерживая ожидание/ошибку. Обновляется этот примитив, без новой библиотеки/глобальной очереди.
- Заменены все прикладные `window.confirm`; специальные готовые диалоги не переписаны. `beforeLeave` стал callback seam только для прежних обычных ссылок/кнопки; native `beforeunload` и открытый UX-01 сохранены.
- Проверки: 152 теста web (48 файлов), web typecheck, boundaries, production build прошли. Scoped ESLint без ошибок; сохраняются complexity warnings в прежних крупных экранах: StudentWorkPlayer 24, WorkEditor 28, SchoolClassWizard 34, TeacherStudentsScreen 39. Новые shared UI/hook без warnings. Дальнейшая декомпозиция соседних orchestration-экранов не входит в этот срез.
- Проверены отмена без записи, точная цель, фокус, pending/double-click/Escape, ошибка и повтор; сброс пароля повторяет requestId, фото — исходный ID, конфликтный reload не стирает ввод при неудаче. Тесты старого native confirm переведены на явный выбор кнопки в диалоге, не удалены.
- Браузерная QA: teacher1, 1280×720 и 390×844, удаление/сброс только открывались и отменялись. На телефоне диалог 358 px при viewport 390 px, фокус на отмене; Escape вернул фокус к меню ученика. Пользовательские записи/пароли/ключи не менялись. Student-сценарии проверены компонентными тестами, отдельный авторизованный student browser smoke не запускался, чтобы не менять общую сессию пользователя.
- Impeccable сохранил белый плотный стиль и прямоугольные controls; Ponystack-contract: существующий Radix-примитив, локальное состояние вместо глобального провайдера, новых зависимостей нет. Проверки не подменяют пользовательскую приёмку или полный WCAG-аудит.
