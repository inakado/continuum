# Небольшие UX-доработки: профиль, фильтры и ФИО

Статус: Completed (локально). Дата: 2026-10-21. Scope согласован пользователем: меню профиля (часть UX-14), фильтры банка (часть UX-09), исправление ФИО (UX-07). UX-11 и UX-13.A исключены; остальные пункты аудита не реализуются в этом изменении. Commit/push/deploy — отдельная команда.

## Контракт и решения

- Общий профиль использует существующий Radix DropdownMenu: Escape, внешний клик, клавиатура, возврат фокуса. Пункты и beforeLogout сохраняются; оформление белое, плоское, без нового кабинета.
- В URL банка сохраняются только параллель, поиск, тема, тип и страница. Поиск заменяет текущую запись history; отдельная смена фильтра/страницы допускает Back/Forward. Значения валидируются; Next/history metadata сохраняются. Выбранное задание и фильтры отчёта остаются следующим срезом UX-09, не скрытым расширением этой задачи.
- ФИО исправляется через «Изменить данные» в меню ученика, в компактной форме с явным сохранением. Логин и пароль не редактируются. Меняется существующий аккаунт, user.name и профиль, но не класс, доступы, сессии, результаты или снимки имени в прежних назначениях.
- Классы/ученики общие для преподавателей. Новый PATCH строго валидирует ФИО и ожидаемые прежние значения; два преподавателя не перезаписывают друг друга молча. Повтор уже применённого изменения безопасен. Миграция не нужна.
- Референсы: [Formative — edit student names](https://help.formative.com/en/articles/2921005-edit-student-names), [Radix Dropdown Menu](https://www.radix-ui.com/primitives/docs/components/dropdown-menu), [Linear filters](https://linear.app/docs/filters). От Formative берём разделение имени/логина, не скрытый double-click; явное действие уже соответствует нашему меню ученика.

## Проверки и завершение

1. Контракт ФИО, атомарная запись и teacher-only API; auth/Origin/строгий body, повтор, конфликт, сохранность аккаунта/назначения.
2. Профиль обеих ролей: клавиатура, Escape/внешний клик, beforeLogout false/true и повторные клики.
3. Фильтры: прямая ссылка, обновление/возврат, Back/Forward, невалидные параметры, сброс страницы, отсутствие лишних записей на ввод.
4. Форма ФИО: предзаполнение, отмена, ошибка/конфликт, сохранение; desktop/mobile, компактность и фокус.
5. Shared/web tests, boundaries, web typecheck/build, API tests/typecheck/build в Docker; docs checks и diff check. Обновить SoR и статус пунктов, не объявлять закрытым весь UX-14/09.

## Прогресс и ограничения

- Финальная production web build, `pnpm docs:check` (links/index/status/generated) и `git diff --check` прошли. Это локальная сборка, не production deploy.

- Реализованы три согласованных среза. Рабочие изменения удаления банка и прежней документации сохранены без сброса. Миграций для этих трёх срезов нет.
- Shared: 40 тестов. Web: 116 тестов в 43 файлах, typecheck и boundary lint прошли. API в Docker: 71 unit-тест, 10 HTTP integration-тестов банка/назначений, typecheck и build прошли. HTTP-тест ФИО проверяет права обеих ролей/двух учителей, Origin/body, повтор/конфликт, конкурентное изменение, сохранность пароля, сессии, доступов и снимков назначений. Форма отдельно проверена при фоновом обновлении списка.
- Полный lint без ошибок; прежние complexity warnings остаются. В изменённых TeacherBankScreen/TeacherStudentsScreen complexity не выросла (37/39). Ponystack-contract: лишних абстракций не выявлено; использованы существующие Radix, Next native history и query hooks. Прежние предупреждения jsdom `window.scrollBy` не подтверждают браузерный drag, который здесь не менялся.
- Во встроенном браузере проверены сохранение синтетического ФИО/неизменный логин, возврат фокуса после сохранения/отмены, профиль с клавиатуры/Escape и внешний клик, восстановление поиска банка после reload и Back при смене параллели. Проверены ширины 1366×900 и 390×844: компактная форма, длинный логин, поля и кнопки без обрезания. Роли/защита beforeLogout дополнительно покрыты component-тестами; отдельный живой student login не выполнялся.
- Локальные QA-данные удалены: два синтетических аккаунта, шесть принадлежащих тестовому учителю задач, импорт и его изображения в MinIO. Пользовательские записи не менялись. Скриншоты проверки временные, не источник истины.
- Troubleshooting: первый HTTP-прогон прервался перезапуском ts-node-dev при параллельной сборке shared; журнал подтвердил причину, повтор после восстановления API прошёл. В новом тесте уточнено ожидаемое изменение `StudentProfile.updatedAt`, не логики приложения. Известный отдельный roster-сценарий с P2034 не менялся и не объявляется исправленным.
- Остаток: выбранное задание/фильтры отчёта (UX-09), унификация остальных подтверждений (UX-14), production-проверка по отдельной команде. Исторические снимки ФИО намеренно сохраняются; автоматической смены логинов нет. Rollback этого среза — откат его кода без отката данных/миграций; принятые исправления ФИО сохраняются в БД.
