# UX-02. Удаление черновиков, архив и восстановление работ

Статус: Completed (локально). Дата: 2026-10-21. Production не обновлялся.

## Цель и scope

Управлять порядком в списке работ через существующее `⋯` и фильтр «Текущие работы / Архив». Без новых вкладок, корзины или массовых операций. Teacher-контур; ученики, банк, ответы и PDF не изменяются. Прежний working tree сохраняется. Commit/push/deploy — отдельно.

## Контракт и решения

- Архив — только фильтр учительского списка. Состав, закреплённые версии, назначения, доступ учеников и результаты сохраняются. Редактирование/назначение по прямой ссылке и копирование архивной работы остаются доступны; копия всегда текущая. Возврат из архива — обратимое действие без подтверждения.
- Неиспользованный черновик — работа, у которой ни одна версия не имеет назначения. Фиксация версии без назначения не запрещает удаление. Сервер повторно проверяет назначения под той же блокировкой работы, которую берёт назначение. Использованная работа доступна только для архива, не удаления.
- Удаление требует компактного подтверждения с названием, фокусом на «Отмена», блокировкой повторов/закрытия при записи и ошибкой в диалоге. Банк заданий и созданные копии сохраняются. Восстановления удалённого через интерфейс нет; для обратимого скрытия служит архив.
- Удаление логическое (`deletedAt`): сохраняется tombstone ID, чтобы повтор старого create/copy не воскресил запись. Удалённая работа недоступна для detail/update/freeze/copy/назначения. Версии и S3 не чистятся этим действием; каскадное удаление исключено. Архив (`archivedAt`) — отдельное состояние.
- `lifecycleRevision` отделена от content `revision`: archive/restore не создают новых редакций содержания и не ломают сопоставимость назначений. PATCH archive принимает желаемое состояние и ожидаемую lifecycle revision; уже достигнутое состояние — безопасный no-op, устаревшее противоположное — 409. DELETE требует ожидаемые content/lifecycle revisions, повтор уже завершённого удаления безопасен.
- Новый lifecycle write-service изолирован от конструктора. Shared Zod, teacher/owner/Origin и `no-store`; одна аддитивная миграция. Список отдаёт UI-признак `canDelete`, не заменяющий серверную проверку. Весь server state — TanStack Query, фильтр списка локальный (полный UX-09 здесь не расширяется).

## Шаги и приёмка

1. Контракты/миграция/API; запрет удаления назначенной работы и воскресания по старому ID, гонка назначения/удаления, повтор archive/restore и защита от запоздалого противоположного действия.
2. Фильтр, меню, подтверждение и пустой архив; copy сохраняется, фокус после скрытия строки — в поиск; роли не смешиваются.
3. Shared/component/HTTP tests: права/Origin/body, конкуренция, stale values, неизменность версий/назначений/ответов, архивирование и продолжение ученической работы, независимая копия после удаления источника, legacy create/copy retries.
4. Desktop/mobile во встроенном браузере; typecheck/boundaries/tests/build, API только Docker; docs generate/check/diff. Обновить SoR и roadmap, зафиксировать результаты.

## Риски и rollback

Новые поля добавляются без reset/backfill. Повторная проверка использования сериализуется с назначением; soft-delete защищает старые запросы. Не обещать физическую очистку БД или файлов. Откат интерфейса не требует удаления данных; старый API, не учитывающий tombstone, нельзя выпускать без отдельной оценки. Production не затрагивается.

## Прогресс

- Реализованы shared-контракты, аддитивная миграция `20261021020000_assessment_work_lifecycle`, lifecycle service, маршруты archive/delete и фильтрация tombstone во всех путях конструктора. Миграция применена к локальной БД, Prisma client обновлён, локальный API перезапущен.
- Меню `⋯` расширено без новой вкладки: «В архив» / «Восстановить», «Удалить черновик». Фильтр рядом с поиском, пустые состояния, безопасное подтверждение, статус/ошибка/повтор, защита от double submit и восстановление фокуса. Сохраняются исходные revisions диалога и payload неизвестного результата запроса; после удаления очищаются detail/preview caches.
- Обновлены ASSESSMENTS, FRONTEND, SECURITY, ARCHITECTURE, generated routes/schema, индекс и обе дорожные карты. Э7, отзыв доступа и корзина не добавлялись.

## Task-specific troubleshooting

- При archive/restore тест обнаружил потерю фокуса: стандартный Radix closeAutoFocus возвращал его на исчезающий trigger после ручного фокуса поиска. Для архива подавлен default возврат; component test и браузер подтверждают поиск, для отмены удаления — trigger строки.
- HTTP-гонка выявила `P2010` с PostgreSQL `40001` в driver-adapter cause, тогда как существующий retry назначения распознавал только `P2034`. Теперь строго распознаются оба serialization-conflict формата, повторяется вся транзакция до трёх попыток, затем 409. Остальные ошибки не маскируются; изоляция Serializable сохранена. Распознавание покрыто unit-тестом.
- Первоначальная проверка start ожидала 201, но действующий endpoint явно возвращает 200; исправлено ожидание, не контракт endpoint.
- Сразу после restart API readiness временно недоступна до завершения bootstrap; повтор после запуска успешен. Никаких production-операций для диагностики не выполнялось.
