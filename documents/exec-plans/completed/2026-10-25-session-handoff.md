Предыдущий зафиксированный production-выпуск — runtime `c3cc6f1a2bd10dfe24e67226fe03dd3d17bda9ca`; его проверка записана в docs-коммите `3293db56e6d1853c60d0d9a90d7902df42ddd42c`. Основание — [production release](2026-10-24-production-assessment-release.md), а не новая live-проверка сервера. Последующий пакет ниже проверен локально; **push/deploy не выполнялись**. Актуальные branch/HEAD/working tree проверить через Git при начале следующего чата.

- Поиск банка и выбора заданий: 300 мс для изменяемой непустой строки, немедленные первый запрос/очистка, отмена устаревшего запроса через `AbortSignal`. URL, экспорт, фильтры и выбор сохранены.
- Из root layout убраны неиспользуемые Excalidraw CSS и asset-path script; пакет/vendor сохранены. CSS chunks уменьшились на 142 125 raw байт.
- В шаблоне Nginx добавлен gzip разрешённых JSON GET проверочных работ. Auth, ключи, пароли и запись исключены. Это **шаблон**, установленный конфиг сервера ещё не менялся.
- Профиль подтвердил лишние рендеры общей шапки при вводе: стандартный `memo` убрал их. `sideEffects: false` в shared исключает неиспользуемые модули из web bundle; CJS API exports сохранены. Login initial JS уменьшился на 59 608 raw байт. Это локальные измерения, не обещание скорости production.
- Единственный React Doctor `error` проверен отдельной воспроизводимой регрессией: прерванный render диалога отзыва мог сохранять устаревший preview в ref. Снимок теперь фиксируется после commit; hash/CAS и защита от двойной записи сохранены. Итог Doctor 0.9.18: **0 errors / 88 warnings**, полный scan без suppressions. Предупреждения разобраны, массовая переделка не поручалась.

## Что осталось

- Выпустить текущий локальный пакет **по новой явной команде**. Nginx требует отдельного переноса директив с сохранением домена/сертификатов, backup, `nginx -t`, reload и авторизованного smoke gzip/identity; обычный frontend deploy его не устанавливает.
- Пользовательская приёмка локальной проверки с **двух физических компьютеров**: [контракт и критерии](../active/2026-10-18-reviewer-api-contract.md). Автотесты её не заменяют.
- UX-05: публикация подробного тестового разбора ученику — пользователь отложил. Учительская статистика и опубликованные PDF уже работают.
- Условные улучшения — только в deferred roadmap: почти одинаковые задачи, исправление завершённой попытки, самостоятельная смена пароля, развитие библиотеки; PERF по реальным фото и выросшей истории. Не выполнять весь список автоматически.
- Подтверждённый долг — complexity budget, транзитивный low KaTeX advisory и ограничение сохранности неподтверждённого ввода при аварийном закрытии. Полного offline нет; галочку локального черновика пользователь отклонил.

## Требования владельца к дальнейшей работе

Эти предпочтения пользователь явно просил передать следующему агенту:

- Отвечать по-русски, кратко; сначала изучать код/сценарий, затем действовать. Ponystack: минимальные ограниченные изменения, без новых абстракций и зависимостей ради предположений. Не трогать несвязанный working tree.
- Перед существенным UI/UX-решением изучать релевантные современные реальные сценарии и первичные источники. Для обучения полезны Formative, Classtime, Gradescope и Wayground; для общих компонентов/таблиц — подходящие решения Apple HIG, Shopify Polaris, Jobber. Выбирать по задаче, объяснять адаптацию, не копировать бренд или добавлять функции только из-за референса. Существующие исследования — в `documents/research/`.
- Сохранять белый плотный редакционный интерфейс: Inter, тёмно-зелёный акцент `#0B6B4F`, прямые углы, тонкие разделители, списки/таблицы. Без карточек на всё, градиентов, лишних вкладок и неоднозначных состояний. Не нужна генерация изображения для каждой правки.
- Использовать существующие shared UI-примитивы, явный focus, доступные подписи и подтверждения в стиле проекта. Проверять соответствующую роль на desktop/mobile; широкая статистическая таблица может прокручиваться горизонтально внутри контейнера.
- Корректность, права, неизменяемые версии, безопасные повторы и сохранность ответов важнее косметики и метрик. Старые результаты не пересчитывать при изменении банка/оценщика.
- Оптимизировать по измерению. Рабочий масштаб — примерно 30 учеников **на класс**, 20–30 заданий, несколько классов и история; это не лимит всей базы. Redis, workers, глобальные memo, виртуализация и переписывание состояния заранее не нужны. React Doctor — диагностический инструмент, не цель добиться формального score.
- После изменения запускать релевантные тесты, boundaries/typecheck/build по контуру и обновлять SoR; историю — в execution plan, остаток — в roadmap. Локальные проверки, CI, deploy, live smoke и пользовательскую приёмку различать. Push/deploy — только по отдельной команде.
