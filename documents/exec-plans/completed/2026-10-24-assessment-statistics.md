# Статистика работ: отдельный учительский раздел

Статус: Completed (локально; production не обновлялся).

## Цель и границы

Реализовать teacher `/teacher/statistics`: список назначенных версий и анализ одной версии по заданиям, ученикам и классам. Основной вид — задания: количество и доля учеников для каждого целого балла от 0 до максимума. Процент набранных баллов по заданию не нужен.

В scope: распределения, полнота данных, таблица учеников, сравнение классов, детализация ответа и опубликованного PDF, сохранение фильтров в URL, desktop/mobile. Оперативный отчёт назначений сохраняется. Вне scope: школьные оценки, объединение разных версий, экспорт, ученическая публикация тестового разбора (следующий срез Э7), изменение записанных результатов.

## Референсы и решения

- [Pearson: Item and Score Response Distribution](https://support.assessment.pearson.com/as/item-and-score-response-distribution-168624203.html): отдельные группы для каждого полученного балла; берём распределение баллов, а не процент освоения.
- [Formative: View and Score Responses](https://help.formative.com/en/articles/6198532-view-and-score-responses): переход от распределения к ученикам и конкретному ответу. Не переносим live-проверку незавершённых ответов.
- Основная навигация «Статистика»; внутри версии три представления «Задания / Ученики / Классы». Прямоугольные контролы, тонкие разделители, белый фон, без KPI-карточек.
- Только завершённые тестовые части и опубликованные рецензии актуальной ревизии входят в распределение; недостающие данные показаны отдельно. Завершённый пропуск — 0. Средние двух частей используют собственные знаменатели; общий итог только полностью готовых работ.
- Чтение использует снимок назначенной версии, не актуальный банк. Для старых попыток баллы по заданиям восстанавливаются тем же grader по закреплённым условиям/ключам/policy, без записи и изменения прежнего итога. При несовпадении с сохранённым общим баллом детализация считается недоступной, а не тихо пересчитывается.
- Данные загружаются read-only, в согласованном DB snapshot; ключи и ответы только в teacher API с проверкой владельца работы. Подробное условие/ответ загружаются по запросу, не в общей матрице.

## Риски и откат

Большие таблицы требуют локального горизонтального скролла на desktop и другого представления на телефоне. Недопустимо выдавать непроверенное за 0 или включать черновик рецензии. Новых зависимостей, миграций и записей в пользовательские данные нет; откат — удаление новых read routes и feature.

## Критерии и проверки

- Отдельный вход со всех учительских экранов, рабочие классовый фильтр и три представления.
- Нулевой опубликованный балл отличается от отсутствующего; отсутствие части не блокирует итог.
- Все классы сравниваются внутри одной версии и снимков назначений.
- Повтор чтения безопасен, чужая работа/получатель/задача недоступны, ученическая роль не получает ключи.
- Длинные названия, 20+ задач, пустые данные, ошибки и повтор, keyboard/focus, desktop/mobile.
