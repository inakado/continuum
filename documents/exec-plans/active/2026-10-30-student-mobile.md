# Мобильная адаптация ученика

Статус: Active. Дата: 30.10.2026.

## Цель и scope

Реализовать согласованные A для материалов и B для выполнения работы по [исследованию](../../research/2026-10-30-student-mobile.md). Проверить отсутствие дублирующихся навигации/статусов, переполнений и регрессий desktop. Сохранить API, доступы, ответы, фото, сохранение и safe-leave. Учительские материалы остаются отдельным следующим этапом. Без публикации.

## Решения

- Student-only chrome и CSS; общие фундаментальные токены/UI-kit и teacher features не меняются.
- Материалы: поиск по уже загруженному каталогу; только доступные параллели, контекст grade/query в URL и возврат в ту же строку. Desktop сохраняет прямые PDF, mobile — отдельное занятие с удобными действиями.
- Выполнение: компактная шапка вместо двойной навигации на телефоне; один номер позиции, нижний toolbar и Dialog карты. Рендерер условия/ответа общий с предпросмотром, управление заданием — student feature.
- Нижняя панель учитывает safe area, не должна закрывать фокус. Предусмотреть поведение при вводе и короткой высоте.
- После проверки удалить прототип, dev-команду/config и временные кеши. QA только во внутреннем браузере, как просит пользователь.

## Этапы

1. Реальные компоненты материалов/занятия и контекст возврата.
2. Реальные student workspace/navigation, список работ и подтверждение.
3. Регрессии сохранения/фото/повторного входа, mobile/desktop QA, docs, уборка прототипа.

## Проверки и прогресс

- Источники повторно сверены: Google list-detail, Apple touch/layout, WCAG Focus Not Obscured. Особое внимание закреплённым панелям и input.
- IAB runtime сообщает `Local browser use is disabled in Work settings`, но скриншот пользователя подтверждает, что доступ включён. Не просить менять разрешения повторно и не обходить ограничение через внешний браузер; переподключить, продолжая независимую реализацию.

## Риски и откат

Не менять семантику оценивания и завершения. Поворот/клавиатура iPhone требуют фактической приёмки. При недоступном IAB нельзя объявлять новый layout визуально проверенным. Откат только новых student/frontend правок; прежний teacher working tree сохранить.

### Исправление MOB-02

По команде пользователя добавлено одно student-only CSS-правило `body:has(.chrome, .mobilePlayerHeader) { overflow-x: clip; }`. Оно снимает лишний scroll container у `body` как с общей, так и с рабочей шапкой; teacher и глобальный CSS не менялись. Кодовая причина MOB-02 устранена, запись убрана из открытого долга. Проверка фактической геометрии по-прежнему остаётся в этом активном плане: новая попытка IAB вернула ту же ошибку подключения, внешний браузер не использовался.

После правки: 5 релевантных файлов / 37 тестов passed, web typecheck, lint:boundaries, docs:check и git diff --check passed; production `pnpm build:web` passed. В выходном CSS проверено правило `body:has(.nFZYha_chrome,.nFZYha_mobilePlayerHeader){overflow-x:clip}`: CSS Modules сохраняет обе scoped-ветки. Новых JS-механизмов/зависимостей/тестов на текст CSS не добавлено; контрактционный проход оставил одну строку рабочего изменения. Без commit/push/deploy.

### Лишние полосы прокрутки вариантов, 31.10.2026

Воспроизведён пользовательский сценарий с пятью утверждениями и inline-математикой. У Markdown overflow-x:auto вычислял overflow-y:auto: на 390px три варианта имели clientHeight 61/87/61 и scrollHeight 67/93/67 при совпадающей ширине 286px. Удалён общий overflow у текстового блока; текст переносится без внутренней вертикальной прокрутки. Общий renderer исправлен для обеих ролей, поскольку причина одна.

Сохранены локальные области широких таблиц/display-формул. Для слишком широкой inline-формулы data-overflow включается по getBoundingClientRect().width относительно уже измеренного MathJax containerWidth, с повтором при resize. mjx-container display:inline имеет scrollWidth=0 даже при ширине645px, поэтому это свойство не подходит для проверки. В IAB подтверждено: на 390px обычный текст overflow visible, широкая формула 645px прокручивается внутри350px (height=scrollHeight47), таблица369px — внутри350px, весь Markdown350px не расширяет страницу. Тест дополнен resize-проверкой: до исправления падал, после passed; stale rendering и fonts-ready проверки сохранены. Снимок student-options-no-scroll.png — исходные компоненты на демоданных.

По замечанию пользователя исправлен отрыв точки: непосредственная пунктуация после inline-математики передаётся тому же MathJax-узлу и удаляется только из следующего текстового фрагмента. Проверка в IAB: формула заканчивается `=0.`, следующий sibling начинается с « После…», overflow650px внутри350px, вертикального overflow нет. Тест фиксирует сохранение точки при typeset и отсутствие отдельно стоящего знака после математики.

Итог проверок после пунктуации: web 76 файлов / 306 тестов passed, typecheck/boundaries/docs/diff passed, production web/shared build passed. На desktop1200px все пять вариантов имеют clientWidth=scrollWidth780px и overflow visible по обеим осям; на390px подтверждён перенос текста без вложенных scroll-контейнеров. Без публикации.
