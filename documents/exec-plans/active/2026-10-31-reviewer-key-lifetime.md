# Ключ проверяющего до отзыва

Статус: Active. Дата: 31.10.2026.

## Цель и решение

Убрать месячное переподключение. Новые ключи имеют expiresAt = null в обеих таблицах; nullable-контракты, read/write guards, лимит 20 подключений, интерфейс и переносимый клиент согласованы. Отзыв, scopes, текущий состав классов и деактивация сохраняются.

Миграция снимает сроки только у неотозванных ключей с будущим сроком и включённой, ещё действующей записью Better Auth. Просроченные/отключённые не оживают. Секреты и идентификаторы не меняются, Keychain не требует повторного connect. Обновление переносимого клиента нужно из-за нового nullable DTO, профиль сохраняется.

## Проверки и выпуск

Проверить shared, teacher UI, Node CLI, Docker API typecheck и reviewer HTTP/DB/S3; отдельно прогнать SQL на изолированных таблицах с действующим, отозванным, отключённым и просроченным ключами. Схему и API-документацию перегенерировать. Production не менять: выпуск/миграция требуют отдельной команды и подтверждённого backup по deploy runbook.

## Результат локальной проверки

- Миграция применена только в локальной Docker-БД; Prisma client обновлён. SQL на временных таблицах проверяет обе даты, отключение, отзыв, просрочку и повторное выполнение.
- Shared: 72/72; teacher-reviewer: 8/8; локальные reviewer API/БД/S3: 10/10; Node-клиент: 15/15. API typecheck в Docker, web/shared typecheck, lint:boundaries, docs:check и diff-check проходят.
- Реальные компоненты на стенде просмотрены в браузере при 390 и 1200 px: подписи помещаются, горизонтального переполнения нет. Управление внутренним браузером недоступно (`browser.user is unavailable`), использован локальный Playwright.
- Переносимый CLI пересобран с nullable DTO. Архив содержит только CLI и две инструкции, без ключей/фото/профилей. Production и подключённый серверный ключ не изменены.
- При первом прогоне тест ошибочно восстанавливал истёкшую запись Better Auth после её проверки: плагин уже удаляет такую запись. Проверки двух независимых сроков переставлены; повторный прогон зелёный.

## Риски и откат

Бессрочный ключ живёт до явного отзыва; права и лимиты сохранены. Откат потребует назначить сроки бессрочным записям перед восстановлением NOT NULL, поэтому старый API нельзя запускать поверх новой схемы без подготовки. Нет смены хешей секретов или повторной выдачи доступа.
