# ARCHITECTURE

Статус: целевая архитектура активной переработки. До завершения плана часть legacy-кода не соответствует этому документу; расхождения перечислены в `documents/exec-plans/active/2026-09-23-content-library-rewrite.md`.

Общая база классов/учеников реализована в Identity & Access; банк, конструктор и ответы — контуры Assessment Bank, Assessment Works и Assessment Assignments; ключи агента/PDF/публикация — Reviewer API. Поведение — [ASSESSMENTS](ASSESSMENTS.md), полная статистика остаётся следующим этапом [дорожной карты](exec-plans/active/2026-10-15-assessment-roadmap.md).

## 1. Архитектурная форма

- Modular Monolith: NestJS API, Next.js web, PostgreSQL и S3-compatible object storage.
- Один API-процесс без отдельного worker и Redis после удаления legacy LaTeX pipeline.
- Better Auth отвечает за login/password и DB-backed sessions.
- Shared Zod-контракты являются единственным transport-контрактом между API и web.
- Локальные авторские инструменты не являются частью production runtime.

## 2. Модули

### Identity & Access

Хранит пользователей, роли, профили и доступ учеников к возрастным группам.

Инварианты:

- `admin` управляет преподавателями;
- `teacher` управляет учениками и их доступами;
- ученик создаётся только через единый identity provisioning path с тем же Argon2 password hashing, что использует Better Auth;
- все преподаватели видят и изменяют общую базу учеников; `leadTeacherId` сохраняет происхождение записи, не является границей доступа;
- деактивация ученика немедленно отзывает все его активные сессии;
- ученик читает только собственные доступы;
- отсутствие доступа скрывает всю возрастную группу независимо от прямой ссылки.
- `SchoolClass` общий для преподавателей, `teacherId` сохраняет создателя; название уникально в учебном году, `StudentProfile.classId` задаёт один текущий класс;
- добавление в класс выдаёт доступ его параллели, перевод не отзывает прежние доступы;
- массовое создание и сброс используют ключи запросов; исходные пароли не хранятся;
- `school-classes-read.service.ts` и `school-classes-write.service.ts` разделяют чтение и транзакционные изменения; удаление класса сохраняет метаданные пакетов без ссылки на удалённый класс.

Первый transport slice:

- `GET /teacher/students`;
- `POST /teacher/students`;
- `PATCH /teacher/students/:id/active`.

### Library

Хранит возрастные группы, разделы, занятия, файловые материалы и состояние публикации.

Инварианты:

- поддерживаются только группы `grade_7`, `grade_8`, `grade_9`, `grade_10_11`;
- раздел принадлежит одной возрастной группе;
- занятие принадлежит одному разделу;
- ученик видит только опубликованные занятия;
- порядок разделов и занятий явный и детерминированный.
- каталог ученика ограничен не только `GradeBand`, но и преподавателем, выдавшим доступ; материалы другого преподавателя той же группы не протекают между контурами.

Первый transport slice:

- `GET /teacher/library`;
- `POST /teacher/library/sections`;
- `PATCH /teacher/library/sections/:id/publish`;
- `POST /teacher/library/lessons`;
- `PATCH /teacher/library/lessons/:id/publish`;
- `PUT /teacher/library/access-grants`;
- `GET /student/library`;
- `GET /student/library/lessons/:id`.

Отсутствие доступа, unpublished section или unpublished lesson возвращают одинаковый `LESSON_NOT_FOUND` на student detail path и не позволяют определить наличие скрытой сущности.

### Assessment Bank

`apps/api/src/assessment-bank` хранит собственный банк каждого преподавателя, неизменяемые версии и временные предпросмотры импорта. Read/write-сервисы разделены; ZIP parsing и лимиты выделены отдельно, transport и безопасный Markdown описаны в shared.

- ZIP v1 проходит проверку манифеста, путей, размеров, содержимого Markdown и рисунков до сохранения файлов.
- Временная запись владения создаётся перед записью рисунков в закрытый S3. Подтверждение возможно только после завершения загрузки.
- Явное подтверждение транзакционно фиксирует версии; блокировка преподавателя и baseline hash защищают от повторов и устаревшего предпросмотра.
- История версий и их рисунки сохраняются; совпадение с текущим содержимым не создаёт новую версию.
- Все маршруты, ключи и рисунки доступны только владельцу-преподавателю. Авторизованный image proxy не раскрывает S3 keys.
- Банк не использует legacy `Task`, PDF-материалы занятия или серверный TeX. Назначений и ученического выполнения в этом модуле пока нет.

### Assessment Works

`apps/api/src/assessment-works` разделяет чтение и транзакционную запись учительских работ. Shared Zod-контракты задают границу API.

- `AssessmentWork` хранит черновик с порядком ссылок на конкретные версии банка, ревизией и серверными суммами; до 500 заданий.
- `AssessmentWorkVersion` хранит полный неизменяемый снимок; пустую версию сохранить нельзя.
- Запись блокирует строку владельца, проверяет `expectedRevision` и повтор последнего `requestId`. Конкурентная запись не перезаписывает незаметно другую редакцию.
- Фиксация версии повторяема по ревизии, дальнейшее редактирование создаёт другую версию, не переписывая старую.
- Рисунки читаются через защищённый маршрут исторической версии банка. Удаление её файлов нельзя вводить без учёта ссылок работ.
- Все маршруты и закрытые материалы проверки доступны только владельцу-преподавателю. Предпросмотр без ключей не является ученическим transport-контрактом.
- Назначения и ответы вынесены в Assessment Assignments; `AssessmentSolutionAnswer` и `AssessmentSolutionPhoto` хранят независимые ревизии фото, legacy `Task` не используется. Закрытые S3-фото читаются только через проверяющий владение API, локальная проверка не запускается сервером.

### Assessment Assignments

`apps/api/src/assessment-assignments` использует immutable-версии Assessment Works, без зависимости от текущего состава класса при чтении попытки.

- `AssessmentAssignment` фиксирует класс версии, `AssessmentRecipient` — исходного получателя и одну ревизуемую попытку, `AssessmentAssignmentRequest` — результат повторяемого назначения.
- Назначение текущего черновика фиксирует версию и получателей в одной Serializable-транзакции с блокировкой работы. `expectedRevision`, `rosterHash` и сохранённый request hash исключают скрытую смену редакции/состава при повторе.
- Новые ученики добавляются явно. Уникальность `versionId + studentId` сохраняется при переводе; удаление класса/аккаунта оставляет snapshot-историю через `SetNull`.
- Старт, запись ответа и завершение сериализуются row lock попытки. Законченные ответы неизменяемы; повтор завершения возвращает прежний итог. Автопроверка выделена в чистый модуль.
- Teacher read-path отдаёт только собственные назначения, статусы и агрегаты. Student read-path проверяет получателя и строит явный публичный whitelist без ключей; рисунки выдаёт отдельный авторизованный proxy из фиксированного снимка.
- Нет server-side нейросети, очереди, таймера, повторных попыток или фоновой сдачи.

### Reviewer API

`apps/api/src/reviewer` — отдельный контур локального проверяющего. Shared Zod задаёт DTO, key broker отделён от bearer guard, чтение отделено от транзакционных записей. Better Auth API Key не превращается в user session.

- `ReviewerDeviceKey` принадлежит преподавателю и ограничивает агента текущими учениками выбранных `classIds` и явными `studentIds`. Права чтения/черновиков/публикации фиксированы, выбор работ и делегирование коллеге отсутствуют. Доступ проверяется для каждого получателя, в том числе внутри общего назначения.
- Старые `assignmentIds` и таблица `AssessmentReviewerGrant` сохранены только как данные прототипа, runtime их не использует; миграция отзывает прежние ключи без расширения прав.
- `AssessmentReview`/`AssessmentReviewVersion` разделяют текущую и опубликованную редакцию; `AssessmentReviewReport` владеет закрытым PDF; `ReviewerWriteReceipt` сохраняет результат повторяемой записи.
- Публикация сериализуется с фото через `assessment_recipients FOR UPDATE`, фиксирует exact-list ревизий и блокирует только проверенную задачу. Черновик не заменяет опубликованный результат.
- CLI получает секрет из macOS Keychain, хранит manifest/фото вне Git и загружает локально подготовленный PDF. Сервер не запускает агента/нейросеть. Инструкция — [REVIEWER-CLIENT](REVIEWER-CLIENT.md).

### Assets

Управляет загрузкой и защищённой выдачей конспектов PDF, задач PDF и интерактивных пакетов.

Инварианты:

- браузер загружает файл через авторизованный API; view URL выдаётся только после backend-проверки прав;
- доменные записи хранят asset key и метаданные, а не публичный URL;
- тип, размер и назначение файла валидируются policy-as-code;
- удаление доменной записи не должно молча оставлять активную ссылку на материал.

### Interactive Delivery

Целевой контур: принимает локально собранный HTML-пакет и публикует его только после проверки и подключения изолированного проигрывателя. Сейчас ZIP можно сохранить как черновик, но учителю доступно лишь скачивание, а ученику он не выдаётся.

Инварианты:

- исходники и зависимости лекции не собираются на сервере;
- пакет запускается в sandboxed iframe без доступа к cookie Continuum;
- произвольный JavaScript не попадает в DOM аутентифицированного приложения;
- пакет проходит проверку manifest, размера, entry point и content hash;
- новая версия не изменяет предыдущую и может быть откачена.

## 3. Основные данные

- `User`, `Session`, `Account`, `Verification`
- `TeacherProfile`, `StudentProfile`
- `SchoolClass`, `StudentProvisioningBatch`, `StudentPasswordReset`
- `AssessmentBankTask`, `AssessmentTaskVersion`, `AssessmentBankImport`
- `AssessmentWork`, `AssessmentWorkVersion`
- `AssessmentAssignment`, `AssessmentRecipient`, `AssessmentAssignmentRequest`
- `AccessGrant`
- `Section`
- `Lesson`
- `LessonArtifact`
- `Asset`

`LessonArtifact` имеет тип `pdf`, `tasks_pdf` или `interactive`, номер версии, asset key, hash и состояние публикации. У занятия одновременно не более одной активной опубликованной версии каждого типа.

## 4. Основные потоки

### Публикация PDF

1. Учитель отправляет PDF в API; API проверяет роль, владельца, тип и размер.
2. API потоково сохраняет PDF в object storage, проверяет сигнатуру и создаёт версию материала.
4. Учитель публикует занятие, активируя последнюю версию каждого PDF.
5. Ученик получает короткоживущую view-ссылку после проверки доступа.

### Публикация интерактивной лекции

1. Лекция собирается локально.
2. Учитель загружает ZIP как черновик; сценарии CLI и manifest ещё не реализованы.
3. После реализации проверки пакета и iframe проигрывателя учитель сможет публиковать версию.

Загрузка лекции не запускает CI и не требует деплоя Continuum.

## 5. Frontend

- `/login` — единая существующая страница входа.
- `/student` — библиотека доступных возрастных групп и занятия.
- `/student/works`, `/student/works/[id]` — назначения, сохраняемые тестовые ответы и завершённый итог.
- `/teacher` — материалы, ученики и доступы.
- `/teacher/students` — классы, массовое/отдельное создание, перевод, удаление, сброс паролей и доступы к возрастным группам.
- `/teacher/bank` — банк, фильтры и предпросмотр с источником, подтверждаемый импорт ZIP и экспорт.
- `/teacher/works`, `/teacher/works/[id]` — список и конструктор работ, выбор из банка, порядок, автосохранение и неизменяемые версии.
- `/teacher/works/[id]/assign`, `/teacher/works/[id]/preview` — назначение редакции классам и просмотр условий.
- `/teacher/works/assignments`, `/teacher/works/assignments/[id]` — назначенные версии и выполнение учениками.
- `/teacher/reviewer-access` — «Подключение агента»: ключи компьютеров с выбором классов/учеников, вход через профиль.
- `/admin` — системное администрирование; teacher provisioning подключается новым Identity & Access flow.

Teacher и student используют отдельные layouts/feature-контуры и общие токены, UI-примитивы, API client и query infrastructure. Безопасный Markdown/formula/image renderer находится в role-neutral `components/assessment`; импорт teacher feature в student запрещён. Старые dashboard shells не переиспользуются.

## 6. Удаляемая legacy-архитектура

- `Course` и `Unit` как учебная траектория;
- unit graph, layout и prerequisites;
- attempts, progress, unlock и overrides;
- photo-review и notifications;
- серверный Rich LaTeX rendering;
- BullMQ, Redis, worker и `packages/latex-runtime`;
- React Flow и старые course/unit экраны;
- Domain Events Log, если после удаления legacy-потоков у него не останется продуктового назначения.

Excalidraw не входит в удаляемую legacy-архитектуру, но не участвует в текущем PDF-пути задач.

## 7. Dependency rules

- Web загружает материалы только через API; короткоживущую ссылку на чтение API выдаёт после проверки доступа.
- Library не знает о S3 SDK: storage implementation скрыта за Assets module.
- Interactive Delivery не использует sanitizer статического HTML и не разделяет с ним read-path.
- Role-specific frontend features не импортируют друг друга.
- Внешние входы валидируются Zod-контрактом до application logic.

## 8. Production после cutover

- существующие production-аккаунты, доступы, материалы и файлы сохраняются;
- изменения новой инициативы выполняются аддитивными миграциями без повторного reset БД или object storage;
- destructive cutover сентября 2026 года не является штатным способом обновления;
- production меняется только отдельным явным деплоем с проверкой `/health`, `/ready`, login и чтения опубликованного занятия.
