# FRONTEND

Назначение: целевая frontend-архитектура, UI-конвенции и правила клиентского слоя.

## Structure

1. `apps/web/app/**` — routes, layouts и navigation seams.
2. `apps/web/features/student-*` — student catalog, lesson read-path и выполнение назначенных работ.
3. `apps/web/features/teacher-*` — authoring, students и access grants.
4. `apps/web/components/ui/*` — role-neutral primitives без доменной логики.
   `apps/web/components/assessment/*` — общий безопасный renderer Markdown, формул и авторизованных рисунков.
5. `apps/web/lib/api/*` и `apps/web/lib/query/*` — transport и server state.

Teacher и student получают отдельные role-specific layouts и feature-контуры. Старые dashboard shells удалены; новые создаются только вместе с реальным каталогом и authoring flow. Cross-import между role-specific features запрещён.

## Цветовая схема рабочих экранов

Teacher, student и admin используют светлую рабочую поверхность независимо от системной темы и сохранённого `continuum-theme`. В `app/globals.css` `:root` задаёт `color-scheme: only light` и базовые светлые tokens; нативные checkbox/radio/select/input, полосы прокрутки и portal-содержимое не наследуют dark chrome на белом фоне. Не подменять нативные чекбоксы рисунками и не добавлять точечные theme-патчи в каждый feature.

Автоматическая/сохранённая тема остаётся для композиции входа: dark tokens ограничены `:where([data-theme="dark"] .glass-scope)`. Низкая специфичность сохраняет локальные цвета `pageDark`/`pageLight`. Сейчас `glass-scope` используется только входом; рабочие layouts и порталы нельзя помещать в этот декоративный контур. Нативные поля входа также остаются светлыми. Смена системной темы, client navigation после входа и старое сохранённое значение `dark` не переключают рабочий UI. Это одинаково для desktop browser, mobile browser и PWA; `forced-colors`/системный режим высокой контрастности не отключается.

## PWA на телефоне

Общий `app/layout.tsx` подключает `public/site.webmanifest`, название приложения, Apple web-app metadata, `apple-touch-icon` и белый `theme-color`. Manifest задаёт `display: standalone`, язык `ru`, стабильные `id`, `start_url`, `scope` = `/`. Установка со страницы конкретной работы не закрепляет её ID в launch URL. Общий `/` использует `features/auth/AppEntry` и существующий `useAuthSession`: действующая сессия открывает `/teacher`, `/student` или `/admin`, отсутствие сессии — `/login`. Сетевая ошибка показывает повтор проверки и не трактуется как выход. Это поведение одинаково для обычного браузера и PWA. Права и сохранение ответов работают по прежним правилам; установка сама по себе не продлевает вход.

Иконки — предоставленный чёрно-серый знак на светлом фоне: PNG 192/512 для Android, отдельный непрозрачный `android-maskable-512x512.png` с безопасным кругом радиуса 40% ширины, Apple 180 px, favicon 16/32 и ICO 16/32/48. Скругление применяет ОС. App Router `app/favicon.ico` и `public/favicon.ico` согласованы. Maskable экспорт уменьшает исходный квадрат до 420 px внутри 512 px с полями 46 px; фон заполнен исходной текстурой, знак не перерисован.

`statusBarStyle: default` сохраняет системную строку состояния. `viewport-fit: cover` не включён: браузер/ОС оставляет безопасные области у выреза и индикатора жеста. Пользовательское масштабирование доступно. Login использует `100dvh` с fallback `100vh`; поля на телефоне имеют 16 px. Общий Dialog ограничен `100dvh - 24px`, включая низкие viewport. Существующие role-specific меню и ссылки возврата используются и в standalone; отдельной PWA-навигации нет.

Установка требует HTTPS (localhost допустим для разработки). iPhone: Safari → «Поделиться» → «На экран Домой», «Открывать как веб-приложение» включено, если переключатель доступен. Android: меню Chrome → «Установить приложение» / «Добавить на главный экран»; формулировка зависит от версии браузера. Запускать с созданной иконки. Адресная строка и панели браузера скрыты, системные часы/батарея остаются. Старую установку с кешированной иконкой может потребоваться удалить и добавить заново.

Работа требует сети. Service worker, offline-кеш страниц/API/фото, push и собственные install-баннеры не вводятся. Для физической приёмки: установить на iPhone и Android, закрыть/запустить с иконки, войти, проверить навигацию и возврат из работы, ввод с экранной клавиатурой, прокрутку/диалоги и выход. Desktop responsive QA не подтверждает поведение ОС. Основания: [Next.js PWA](https://nextjs.org/docs/app/guides/progressive-web-apps), [Google install criteria](https://web.dev/articles/install-criteria), [Google maskable icons](https://web.dev/articles/maskable-icon), [WebKit Safari 26](https://webkit.org/blog/17333/webkit-features-in-safari-26-0/).

## Routes Map

- `/login` — единый вход.
- `/student` — доступные возрастные группы и каталог.
- `/student/lessons/[lessonId]` — открытие опубликованных PDF конспекта и задач; интерактивный проигрыватель ещё не подключён.
- `/student/works`, `/student/works/[id]` — собственные назначения, начало/продолжение, автосохранение и завершение.
- `/teacher` — обзор материалов.
- `/teacher/materials` — разделы и занятия.
- `/teacher/materials/[lessonId]` — редактирование и публикация занятия.
- `/teacher/students` — классы, отдельное и массовое создание учеников, переводы, доступы и сброс пароля.
- `/teacher/bank` — банк заданий, предпросмотр, импорт и экспорт ZIP.
- `/teacher/works`, `/teacher/works/[id]` — список, конструктор и предпросмотр работ.
- `/teacher/works/[id]/assign`, `/teacher/works/[id]/preview` — выбор редакции и классов, отдельный просмотр условий.
- `/teacher/works/assignments`, `/teacher/works/assignments/[id]` — список назначенных версий и таблица выполнения.
- `/admin` — системное администрирование; управление преподавателями будет добавлено в новом identity flow.

Старые `/student/courses*`, `/student/sections*`, `/student/units*`, `/teacher/sections*`, `/teacher/units*`, `/teacher/review*`, `/teacher/events` и `/teacher/analytics` удалены. `/student`, `/student/lessons/[lessonId]`, `/teacher/materials` и `/teacher/students` работают через новый API. Teacher materials использует вкладки классов, сворачиваемые разделы, инспектор занятия и versioned upload готовых артефактов.

## Верхняя навигация учителя

`features/teacher-shell/TeacherChrome` объединяет `ContinuumHeader` и пять ссылок teacher-разделов. Используется материалами, учениками, банком, работами/назначениями/статистикой и подключением агента. Весь блок закреплён через CSS `position: sticky; top: 0`, находится в потоке страницы и сохраняет высоту: 128 px на desktop, 106 px при ширине до 700 px. Нет scroll handlers, скрывания по направлению прокрутки, изменения высоты или навязанного smooth scroll. Непрозрачный фон и тонкие разделители сохраняются.

Горизонтальная навигация прокручивается отдельно, активная ссылка открывается в видимой области. Для teacher-страниц `body:has(.chrome)` использует `overflow-x: clip`: прежний `hidden` создавал ложного scroll-предка и ломал sticky. Глобальный foundation и student layout не меняются. У прямого `main` задаётся `--teacher-chrome-height` и scroll margin фокусируемых элементов. Закреплённые заголовки таблицы выполнения располагаются под панелью; на телефоне таблица сохраняет существующую строчную адаптацию.

Общее меню профиля обеих ролей — немодальный Radix DropdownMenu: не блокирует прокрутку `body`, сохраняет позицию страницы и привязку к кнопке. Клавиатура, Escape, закрытие снаружи и возврат фокуса сохраняются. Это навигационное меню; прикладные диалоги по-прежнему модальные.

## Различимость прогресса назначения

В `AssignmentReportView` фильтр «Тестовая часть» открыт: четыре кнопки с `aria-pressed`, счётчиками и обычной клавиатурной активацией. На телефоне — две колонки. Это фильтрация существующей таблицы, не новые вкладки. Счётчики учитывают класс, поиск и независимый фильтр развёрнутой части, но не выбранный тестовый статус; URL `status`, Back/Forward и сброс страницы сохраняются. Отсутствующая тестовая часть скрывает группу.

`ReportTestStatus` дополняет подпись значком и сдержанной заливкой: нейтральный круг — «Не начата», синий круг с точкой — «В работе», зелёный круг с галочкой — «Завершена». Цвет означает прогресс, не правильность. Балл остаётся отдельной строкой; фото и опубликованные проверки сохраняют независимый смысл.

## Получатели назначения у заголовка

`teacher-assignments/AssignedClasses` находится под версией, составом и баллами работы в `AssignmentReportView`. Видимая строка «Назначено» содержит одну текстовую кнопку: названия одного/двух коротких классов либо количество классов, затем общее число получателей. Для одинаковых названий разных учебных лет используется количество. Длинная сводка ограничена шириной контейнера; полное доступное имя сохраняется. Число получателей относится ко всей версии и не зависит от поиска, состояния или выбранного класса.

Кнопка открывает немодальный Radix Dialog: привязанную панель до 400 px на desktop, нижнюю панель до 80dvh на телефоне. Нет раскрытия в потоке, постоянной боковой колонки или дополнительного ряда кнопок. Открытие не сдвигает таблицу и не блокирует body, поэтому закреплённая шапка сохраняется. Панель содержит название, учебный год, число исторических получателей каждого класса и отдельное удаление назначения. Нажатие снаружи/Escape закрывает панель; прокрутка страницы закрывает desktop-привязку, внутренняя прокрутка списка остаётся доступной. У панели есть явное закрытие 44 px и доступный заголовок. На телефоне панель также немодальная: нет несохранённой формы, фон доступен, переход фокуса наружу закрывает панель.

Перед `RevokeAssignmentDialog` список закрывается; подтверждение получает начальный фокус на «Отмена». После отмены или удаления фокус возвращается к сводке, если отчёт остаётся открыт. Подпись «Удалить назначение…» отражает существующую необратимую операцию; snapshot hash, запросы, защита повтора и переход после удаления последнего назначения сохраняются. «Добавить учеников» остаётся видимым существующим действием и не дублируется в панели.

Фильтр «Класс» показывается только при нескольких назначениях. `useReportFilters` игнорирует и нормализует через replaceState недействительный либо избыточный одиночный class, сохраняя поиск, status, photos и страницу. После фактического удаления назначения существующий handler сбрасывает класс и страницу. Формы назначения и сводка используют общие русские подписи счётчиков из `assignment-labels`.

## Выравнивание пунктов меню

Общий `DropdownMenuItem` использует flex, вертикальную центровку, промежуток 10 px между значком и текстом, минимальную высоту 44 px. SVG не сжимается и не участвует в базовой строке текста. Это правило действует для меню обеих ролей; текстовый пункт без значка не получает пустой отступ. Feature-палитра меню задаёт реальные токены (`--radius-control`, `--glass-border`); `--control-radius` не управляет скруглением Radix item.

## Подтверждения

В обеих ролях прикладные подтверждения используют существующий `components/ui/AlertDialog` на Radix и локальный `useConfirmation`: белый прямоугольный диалог без декоративного blur/shadow, конкретные цель и последствия, «Отмена» в начальном фокусе. Действие фиксируется при открытии; повторные клики не меняют его цель. Пока Promise выполняется, обе кнопки и Escape заблокированы; диалог закрывается после успеха, ошибка выводится внутри с возможностью повтора того же действия. Неизвестные технические ошибки не показываются сырым текстом. После отмены восстанавливается фокус на существующий trigger; для меню ученика он передаётся явно. Секреты в описания не включаются, глобального провайдера/очереди нет.

Заменены системные окна сброса пароля/удаления ученика/архива класса, закрытия одноразовых доступов и неопределённого результата массового создания, отзыва ключа агента, загрузки сохранённой версии после конфликта и удаления фото ученика. Специальные диалоги удаления банка/работ/назначений/материалов сохраняются. Новые подтверждения для обычных действий не добавлены. AlertDialog не закрывается кликом по фону; Escape и отмена работают вне pending.

Обычные ссылки и кнопка возврата из конструктора вызывают `useSaveBeforeLeave.request` через `WorksShell`; тот же guard передаётся в `ContinuumHeader.beforeLogout`. Он немедленно запускает/дожидается последовательного `useWorkDraft.flush`, включая ввод до debounce. Общий `lib/navigation/use-save-before-leave` также обслуживает прежний `useStudentLeave` через compatibility re-export: единственный history engine сохраняет поля Next, восстанавливает позицию при Back/Forward, затем разрешает согласованный переход. Модифицированный клик, новая вкладка и скачивание не считаются уходом. Ошибка оставляет экран доступным, показывает плоский белый диалог «Остаться / Повторить сохранение / Выйти без сохранения» с начальным фокусом на безопасном действии. Discard останавливает будущие запросы и обновления cache из позднего ответа, не откатывая уже записанное сервером.

`RoleGuard` сохраняет уже открытый teacher editor `/teacher/works/[uuid]` при потере сессии/сетевой ошибке. `WorkReauthenticate` использует существующий `authApi`, фиксированный логин и проверку исходного ID/роли до восстановления session cache и повторной записи. Другой аккаунт не получает этот черновик. Первоначальный доступ без авторизации, списки работ и назначения этим исключением не открываются. Черновик находится только в памяти вкладки. Системное предупреждение `beforeunload` остаётся для закрытия/перезагрузки и междокументного ухода; его оформление и надёжность контролирует браузер.

## Банк заданий

Фильтры `/teacher/bank` хранятся в URL: `grade`, `search`, `topicPath`, `type`, `exam`, `source`, `page` (прежний `topic` читается для существующих ссылок); `task` хранит UUID открытого задания. Ввод поиска заменяет текущую запись истории; выбор задания, смена остальных фильтров и страницы добавляют запись. Обновление, прямая ссылка и Back/Forward восстанавливают фильтры и открытое условие; на телефоне ссылка с `task` сразу открывает предпросмотр, «К списку» убирает этот параметр. Невалидные поля получают безопасные значения, смена фильтра/страницы сбрасывает выбор, опустевшая страница ограничивается последней доступной. Если после успешной загрузки выбранного ID нет в текущем списке, параметр убирается через replace, доступен первый элемент или пустой список. При сетевой ошибке выбор не сбрасывается. `task` не передаётся в запрос списка/экспорт и не позволяет читать задание вне авторизованного списка. Состояние сервера остаётся в TanStack Query, browser storage банка не используется.

Меню «Действия с заданием» (`⋯`) в панели предпросмотра содержит удаление из банка. Диалог объясняет сохранность уже собранных работ и восстановление импортом; начальный фокус на отмене, закрытие и повтор блокируются во время запроса. После удаления обновляются список, темы и выбранное задание; последняя пустая страница переключается назад. На телефоне меню остаётся рядом с возвратом к списку. Светлая цветовая схема и фон полей закреплены локально в teacher-bank, включая вложенный предпросмотр: системная тёмная тема не делает нативное поле чёрным.

`features/teacher-bank` использует существующие шапку и учительскую навигацию, вкладки возрастных групп, компактный список шириной 260–360 px и широкую область условия без новых dashboard shells. На desktop список и условие имеют независимую нативную прокрутку в ограниченном workspace; toolbar и навигация остаются за пределами scroll-области условия. Его можно развернуть, скрыв список без сброса выбранной задачи. На узком экране подробности открываются вместо списка с возвратом назад. Источник и внешний ID видны сразу, расширенные метаданные и версия — в раскрываемом блоке. Ответ/разбор помечен «Только преподавателю».

Рабочие экраны teacher/student используют общие семантические `--catalog-*` из `globals.css`: стальной синий `#445F92` для действий, `#354D7B` для hover, светлый `#EDF2FA` для выбора. Текущий раздел навигации графитовый; выбранная параллель и задача используют акцент и явный контур/подчёркивание. Успешные результаты сохраняют отдельный зелёный `--catalog-success`; ошибки/удаление — danger. Общий CSS Module `components/ui/catalog-action.module.css` задаёт primary/secondary и их hover/disabled/focus через `composes` для банка, работ, классов, подключения агента и ученического выполнения. Геометрия остаётся в role-specific features; общие токены доступны портальным диалогам. Размеры заголовков, внешние отступы, ширины, плотность и серверное поведение сохранены.

Импорт — отдельный полноэкранный сценарий «Пакет → Проверка → Результат», а не немедленная запись после выбора файла. До подтверждения доступны статусы изменений и полный предпросмотр. Server state и invalidation находятся в TanStack Query hooks; transport parsing использует shared Zod-контракты.

Банк `TeacherBankScreen`, проверка импорта `BankImportReview` и подбор/просмотр выбранных заданий `WorkBankPicker` используют общий CSS Module `components/ui/task-workspace.module.css`: высота desktop workspace — `clamp(360px, 65dvh, 760px)`, список и условие прокручиваются независимо через нативный `overflow-y: auto`. Между списком и разделителем оставлен зазор 24px (16px до 1150px), справа от разделителя — внутренний отступ условия. Scrollbar находится у правого края своей области; `scrollbar-gutter: stable` предотвращает сдвиг содержимого. Список сохраняет DOM, позицию и чекбоксы при выборе; ключ меняется только у области условия, чтобы новая задача открывалась сверху без потери фокуса кнопок навигации. Области именованы, доступны с клавиатуры; загрузка условия помечена `aria-busy`. До 800px банк и подбор сохраняют переход «список ↔ условие», а импорт показывает список высотой до половины viewport и условие ниже; условие использует обычную прокрутку страницы. Student-контур не меняется. Референсы: [GitHub Primer SplitPageLayout](https://primer.style/product/components/split-page-layout/) — именованная pane и responsive-разделение; [Mantine AppShell.Section](https://mantine.dev/core/app-shell/#appshellsection-component) — ограниченная область и прокрутка её содержимого. Используется layout-принцип без добавления библиотек.

На результате подтверждённого импорта `BankImportResult` предлагает необязательное создание работы рядом с возвратом в банк. `useImportWork` использует существующий TanStack create-hook работ, фиксирует один UUID и начальное тело на попытку, блокирует синхронный повтор и сохраняет запрос для retry. Начальный состав берётся из упорядоченных закреплённых ссылок confirm, включая неизменённые задачи; детали не перечитываются по latest и не передаются через URL/browser storage. При успехе detail-cache уже заполнен ответом, список работ инвалидирован, переход идёт в обычный WorkEditor с `?from=import` для фокуса/выделения названия. После перехода discard preview выполняется независимо; ошибки очистки не отменяют созданную работу. На телефоне две кнопки располагаются вертикально. У полностью неизменённого пакета frontend допускает confirm через «Продолжить»; результат называется «Пакет обработан». Для старого результата без закреплённых ссылок CTA скрыт.

Markdown преобразуется в ограниченное дерево и рендерится React без сырого HTML. Общий `components/assessment/AssessmentMarkdown` мемоизирован и используется банком, конструктором и ученическим выполнением. MathJax загружается по необходимости; runtime и шрифты копируются в `public/vendor/mathjax` через `sync-mathjax-assets.mjs`, внешняя CDN не требуется. `AssessmentImage` использует `crossOrigin="use-credentials"`, чтобы запрос проходил через уже настроенный credentialed CORS, в том числе между localhost:3001 и :3000. Допустимы только image routes банка или собственной ученической работы; чужой произвольный URL не используется. Глобальная CORP-политика API не ослабляется. Ошибка рисунка заменяет `<img>` компактным сообщением с повтором; закрытые ключи не передаются в student features.

`components/ui/SearchField` — общий контролируемый поиск: банк, ученики, список работ, выбор заданий, назначения, отчёт и выбор учеников подключения агента используют одну реализацию. Внешний контейнер получает `focus-within`, включая лупу и очистку; внутренний `type=search` имеет appearance none/radius 0 без собственного outline. Нативный cancel заменён на `Очистить поиск` с aria-label, клавиатурным фокусом и type=button. Пустая кнопка скрыта/disabled с резервированием места; disabled отключает и поле, и очистку. Очистка вызывает прежний callback с пустой строкой и возвращает фокус в input, сохраняя остальные фильтры. Необязательный `inputRef` позволяет экрану работ вернуть фокус после действий над работой. На телефоне шрифт 16px; layout остаётся у feature, а внутренние стили защищены от широких feature-селекторов. В мобильном выборе заданий параллель и поиск занимают полную строку, поле темы и кнопка остальных фильтров стоят рядом. Глобальный radius, Login/Input и student UI не изменяются; локальных type=search в production features больше нет.

### Исправление условия

`BankTaskActions` передаёт снимок выбранной задачи в `TeacherBankScreen`, который держит `BankTaskCorrection` вне условной рабочей области. Диалог остаётся открытым, если исправление убрало задачу из текущей поисковой выдачи. В диалоге можно скачать её ZIP, загрузить один исправленный stable ID и сравнить только условие/рисунки/варианты: без фиктивных полей ответа и повторяющихся сведений. Источник показан один раз в заголовке; технический stable ID остаётся в сообщениях об ошибке несовпадения. Сохранение появляется после успешного preview. Сравнение: две колонки desktop, переключатель «Сейчас / Исправление» на мобильном full-screen. Данные preview/correct/download — TanStack mutations/queries, API-контракты shared. До предпросмотра и подтверждения сохранения нет. Подтверждение неизменности смысла обязательно; сервер отдельно защищает ключ/тип/баллы/ID вариантов и ownership. После ошибки запрос повторяется с тем же importId/expectedVersion; замена ZIP начинает новое подтверждение. Pending блокирует повтор и закрытие; успех явно сообщает сохранность ответов/баллов.

`useCorrectBankTask` обновляет bank/works/statistics cache. У ученика текущий availability polling сообщает `presentationRevision`; `StudentWorkSession` перечитывает detail, сохраняя key игрока, локальные ответы и фокус. Общий Markdown-parser поддерживает сохранённые display-формулы внутри абзаца и отклоняет непарные разделители. При создании новых архивов display-формулы готовятся отдельными блоками по [гайду](ASSESSMENT-PACKAGE.md).

## Конструктор работ

В «Моих работах» подпись показывает только факт наличия назначений: «Не назначена» / «Назначена». Обязательный `hasAssignments` приходит в DTO списка из API; frontend не выводит статус из права `canDelete`, ревизии или наличия сохранённой версии. Отметка «Архив» независима и не заменяет подпись назначения. После успешного назначения `useAssignWork` инвалидирует список работ; существующий отзыв назначения также обновляет его. Технический «Черновик» в списке и редакторе не показывается. Обычные правки, presentation corrections и состояние прохождения не добавляют отметок редакции/изменений. Текущая обратная связь автосохранения («Сохраняем», «Сохранено», ошибки) сохраняется.

Импорт банка запрашивает duplicate hints отдельным TanStack query после preview, с gcTime 0, retry false и без refetch-on-focus. Query не входит в busy/disabled подтверждения; pending/unavailable/error — неблокирующий текст с ручным повтором. Отмечаются только stableId из текущего preview. BankImportReview отвечает за список/условие/подсказки; BankDuplicateWarnings открывает общий Dialog с двумя BankTaskPreview. Кандидат банка запрашивается по pinned version, ZIP — через preview endpoint. На mobile колонки становятся вертикальными без горизонтального overflow; закрытие возвращает focus на исходное «Сравнить» через Dialog onCloseAutoFocus. Данные preview не копируются в browser storage.

В `/teacher/works` поиск и «Текущие / Архив» сохраняются в URL (`search`, `show=archived`): поиск заменяет history, переключатель добавляет. Ссылки строк переносят эти два параметра в редактор, «К работам» возвращает их через whitelist без произвольного return URL. Reload, Back/Forward и явная кнопка возврата восстанавливают контекст. Поиск ограничен 200 символами, неизвестный show трактуется как текущие работы; серверный список не дублируется в browser storage.

В «Добавить из банка» доступны exam/provider из существующего API, совместно с параллелью, поиском, темой и типом. Смена фильтра сбрасывает страницу/мобильное условие, но не выбранные закреплённые версии. При пустом отфильтрованном наборе «Сбросить фильтры» сохраняет параллель и selection. Общий `teacher-bank/BankFilters` используется обоими teacher-экранами: `BankTopicPicker` строит иерархию из полных API `topicPaths`, `BankExtraFilters` применяет черновик типа/ЕГЭ/источника одним действием. Путь, включая выбранный до обновления facets, остаётся в кнопке с многоточием; полное значение видно в строке активного условия. `BankFilterPanel` использует существующий Radix Dialog: привязанный к кнопке popover на desktop и нижняя панель до 85dvh на телефоне, портальное содержимое использует токены каталога. Раскрытие/возврат внутри тем локальны и не меняют query, выбор узла передаёт весь путь. Enter/Tab работают как для обычных списков кнопок, Escape закрывает окно и возвращает фокус; фиктивные tree-роли не используются. Локальные состояния окна не дублируют серверные данные. В банке и preview импорта ошибка условия имеет read-only «Повторить загрузку условия»; повтор не запускает импорт или запись в банк.

Клавиатурный `data-highlighted` в меню действий работ получает явный светло-зелёный фон с selector, специфичнее общего DropdownMenuItem. Пункты удаления сохраняют красное выделение. Escape возвращает фокус на trigger.


В «Моих работах» поиск соседствует с обычным select «Показывать: Текущие работы / Архив». Это локальный фильтр общего owner-scoped query, не новая вкладка. Пустой архив объясняется короткой фразой; поиск применяется внутри выбранной группы. Архивирование/восстановление выполняются через `⋯` без подтверждения, не закрывают ученикам назначения и не запрещают редактирование по прямой ссылке. Состояние «Архив» видно в строке и редакторе.

«Удалить черновик» отделено разделителем и показано только при `canDelete`; сервер перепроверяет использование. Компактный белый Radix-диалог сохраняет начальные название/revision/lifecycleRevision при фоновом обновлении. Фокус — на отмене, pending блокирует закрытие и повтор, ошибка остаётся в диалоге. После отмены фокус возвращается в меню строки, после удаления/скрытия — в поиск; при архивации подавляется стандартный возврат Radix на исчезающий trigger. Detail и все preview-cache entries удалённой работы очищаются. API-мутирования/invalidation остаются в query hooks; неизвестный результат архивирования повторяется с прежним payload, без автоматического применения нового намерения к обновлённому состоянию.

В списке `/teacher/works` у каждой строки есть Radix-меню `⋯` с «Создать копию». Действие копирует текущую сохранённую ревизию, не ввод открытого редактора. Успех заполняет detail query cache и открывает новый черновик; во время запроса меню блокируется, у строки показано «Создаём копию…». Ошибка и явный повтор остаются у той же строки. При неопределённом исходе повтор использует прежние ID/ревизию даже после обновления списка; определённый 4xx-конфликт позволяет явно повторить уже с актуальной ревизией. Нет отдельного подтверждения, новых вкладок или формы копирования. Список работ обновляется через TanStack Query.

При пропуске удалённых заданий редактор копии показывает спокойное текстовое сообщение с числом пропусков при создании. Это не блокирует редактирование, включая пустую копию. Меню использует существующее плоское белое оформление и клавиатурное управление.

`features/teacher-works` сохраняет общий teacher header и плотный белый стиль. Конструктор — полноширинный список с раскрытием условия, а не две постоянные равные колонки. Выбор из банка открывается отдельно, с фильтрами, отметками и широким предпросмотром; на мобильной ширине список и условие переключаются. Источник не подменяется порядковым номером работы.

Выбор из банка не добавляет ряд вкладок к общей навигации. После первой отметки появляется белая нижняя панель с тонким нейтральным разделителем: один счётчик/баллы, вторичное «Посмотреть» и основное «Добавить в работу». Прямое добавление не требует просмотра. На мобильной ширине для переноса итога и действий используются ограниченные grid tracks; фактическая геометрия проверяется отдельно в браузере. Ошибка добавления остаётся рядом с действиями в панели, отметки сохраняются.

«Посмотреть» меняет заголовок на «Выбранные задания», скрывает фильтры и показывает весь локальный набор закреплённых версий с метаданными и полным условием. Верхнее «К банку» восстанавливает фильтры/страницу; возврат к конструктору остаётся отдельным действием из банка. Смена режима переводит фокус на заголовок и возвращает мобильный экран к списку. После снятия последней отметки просмотр остаётся пустым, без автоматического переноса пользователя. Уже включённые в работу задания не учитываются; порядок правится только после добавления в конструктор. Детали загружаются через TanStack Query по ID и конкретной версии; latest и историческая версия не делят cache entry. Список выбранного не запускает массовую загрузку всех условий.

Native drag работает только за ручку; маркер показывает место вставки. Доступные альтернативы — стрелки клавиатуры на ручке и Radix-меню «Выше», «Ниже», «На позицию…». Удаление меняет только состав и имеет отмену последнего действия в пределах лимита. В редакторе ключи остаются отдельным закрытым disclosure.

Существующий `WorkPreview` использует role-neutral `components/assessment/AssessmentQuestions` и `AssessmentAnswerInput`: одна задача, номера/состояния, компактный мобильный навигатор и общая типографика/контролы с учеником. `StudentWorkQuestions` сохраняет только ученическую orchestration: session position, requested task и фото/публикации; teacher feature не импортирует student feature. Общий компонент получает явный whitelist публичных полей без grading/solution. Стили полей ограничены workspace, чтобы широкие teacher selectors не растягивали radio/checkbox.

Пробные ответы `WorkPreview` хранятся отдельно от `useWorkDraft`, без student endpoints, попыток и storage. Выход из просмотра и смена работы/версии/набора задач очищают ввод. Пробные фото используют локальные blob URL, общий viewer и существующий `solutionPhotoPolicy`; remove/unmount освобождает URL. В `SolutionPhotoList` blob URL обрабатывается локально, серверные пути по-прежнему получают API base.

`WorkPreviewAnswerCheck` запускает TanStack mutation только по «Проверить ответ», без invalidation/записи query данных работы. Payload содержит ID задачи и явную ревизию черновика/номер версии, не ключи. Результат/ошибка привязаны к точному payload: правка поля, переход на другое задание или смена source не показывают запоздалую отметку для другого ввода. Пока черновик не сохранён, проверка отключена; сетевую ошибку можно повторить. `Сохранить версию` остаётся прежним отдельным действием и не включает пробные ответы. Учительский API/права описаны в [ASSESSMENTS](ASSESSMENTS.md).

Числовая оценка в preview и ученическом результате использует `data-score`: `correct` — зелёный `#0b6b4f`, `partial` — тёмный янтарный `#805816`, `incorrect` — красный `#a33a32`. Текст «Баллы: X из Y» сохраняет смысл без цвета; плашки и словесные оценки не добавлены. Банк показывает человекочитаемые тип и правило в существующем disclosure «Источник и сведения», без нового фильтра/переключателя. Student список использует сохранённые points/maxPoints с fallback для прежнего DTO; промежуточные баллы не называются полностью верными ответами.

Query hooks хранят серверные данные, `useWorkDraft` — редактируемый локальный черновик и последовательное автосохранение. У неподтверждённого запроса сохраняются прежние `requestId` и payload; после ответа сохраняются следующие изменения. Конфликт ревизий не сбрасывает форму без подтверждения. Browser storage для условий/ключей не используется. Полные правила и API — [ASSESSMENTS](ASSESSMENTS.md).

## Назначение и выполнение

`features/teacher-statistics` — отдельный teacher-раздел `/teacher/statistics`. Список использует `use-statistics-list-filters.ts`: название/класс в URL, ввод поиска через replaceState, выбор класса/сброс через pushState. Статическая страница обёрнута Suspense. Ссылка версии передаёт `listSearch`/`listClass` для возврата и сопоставленный ID назначения в `class`; обратная ссылка строится по whitelist на фиксированный локальный маршрут. Переключатель «По заданиям / По ученикам / Сравнение классов» и класс находятся в одном компактном ряду. Основной экран — настоящая таблица с общими балльными колонками, строками около 48px, поиском и сортировкой по заголовкам. Формат значений переключает долю учеников на количество. Цвет только дополняет цифры; незавершённые и непроверенные результаты отделены от нуля.

`StatisticsScoreTable` используется для заданий и классов; `statistics-table.ts` содержит сортировку, форматирование и фильтрацию групп. Балльная группа открывает учеников в одной правой панели `StatisticsDetailsDrawer`; из неё доступны сохранённый ответ и переход к отфильтрованной матрице. Условие/источник открываются по названию или кнопке номера колонки матрицы. Кнопка имеет доступное имя с номером и названием, зону не менее 44px; переиспользует ту же панель без переключения представления и сброса фильтров. `StatisticsAnswerContent` загружает фактические данные только по запросу. Панель использует существующий Dialog с focus trap, Escape и возвратом фокуса, на телефоне занимает всю ширину. Стили панели scoped и имеют приоритет над общим центрированным Dialog.

Распределения заданий/классов имеют локальный горизонтальный скролл и sticky-шапку; на мобильном название задания закреплено слева. Экран версии расширяет только собственный teacher main до 1920px через `WorksShell.mainClassName`. Матрица учеников — фиксированный colgroup (имя 200px, класс 80px, задача 56px, итог 84px), без растягивания пустого пространства. Слева sticky-имя, справа sticky-итоги с offsets по присутствующим частям. Номера и баллы центрированы по одной оси, `1/2` не переносится; в ячейках pending — прочерк с доступным состоянием. Контейнер матрицы не ограничивает высоту: вертикально движется страница, горизонтально — матрица. До 900px правые итоги не закрепляются, чтобы сохранить область заданий; до 760px имя 160px. Страницы по 20 учеников; выбранное задание оставляет одну колонку рядом с итогами. `displayName` использует явные поля профиля; исходное ФИО и CSV сохраняются. URL хранит класс/представление/задание/балл/наличие результата/страницу, единицы и сортировку. Поиск локальный; ФИО и ответы в URL не записываются. Смена представления переводит фокус к его содержимому. Знаменатели, отсутствие части/результата, исторические баллы и публикации — в [ASSESSMENTS](ASSESSMENTS.md#учительская-статистика).

В матрице учеников «Скачать CSV» использует весь отфильтрованный набор до пагинации и текущий выбор колонки задания. `statistics-csv.ts` формирует файл из существующего read DTO, без дополнительных запросов и browser storage. Пустые баллы не заменяются нулём; строковые значения защищены от spreadsheet formula injection. Кнопка со счётчиком находится под таблицей, на телефоне имеет высоту не менее 44px; новые меню/вкладки не добавляются.

`features/teacher-assignments` переиспользует teacher shell, прямоугольные controls и существующие токены. Внутри «Работы» — вкладки «Мои работы» и «Назначения». Назначение — один экран: редакция, просмотр, чекбоксы классов, раскрываемый состав, итог получателей. Нет постоянного второго инспектора или диалога с тяжёлой таблицей.

Prepare-query не обновляет проверенный список в фоне; новая ревизия или состав загружаются явно. Кеш prepare удаляется при уходе с формы, чтобы новое посещение перечитывало получателей. При неизвестном результате POST форма блокирует изменение payload и сохраняет ключ повтора. Таблица выполнения получает server state через TanStack Query и обновляется каждые 10 секунд только в активной вкладке. Фильтрация выполняется локально; UUID назначения класса (`class`), `status` и `page` сохраняются в URL для обновления и Back/Forward. Поиск ФИО/логина в URL не записывается: до 200 символов в `sessionStorage` текущей вкладки, отдельно для преподавателя и версии отчёта, с очисткой при logout. Закрытие вкладки заканчивает хранение; при недоступном storage ввод работает, но после обновления не восстанавливается. Ответы, результаты и ключи в storage не попадают. Неизвестные состояния/классы дают «Все», номер страницы ограничивается доступными строками. Смена класса/состояния добавляет запись истории и сбрасывает страницу; ввод поиска только заменяет текущую страницу, без записи на каждый символ.

В отчёте controls идут «Класс → Поиск → Тестовая часть»: последнее поле — существующий WorkSelect с вариантами «Все / Не начали / В работе / Завершили» и счётчиками в пределах класса/поиска. «Все» снимает фильтр. Для работы без автоматических заданий поле скрыто, старый URL `status` не отфильтровывает учеников. Отдельных status-tabs нет. На телефоне поля полной ширины стоят друг под другом, font-size 16px предотвращает zoom. В смешанном отчёте пять колонок; статус/заполнение/автоматический балл объединены, фото и опубликованные проверки независимы. Отсутствующие части скрываются. Мобильная строка сохраняет подписи «Тестовая часть / Решения / Проверка», а ссылка на фото открывает прежнюю панель с PDF. Незавершённый тест не отображается как нулевой балл.

Ученический список показывает два текстовых прогресса без бейджей: тест и фото/публикации. `resultReady` и счётчики поступают из обязательного server DTO; роль не пересчитывает публикацию из наличия черновиков. В teacher-назначениях все агрегаты выражены в учениках; список тоже перечитывается каждые 10 секунд в активной вкладке. Подробный контракт — [ASSESSMENTS](ASSESSMENTS.md#независимые-состояния-частей).

Действия списка ученика добавляют `?view=solutions` или `?view=result`, не меняя права и API попытки. Проигрыватель дожидается актуального списка фото: первое действие выбирает развёрнутую задачу без фото, второе — задачу с опубликованным разбором. После выбора параметр удаляется через replaceState, позиция сохраняется существующим механизмом; последующая навигация не перехватывается обновлением данных. Обычное «Продолжить» сохраняет прежнюю позицию. Фото перечитываются при каждом входе в проигрыватель, чтобы старый cache не выбирал неверную задачу.

`features/student-works` получает отдельный whitelist DTO и не импортирует teacher features. Показана одна задача с навигатором; ввод и подтверждённые ответы разделены. Последовательное сохранение использует debounce 400 мс, `networkMode: always` и повтор прежнего payload при неизвестном исходе. Перед ссылкой/выходом из профиля очередь принудительно сохраняется; ошибка требует выбора ученика. `lib/navigation/history-position` устанавливается один раз в `QueryProvider`, сохраняет поля Next и валидные session/index после обновления страницы и позволяет feature-guard удержать неотменяемый `popstate` до решения об уходе, включая Back/Forward. Междокументный уход защищает native `beforeunload`. Завершение имеет сводку пропусков; восстановление входа сохраняет редактор той же работы. Полное поведение — [ASSESSMENTS](ASSESSMENTS.md).

Server state, ошибки, mutations и новые ученические ответы не записываются в browser storage. Настройка локального черновика удалена; `useAnswerDraft` только безопасно восстанавливает прежние записи, если они уже существуют. Logout очищает query cache и прежние черновики; успешный вход заменяет auth cache. Ключи обеих ролей централизованы в `lib/query/keys.ts`, русское сообщение API/сетевой ошибки — в `lib/api/error-message.ts`.

### Отзыв назначения

В отчёте версии native disclosure «Назначенные классы» раскрывает строки класса/года с «Убрать назначение», без новой вкладки или destructive checkbox. Radix-подтверждение переиспользует плоский белый dialog конструктора, показывает точную область удаления и текущие счётчики. Preview загружается при открытии; первый успешный снимок фиксируется в локальном state эффектом после commit, а не записью в ref во время render. Прерванная отрисовка не фиксирует recipients hash; до фиксации подтверждение отключено, дальнейшее фоновое обновление не расширяет удаление. Фокус на отмене, синхронный guard исключает повторный клик до перерисовки; закрытие при записи заблокировано, ошибка остаётся в окне. После отмены фокус возвращается на кнопку, после удаления — на summary списка классов; при удалении последнего назначения выполняется переход к назначениям.

Mutation обновляет report cache без удалённого класса/получателей и инвалидирует назначения/prepare/список работ. Student list и отдельный availability-query проверяются раз в 10 секунд только в активной вкладке и при возврате/восстановлении сети. Availability не перечитывает условия/ответы и не заменяет локальный ввод серверным. 404 или отказ записи размонтирует player, отключает detail-query и очищает detail/фото cache; сетевая ошибка этого не делает. Ни общий shell, ни teacher features в student не импортируются.

## Ученики и доступы

- «Изменить данные» в меню ученика открывает компактный диалог ФИО с явными «Отмена»/«Сохранить». Фокус сначала на фамилии, после закрытия — на кнопке меню. Отчество необязательно; логин показан только для чтения. Форма сохраняет начальные значения для проверки конфликта даже при фоновом обновлении списка; ошибка не сбрасывает ввод. Во время записи поля, закрытие и повтор блокируются.

Общее меню профиля обеих ролей использует существующий Radix DropdownMenu: Escape, внешний клик, клавиатура и возврат фокуса. Ролевые пункты и `beforeLogout` сохраняются, повторный выход во время ожидания блокируется. Оформление белое, плоское, без дополнительной страницы профиля.

- Один экран сохраняет создание отдельного ученика и полноэкранный мастер «Класс и список → Проверка списка → Доступы».
- Список фильтруется по классу и ФИО/логину. В выборе класса есть группы «Текущие классы» и «Архивные классы»; пустые группы не показываются. Архивный класс выбирается напрямую, отдельного переключателя архива нет. «Все ученики» и «Без класса» сохраняются. Счётчик подписан «Всего», а не оформлен как индекс заголовка.
- Классы редактируются и архивируются; удаление подтверждается отдельно, удаление учеников вместе с классом выключено по умолчанию.
- Меню ученика разделяет сброс пароля, удаление из класса, отключение и удаление аккаунта. Доступы к материалам остаются плоскими переключателями; при зачислении доступ своей параллели выдаётся автоматически.
- У native select собственный шеврон с внутренним отступом, без изменения общих компонентов другой роли.
- Доступы можно скачать в CSV или распечатать индивидуальными карточками: ФИО, адрес текущего домена с `/login`, логин, пароль, без бренда, предмета и класса. Длинные значения переносятся внутри двухколоночной печатной сетки.
- Одноразовые пароли не сохраняются в browser storage; неопределённый результат массового запроса повторяется с прежним ключом.

## Массовое удаление

Банк и ученики используют teacher-only примитивы `features/teacher-bulk-actions`: нативные чекбоксы, mixed-состояние общего выбора, счётчик и компактную строку действий над списком. Просмотр задачи остаётся отдельной кнопкой. Выбор всех охватывает текущую страницу банка или видимый список учеников; при числе свыше `BULK_ACTION_LIMIT` явно предлагаются первые 100. Смена фильтров/страницы снимает выбор; возврат к прежнему фильтру не возвращает старые отметки. При ошибке выбор сохраняется.

Удаление подтверждается общим `useConfirmation`/`AlertDialog`: количество, название для одной записи, последствия и безопасный начальный фокус на «Отмена». После успеха доступна «Отменить» для всей группы, без таймера. Ошибка восстановления оставляет receipt и повтор. Уведомления живут в текущем экране до закрытия/ухода; browser storage не используется. Фокус после закрытия возвращается к общему выбору, при пустом банке — к поиску; отмена/закрытие уведомления также возвращает его к поиску. Существующая одиночная отмена банка сохраняется; меню удаления ученика использует новый механизм на одном элементе.

Паттерны: [Carbon batch actions](https://www.carbondesignsystem.com/building-blocks/core/components/data-table/guidelines), [Shopify selection and actions](https://shopify.dev/docs/apps/build/app-home/migrate-from-polaris-react/unstable-bulk-actions), [Material snackbar action](https://m3.material.io/components/snackbar/overview). Используются существующие токены, нативные inputs и установленный Radix; новых UI-зависимостей нет.

## API Client Behavior

- Все запросы к API используют `credentials: "include"`.
- Login/session/logout выполняются Better Auth client.
- `401` означает отсутствие сессии; `403` — отсутствие роли или доступа к возрастной группе.
- Ответы критичных transport interfaces проходят Zod parsing.
- Object storage URL используется без cookie/credentials.

## Server-State Rules

- `@tanstack/react-query` — единственный общий server-state слой.
- Query keys и invalidation централизованы.
- Чтение и запись разделены: query для read-path, mutation для write-path.
- Draft editor state может быть локальным, но опубликованное состояние всегда перечитывается с сервера.
- UI не вычисляет доступ: API возвращает только разрешённые ученику сущности.
- Общий `ContinuumHeader` мемоизирован стандартным React `memo`, без custom comparator: ввод/сохранение ответа со стабильными props не перерисовывает профильное меню. Собственные auth query/state/context продолжают обновляться; новый `beforeLogout` должен учитываться, безопасный выход не кешируется.
- `useTeacherBank` общий для банка и конструктора: изменённая непустая строка поиска ждёт 300 мс через `enabled`, начальная загрузка/очистка выполняются сразу. Текущие фильтры остаются query key и значением UI/URL/экспорта; list-query передаёт TanStack `signal` в API client. Смена фильтров не показывает данные прежнего запроса под новым поиском.

## Materials

- В teacher-library удаление PDF находится рядом с открытием/заменой файла, удаление занятия — внизу инспектора, раздела — в заголовке раздела. Белый компактный диалог объясняет состав удаления; фокус сначала на «Отмена», после отмены возвращается к кнопке. Во время запроса повтор и закрытие блокируются, ошибка остаётся в диалоге. Серверный 409 требует нового подтверждения; списки и инспектор обновляются через query invalidation.
- PDF рендерится через PDF.js и скачивается по свежей presigned URL.
- Интерактивный ZIP пока загружается как черновик без ученического проигрывателя. Будущий запуск должен использовать отдельный sandboxed iframe, а не `dangerouslySetInnerHTML`.
- MathJax загружается локально.
- `@continuum/shared` помечен `sideEffects: false`: web использует ESM source alias и исключает неиспользуемые контракты/Markdown parser. Shared runtime-модули не должны полагаться на импорт ради внешней регистрации; если такой модуль появится, metadata нужно пересмотреть. Используемые схемы и локальная настройка parser сохраняются, CJS API exports не меняются.
- Excalidraw сохранён для будущих authoring-сценариев; его CSS и asset-path script не подключаются в root layout. Пакет/vendor сохранены, рабочие teacher/student экраны редактор не загружают. Будущий экран редактора должен подключить необходимые стили и assets в своём контуре.

## Фотоответы развёрнутых задач

Условие `extended` использует тот же role-neutral `AssessmentMarkdown`, формулы, таблицы и изображения, что автоматические задания. Под ним `StudentSolutionUpload`: компактная область выбора/перетаскивания, форматные ограничения и полученные страницы. На мобильном скрыта только подсказка о drag-and-drop; выбор файлов, крупный просмотр, замена/удаление остаются доступны.

В общем MathJax `output.linebreaks.inline = false` сохраняет короткие равенства целиком при переносе. Чрезмерно широкое содержимое прокручивается внутри Markdown-блока, не расширяя страницу.

`SolutionPhotoList` — общий просмотр собственных ответов ученика и решений в назначениях учителя, без импорта feature-кода другой роли. Превью сохраняет пропорции. `useSolutionPhotos` держит server state в TanStack Query, очередь выбранных файлов — только в памяти вкладки. Тестовые ответы и фото используют разные API/ревизии. Навигация/выход ждут обе очереди; неподтверждённые файлы не отмечаются полученными. Учительский просмотр — inline-панель из таблицы выполнения, не новый экран редактирования рецензий.

Опубликованная проверка добавляет баллы (включая ноль) и PDF под задачей у ученика/учителя. Черновик ученику не виден. Возврат во вкладку обновляет фотоответы только без локальной очереди/запроса; запись отменяет старый query, чтобы поздний ответ не затёр подтверждённую загрузку.

## Подключение агента

`features/teacher-reviewer` и `/teacher/reviewer-access` — teacher-контур подключения компьютеров. Вход через профиль, не пятая вкладка. Форма inline: название, классы, отдельные ученики под раскрытием (поиск/фильтр «Без класса»), пароль. Выбранные ученики сохраняются при фильтрации и выборе их класса; явный персональный доступ имеет другую семантику при переводе. Нет выбора работ, технических scopes или отдельного предоставления доступа коллеге. Инструкция подключения под раскрытием; строки подключений содержат название, доступ, срок и отзыв. Белый фон и тонкие разделители.

Server state проходит `lib/assessment/reviewer.api.ts`, shared Zod и центральные query keys. Исключение — однократный secret: прямой abortable request и короткоживущее состояние компонента, без mutation/query cache и storage. «Готово», отмена, logout и unmount очищают его; поздний ответ после отмены игнорируется. Список не содержит raw key. Подключение описано в [REVIEWER-CLIENT](REVIEWER-CLIENT.md).

### Фото решений: очередь и фильтры

Учительский отчёт использует существующие `WorkSelect` в адаптивной сетке фильтров. Фото и тест — независимые оси; URL хранит только разрешённый enum `photos`, ФИО остаётся приватным поиском вкладки. Видимый язык: «Тестовая часть», «Развёрнутая часть», «N из M заданий», «Решения», «Проверено». «Фото» используется только для прикрепления и просмотра конкретных файлов. Внутренние `photoTaskCount` и URL `photos` сохраняются; техническая модель не выносится в постоянные пояснения. Блок `.report` и элементы `.report__solutions`, `.report__open` локальны CSS Module; стили не зависят от перевода `data-label`.

Ученическая очередь — локальное состояние `File` и описаний в `useSolutionPhotos`, серверная галерея — TanStack Query. `StudentPhotoQueue` показывает построчные состояния без фиктивного процента. Ошибка файла и действия продолжения/очистки находятся рядом с очередью; при переходе к другой задаче верхний статус возвращает к задаче с неподтверждёнными фото. Принятые файлы не удаляются очисткой очереди. Открытая teacher-панель обновляется Query polling раз в 10 секунд без background refetch, сохраняет данные при ошибке и выбранное фото при обновлении.
