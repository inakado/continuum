# Интерактивная лекция: пакет v1 и проигрыватель

Назначение: контракт импортируемого материала, локальная сборка и технические границы общего проигрывателя. Учебные и визуальные паттерны — [INTERACTIVE-LESSONS](INTERACTIVE-LESSONS.md), публикация и права — [CONTENT](CONTENT.md), изоляция — [SECURITY](SECURITY.md).

## Разделение ответственности

- Приложение предоставляет настоящий `ContinuumHeader`, профиль, меню разделов и масштаб. Оно проверяет доступ и хранит ограниченное состояние читателя.
- Пакет содержит статью, формулы, вопросы, геометрию и код демонстраций. Его код исполняется только внутри iframe и не импортируется в основной React runtime приложения.
- Локальный authoring kit предоставляет `LessonDefinition`, `LessonArticle`, контекст формул/самопроверки/масштаба и bridge. Новая лекция задаёт содержание и собственные модели; не копирует страницу, профиль и обработчики навигации.
- Новые демонстрации собираются в пакет без регистрации в production-приложении. Новый общий UI-сценарий или изменение контракта требует совместимого расширения каркаса и проверок прежних пакетов.
- Host обновляется вместе с приложением. Authoring kit включается в неизменяемый пакет при сборке: чтобы изменить оформление/логику статьи в уже опубликованной лекции, её нужно пересобрать и импортировать новой версией. Исходники общие, существующие пакеты не переписываются автоматически.

## Состав архива

Ровно два файла в корне ZIP, без каталогов:

```text
manifest.json
lesson.html
```

`lesson.html` — полный UTF-8 HTML-документ со встроенными JS/CSS/шрифтами/рисунками. Внешние библиотеки и изображения нужно включить при локальной сборке: сетевые обращения проигрыватель блокирует. Сервер ничего не компилирует и не исполняет.

Манифест:

```json
{
  "schemaVersion": 1,
  "lessonId": "kin-01",
  "title": "Основные понятия кинематики",
  "entrypoint": "lesson.html",
  "contentSha256": "<64 lowercase hex characters>",
  "sections": [{ "id": "kinematics-title", "title": "Основные понятия" }],
  "questions": [{ "id": "motion-question", "revision": 1 }]
}
```

Пример показывает структуру, а не готовый hash/полный список KIN-01. Каноническая схема и лимиты — `packages/shared/src/contracts/interactive-lesson.ts`: ZIP ≤16 МиБ, HTML ≤32 МиБ, манифест ≤32 КиБ, до 100 уникальных разделов и 100 вопросов. `lessonId` и внутренние ID — стабильные латинские slug. SHA-256 считается по исходным байтам `lesson.html`. При изменении смысла вопроса/ключа повышать его `revision`; смена оформления сама по себе не сбрасывает ответ.

Импорт проверяет имена/число файлов, методы сжатия, фактические размеры, UTF-8, JSON-схему, CRC и SHA-256. Дубликаты, traversal, каталоги, symlinks, специальные и зашифрованные записи отклоняются. Проверка структуры не делает JavaScript доверенным: изоляция обязательна и для валидного архива.

## Подготовка следующей лекции

1. Создать модуль `LessonDefinition` с `lessonId`, заголовком, контекстом, ID статьи/заголовка, разделами, ревизиями вопросов и компонентом `Content`.
2. В `Content` сохранить исходные объяснения, формулы и ссылки; добавить тематические модели. Повторно использовать authoring-компоненты. Реестры формул и демонстраций принадлежат конкретной лекции.
3. Запустить из корня репозитория:

```sh
node scripts/interactive-lessons/build-package.mjs apps/web/features/student-library/kinematics-package.tsx output/interactive-lessons
```

Для другой лекции заменить первый аргумент. Короткая команда для образца — `pnpm lesson:build`. Результат — `<lessonId>.zip`, HTML и манифест для локальной проверки. По умолчанию собирается KIN-01. Скрипт использует уже установленные Vite, React, MathJax и yazl; серверу эти authoring-действия не нужны.

4. Проверить конечный ZIP действующим parser и открыть его через настоящий предпросмотр. Проверить desktop/телефон/масштабы, все модели, ссылки и самопроверку по [критериям](INTERACTIVE-LESSONS.md#7-порядок-переноса-и-приёмка).
5. В материалах занятия загрузить ZIP, открыть «Предпросмотр» и явно опубликовать занятие. Предыдущая активная версия продолжает работать до успешной публикации новой.

Текущая сборка предварительно рендерит конечный набор TeX-формул в MathJax CHTML и встраивает используемые шрифты. Метрики учитывают x-height Medeo и сохраняют размер формул прототипа. Формулы собираются обходом реального `Content`, а не регулярными выражениями из исходника. Для новой демонстрации с произвольной динамической TeX-формулой потребуется явно расширить authoring renderer; отсутствующая в сборке формула не подменяется молча. Математика KIN-01 не требует runtime-загрузок.

## Открытие и версии

- Загрузка: существующий `PUT /teacher/library/lessons/:id/artifacts/upload?type=interactive`.
- Предпросмотр любой конкретной версии: `GET /teacher/library/artifacts/:id/interactive`.
- Чтение учеником: `GET /student/library/artifacts/:id/interactive`; только активная опубликованная версия, опубликованные занятие/раздел и выданная параллель.
- Ответ обоих read-path: `{artifactId, manifest, html}`, `Cache-Control: no-store`. Ответ валидируется shared-схемой. S3 keys не раскрываются.
- Teacher route: `/teacher/materials/interactive/[artifactId]`; student route: `/student/lessons/[lessonId]/interactive`.
- Публикация повторно проверяет сохранённый пакет и переключает активную версию атомарно под блокировкой занятия. Изменившийся состав требует повторить действие после обновления данных.
- Выбор старой версии как активной через UI/API пока отсутствует; исторические артефакты не перезаписываются.

## Изоляция и bridge

Host добавляет свою CSP перед HTML пакета и создаёт iframe `sandbox="allow-scripts"`, без `allow-same-origin`, отправки форм, всплывающих окон и навигации верхнего окна. `referrerPolicy="no-referrer"`; внешние ресурсы/fetch, вложенные фреймы, объекты и отправка форм запрещены. Разрешены встроенный JS/CSS и локальные data-ресурсы. У пакета нет доступа к cookie, auth headers, идентификатору аккаунта и storage родителя. Sandbox не гарантирует ограничение CPU/памяти произвольного скрипта; автор должен проверять производительность своих моделей.

Самопроверка не зависит от нативного submit: кнопка `type="button"` проверяет ответ напрямую, Enter в поле вызывает ту же проверку с учётом IME. В sandbox без `allow-forms` браузер может блокировать submit до React-обработчика; добавлять разрешение форм ради этого не нужно. Клик, Enter в поле и Enter на кнопке проверяются в настоящем iframe.

Контракт `interactive-lesson-bridge.ts`: envelope `{channel:"continuum.lesson",version:1,type:...}` и строгие payload-схемы. Пакет отправляет `ready`, текущий `section` и `state`; host — `init`, `navigate`, `scale`, `visibility`. Передача использует `postMessage`: host проверяет `event.source === iframe.contentWindow`, opaque origin и схему, пакет — окно родителя и схему. Unknown section/question IDs игнорируются. URL, HTML для родительского DOM, произвольные storage keys и команды приложения в протокол не входят. Повторный handshake не пересоздаёт уже запущенную статью.

Состояние reader содержит только выбранный масштаб и результаты `correct`/`incorrect` известных вопросов. Host сохраняет его локально в namespace аккаунта/занятия/`lessonId`, проверяет ревизии вопросов. Сырые ответы и оценки не сохраняются, между устройствами синхронизации нет. Превью учителя отделено от ученического состояния. Недоступность storage не блокирует чтение.

- Общий host: `apps/web/components/interactive-lesson/`.
- Authoring kit: `apps/web/components/interactive-lesson/authoring/`.

- Текущий ZIP и диагностические файлы: `output/interactive-lessons/` (локальные результаты сборки).
