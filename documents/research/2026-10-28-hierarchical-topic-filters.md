# Иерархический фильтр тем банка задач

Дата проверки: 28.10.2026. Исследование, не утверждённый дизайн и не реализация. Код приложения не менялся. Использованы официальные документация, исходники и публичное ecommerce-демо. Ссылки на ветки `master`/`dev` подвижны.

## Вывод для Continuum

Для плотной панели с поиском, типом, ЕГЭ и источником подходит одно поле «Раздел или тема», открывающее иерархический выбор. Уровней должно быть столько, сколько есть в `topicPath` — от 1 до 5. Пользователь должен иметь возможность выбрать весь раздел и остановиться на любой глубине.

Ключевое решение — **раскрытие узла и выбор фильтра являются разными действиями**. «Механика → Кинематика» может быть только просмотром ветки; «Выбрать Кинематику» применяет фильтр ко всем её потомкам. Если каждый шаг сразу меняет выдачу, это другой допустимый сценарий, как у Algolia, но его следует выбирать осознанно.

Предложение по результатам сравнения: на desktop — компактный popover с поиском по полному пути и иерархией; на телефоне — одна текущая ветка, явный «Назад» и действие «Все задачи этого раздела». Колонки можно рассматривать для desktop, но не растягивать 3–5 колонок на телефон. Новая UI-библиотека для этого не требуется: источники ниже полезны как проверенные модели взаимодействия.

## Ant Design Cascader

- Рекурсивные `children` и значение-массив задают путь, а не фиксированные три уровня. `changeOnSelect=true` разрешает выбрать промежуточный узел; по умолчанию он выключен. `expandTrigger` по умолчанию `click`, также есть `hover`; отображение выбранного пути настраивается через `displayRender`. [Официальный API](https://ant.design/components/cascader/#api).
- В реализации `onPathOpen` меняет активный путь, `onPathSelect` вызывает выбор. При `changeOnSelect` и раскрытии кликом родитель уже становится выбранным, хотя popup остаётся открыт; при hover или выборе с клавиатуры popup закрывается. Это **не готовое разделение «посмотреть ветку / применить»**. [List.tsx](https://github.com/react-component/cascader/blob/master/src/OptionList/List.tsx#L109-L132).
- Поиск проверяет подписи каждого сегмента пути без учёта регистра, выводит путь с `/`; при разрешённых промежуточных путях они тоже участвуют в результатах. Стандартный лимит — 50. Поиск фразы вида `Механика Кинематика` как нескольких токенов этот алгоритм сам по себе не реализует. [useSearchOptions.ts](https://github.com/react-component/cascader/blob/master/src/hooks/useSearchOptions.ts).
- В клавиатурном коде ↑/↓ перемещают активный пункт, → входит в дочернюю колонку, ← возвращается, Enter выбирает, Esc закрывает; при поиске ←/→ не переключают колонки. Навигация стрелками сама не вызывает `onPathSelect`. [useKeyboard.ts](https://github.com/react-component/cascader/blob/master/src/OptionList/useKeyboard.ts).
- `showSearch` не поддерживает серверный поиск, `loadData` несовместим с `showSearch`. Это существенное ограничение при неполном локальном дереве. [Документация поиска и lazy loading](https://ant.design/components/cascader/#components-cascader-demo-search).

**Живая проверка basic demo:** три последовательных клика добавляют соседние колонки в одном popover; поле остаётся пустым до выбора листа; лист закрывает popup и показывает весь путь и Clear. Это проверка стандартного режима, не `changeOnSelect`. Мобильный viewport не проверялся.

**Оценка:** хороший референс компактного поля, пути и клавиатуры для React. Для нашего сценария опасно переносить `changeOnSelect` без решения, должны ли промежуточные клики немедленно перезапрашивать банк. Hover нельзя делать обязательным способом раскрытия на телефоне.

## Element Plus Cascader

- По умолчанию одиночный выбор разрешён только для листьев. `props.checkStrictly=true` позволяет выбрать любой уровень независимо от детей. `emitPath=true` отдаёт весь путь. [Официальная документация](https://element-plus.org/en-US/component/cascader.html#select-any-level-of-options).
- При `checkStrictly` выводится radio с `@click.stop`; строка раскрывает ветку при click-режиме. `checkOnClickNode` позволяет намеренно объединить клик по строке с выбором; отключённый вариант полезнее для разделения действий. Выбор radio также может раскрыть узел, но простое раскрытие не обязано выбирать его. [node.vue](https://github.com/element-plus/element-plus/blob/dev/packages/components/cascader-panel/src/node.vue).
- Поле умеет `filterable`, `show-all-levels`, `filter-method`. Исходник формирует текст пути и фильтрует загруженные узлы; с `checkStrictly` поиск охватывает и родителей. Это не доказательство глобального поиска по ещё не загруженному lazy-дереву. [cascader.vue](https://github.com/element-plus/element-plus/blob/dev/packages/components/cascader/src/cascader.vue#L620-L628).
- В панели реализованы ↑/↓ между пунктами, ←/→ между меню и Enter для проверки узла. [index.vue](https://github.com/element-plus/element-plus/blob/dev/packages/components/cascader-panel/src/index.vue#L302-L364).
- Мобильное ограничение видно в исходном CSS: панель `display:flex`, `width:fit-content`, меню `min-width:180px`, строка 34px, подписи обрезаются через ellipsis. Три колонки требуют минимум 540px без учёта внешних рамок. Это вывод из CSS, **не результат визуального теста на телефоне**. [cascader-panel.scss](https://github.com/element-plus/element-plus/blob/dev/packages/theme-chalk/src/cascader-panel.scss).

**Оценка:** наиболее ясный из рассмотренных референс независимых навигации и выбора родителя. Прямая установка Vue-компонента в Next.js неуместна; переносимая ценность — контракт взаимодействия. Многоколоночная панель требует отдельного мобильного представления.

## Algolia InstantSearch HierarchicalMenu

- Это вложенное меню фасетов, а не закрытый select. Каждый уровень индексируется отдельным атрибутом (`categories.lvl0`, `lvl1`…), содержащим накопленный путь. Массив `attributes` позволяет задать и пять уровней. Есть counts, ограничение количества пунктов, `showMore`, управление показом соседей родителя через `showParentLevel`; по умолчанию корневые counts могут меняться при уточнении, для их сохранения предусмотрен `persistHierarchicalRootCount`. [Официальный API](https://www.algolia.com/doc/api-reference/widgets/hierarchical-menu/js).
- У HierarchicalMenu нет встроенного поиска по значениям фасета: глубокие уровни не загружены до уточнения. Поле общего поиска товаров рядом не делает само дерево searchable. [Официальное объяснение ограничения](https://support.algolia.com/hc/en-us/articles/13212812252945-Can-hierarchicalMenu-be-searchable).
- [Публичное ecommerce-демо](https://instantsearchjs.netlify.app/examples/js/e-commerce/) **проверено в браузере на desktop**, включая screenshot и AX-состояния. Начальный список категорий соседствует с брендами, ценой, доставкой и рейтингом. Клик `Appliances` раскрыл дочерние категории и сменил товары, counts брендов и URL на `/search/Appliances/`; клик `Dishwashers` сузил выдачу и URL до `/search/Appliances%2FDishwashers/`. У выбранной дочерней ссылки адрес ведёт к родителю; у выбранного корня — к общему поиску. Это выбор с немедленным уточнением, а не отдельное browse-only раскрытие.
- Демо связано с настоящим InstantSearch-примером: `search.ts` подключает widgets `categories`, `brands`, `priceSlider`, `ratings`, routing и mobile-specific widgets; это подтверждено чтением исходника, **не мобильной визуальной проверкой**. [Исходники демо](https://github.com/algolia/instantsearch/tree/master/examples/js/e-commerce), [search.ts](https://github.com/algolia/instantsearch/blob/master/examples/js/e-commerce/src/search.ts). Отдельный [официальный Storybook](https://instantsearchjs.netlify.app/stories/js/?path=/story/refinements-hierarchicalmenu--default) найден через сайт Algolia; его интерактивность в этом проходе не проверялась.

**Оценка:** сильный референс соседства дерева с другими фильтрами и немедленной выдачи на любом уровне. Постоянное дерево занимает вертикальное место; на 5 уровнях отступы съедают ширину. Подключение поискового сервиса ради фильтра тем несоразмерно задаче. Ни touch-поведение, ни клавиатурный сценарий ecommerce-демо здесь не проверялись; наличие обычных ссылок не заменяет такую проверку.

## Что ограничивает будущую реализацию в текущем коде

1. Пакет уже допускает `topicPath` длиной 1–5: [assessment-package.ts](../../packages/shared/src/contracts/assessment-package.ts).
2. API получает полные пути, но отдаёт `topics` через `flatMap(topicPath)` и `Set`: связи родителей и одинаковые подписи в разных ветках теряются. Строить достоверное дерево из нынешнего `topics:string[]` нельзя; из задач одной страницы — тоже. [AssessmentBankReadService.list](../../apps/api/src/assessment-bank/assessment-bank-read.service.ts).
3. Фильтр `topic` — одна строка, запрос использует `topicPath: { has: query.topic }`. Одинаковый сегмент в разных ветках совпадает сразу в обеих; это не фильтр по префиксу пути. Переход к точной ветке потребует явного transport-контракта и серверной семантики. [Query schema](../../packages/shared/src/contracts/assessment-bank.ts), [where](../../apps/api/src/assessment-bank/assessment-bank-read.service.ts).
4. Темы сейчас зависят от владельца и `gradeBand`, но не от поиска, типа, ЕГЭ и источника. Counts по узлам не возвращаются. Нельзя обещать доступные количества как в Algolia без отдельного решения об агрегации и применяемых фильтрах. [list](../../apps/api/src/assessment-bank/assessment-bank-read.service.ts).
5. Фильтр есть в двух teacher-контурах: [BankFilters](../../apps/web/features/teacher-bank/BankFilters.tsx) и [WorkBankFilters](../../apps/web/features/teacher-works/WorkBankFilters.tsx). Будущий общий контракт должен покрывать оба; student-контур для этого не нужен.

## Минимальный контракт для следующего прототипа

Это рекомендация исследования, не принятые требования:

- Один выбранный узел, идентифицируемый полным путём; выбор родителя включает его поддерево и собственные задачи.
- Отдельные `expandedPath` и выбранный путь; browse-only переход не запускает запрос банка. Явное действие выбора на каждом уровне и сброс «Все темы».
- Поиск по всем известным путям с показом контекста совпадения; одинаковые подписи в разных ветках не склеиваются.
- Управление без hover: tap/click для перехода, отдельное доступное действие выбора, на телефоне «Назад» и один список. Клавиатура: видимый фокус, навигация, Enter/Space, Esc и возврат фокуса к полю.
- Проверка на путях длиной 1 и 5, одинаковых названиях в разных ветках, длинных русских подписях, выборе родителя, пустой выдаче от других фильтров и восстановлении URL.

До изменения API достаточно визуального прототипа на явном дереве с 1–5 уровнями. Установка Ant Design, Element Plus или Algolia не является результатом этого исследования.

## Адаптация для Continuum

### Организация остальных фильтров

[Linear](https://linear.app/docs/filters) показывает общие фильтры в одном меню, позволяет сразу найти свойство вводом и сохраняет применённые условия в URL. Зависимый контекст тоже встречается: для milestones сначала выбирается project. Это референс организации плотной панели, а не доказательство наличия у Linear такого же дерева учебных тем. В этом проходе изучена официальная документация; взаимодействие с авторизованным продуктом не проверялось.

[GitHub Primer](https://primer.style/product/scenario-patterns/filter/) рекомендует searchable SelectPanel для выбора из известного списка, отдельные dropdown для коротких наборов и более сложный Filter для комбинаций условий. Выбранное значение должно быть видно на кнопке, состояние — отражено в URL, сброс — доступен. Поиск внутри списка требует SelectPanel или Dialog, а не вложенных полей ввода в ActionMenu. Это проверено по официальным рекомендациям, не по закрытому аккаунту GitHub.

Для банка предлагается оставить на виду поиск и «Раздел или тема». Тип, ЕГЭ и источник собрать под одной кнопкой «Фильтры»; рядом показывать применённые условия с отдельным сбросом. Это кандидат для прототипа: перенос частых фильтров внутрь добавляет клик, поэтому окончательное расположение нужно проверить на реальном сценарии учителя. На телефоне дополнительные фильтры открываются одной панелью; отдельные всплывающие окна не вкладываются друг в друга.

### Предлагаемое поведение поля тем

1. Закрытое поле: «Все разделы и темы» или выбранный путь, например «Механика / Баллистика»; доступен сброс только темы.
2. Открытие показывает корни и поиск. Клик «Механика ›» открывает её содержимое, не меняя результаты банка.
3. Первая строка внутри — «Вся механика»: она выбирает и собственные задачи раздела, и дочерние темы. Остальные строки ведут глубже либо выбирают конечную тему. Таким же способом можно остановиться на любом промежуточном уровне.
4. На desktop предлагаются максимум две соседние колонки; при большей глубине старшие предки остаются в строке пути с возможностью возврата. На телефоне — одна колонка текущей ветки и «Назад». Это адаптация для проекта, не поведение Ant Design по умолчанию.
5. Выбор темы или всей ветки сразу применяет фильтр и закрывает окно. Просмотр веток не делает сетевых запросов банка. При повторном открытии виден выбранный путь; поиск выводит совпадения вместе с родителями.
6. Пустые уровни не создаются: задача с одним «Механика» допустима, с двумя «Механика / Баллистика» — тоже. В метаданных отсутствующие строки скрыты. Тематический путь банка и «Подраздел источника» остаются разными признаками.

Поведение фокуса и выбора нужно проверять отдельно. [WAI-ARIA Tree View](https://www.w3.org/WAI/ARIA/apg/patterns/treeview/) различает фокус и выбор и описывает стрелочную навигацию для дерева. Для одноколоночного перехода между списками следует выбрать подходящую семантику диалога и обычных списков; автоматически добавлять `role="tree"` без полного клавиатурного поведения нельзя.

Следующий предметный шаг — небольшой интерактивный прототип двух состояний (desktop и телефон) с длинными русскими названиями и пятью уровнями. Продуктовый код в рамках исследования не менялся; мобильная компоновка пока является предложением, не проверенным интерфейсом.
