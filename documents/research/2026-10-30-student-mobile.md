# Мобильные экраны ученика: источники, аудит и прототипы

Дата: 30.10.2026. Источники и исходный аудит; согласованные A/B реализованы локально, временный прототип удалён. Новый визуальный проход пока не подтверждён из-за сбоя управления IAB. Приоритет пользователя — ученик с телефона; teacher materials остаются вторым приоритетом. Верхние teacher-разделы, API, доступы и ответы не меняются.

## Источники → наши решения

| Первичный источник | Что подтверждает | Как применяем / где граница |
| --- | --- | --- |
| [Google: adaptive list-detail](https://developer.android.com/develop/ui/compose/layouts/adaptive/list-detail) | В узком окне видна одна панель, выбранный объект занимает экран; на широком список и содержимое могут соседствовать. | На телефоне список занятий → занятие с явным возвратом. Не складывать длинный каталог и содержимое друг под другом. Это перенос паттерна на web, не рекомендация использовать Compose. |
| [Apple: Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars) | Верхнеуровневые разделы обозначаются понятными подписями и символами. | Сохраняем две сущности «Материалы / Работы». Варианты сравнивают верхнюю и нижнюю композицию; источник не требует переносить нашу навигацию вниз. В активной работе отдельная локальная навигация; выход должен сохранять существующий safe-leave. |
| [Apple: UI Design Dos and Don’ts](https://developer.apple.com/design/tips/) | Удобные touch-цели, читаемая типографика, понятное выравнивание. | Основные контролы прототипа не ниже 44 CSS px. Apple говорит о 44 pt; 44 CSS px — наша web-цель, а не буквальное равенство физических размеров. |
| [WCAG 2.2: Target Size Minimum](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) | Минимум AA — 24×24 CSS px с исключениями, в том числе для достаточного интервала и inline-ссылок. | Не объявляем каждую 21px-ссылку автоматическим нарушением WCAG. Увеличение до 44px — практический UX-выбор для основных действий с телефона. |
| [WCAG 2.2: Focus Not Obscured](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html) | Закреплённые панели не должны полностью скрывать сфокусированный контрол. | Отступы контента и scroll margin; toolbar скрыт при текстовом вводе. Итоговую геометрию и iPhone-клавиатуру проверять отдельно от component tests. |
| [Google Classroom: iPhone student guide](https://support.google.com/edu/classroom/answer/9582544?co=GENIE.Platform%3DiOS&hl=en) | Classwork сгруппирован по темам; нажатие элемента открывает содержание/работу. | Полное название, понятная группировка и явный переход важнее технических имён файлов. Не переносим Classroom целиком и не добавляем ленту. |
| [Google Classroom: iOS submission](https://support.google.com/edu/classroom/answer/6020285?co=GENIE.Platform%3DiOS&oco=1) | Материалы/вложения, фотографии и явное подтверждение отправки — разные шаги. | У нас тест завершается отдельно от фото; не обозначать загруженное фото как завершённую работу. Дедлайны, повторная сдача, сканер и новые права не добавляются. |
| [Shopify: responsive Table](https://shopify.dev/docs/api/app-home-ui-extension/latest/web-components/layout-and-structure/table) | На мобильном таблица может перестраиваться в список, столбцы получают роли в списке. | Сводка работы должна перегруппироваться по смыслу, а не повторять длинные desktop-подписи. Сохраняем независимые тест/фото/проверку, без нового общего статуса. |

Содержимое Apple Tab bars проверено официальной поисковой выдержкой: основной HTML требует JS, Markdown endpoint через web tool не поддержан. Сложные рекомендации о жестах/скрытии панелей из этого источника не выводились. Остальные ссылки прочитаны как первичные страницы/официальные поисковые результаты. Выбор A/B/C ниже — наш вывод, не якобы готовое решение Apple или Shopify.

## Исходный аудит до изменений

Настоящие `StudentLibraryScreen`, `StudentLessonScreen`, `StudentWorksScreen`, `StudentWorkScreen`, `StudentFinishReview`, `StudentSolutionUpload`, общая шапка, Markdown/MathJax и CSS загружены в изолированном Vite. Данные вымышленные: одна доступная параллель, три раздела, 12 занятий, три работы, 22 тестовых + 8 развёрнутых заданий. Это снимки **текущего кода на демонстрационных данных**, не снимки базы production. Baseline использует реальные хуки с API-адаптерами в памяти; запросов в backend нет.

| Приоритет | Сценарий | Наблюдение на 390×700 | Предлагаемое изменение |
| --- | --- | --- | --- |
| P1 | Каталог материалов | Длинные названия обрезаются до одной строки. PDF-действия высотой 21px. Фиксированные вкладки показывают четыре параллели, хотя доступна одна. Нет поиска. | Полное название; большая отдельная touch-цель; показать доступную параллель текстом, выбирать её только если доступно несколько; поиск по загруженному каталогу. |
| P1 | Страница занятия | Две PDF-кнопки по 21px. Длинные имена файлов: содержимое 477/440px в колонке 248px, визуально выходят за колонку. Глобальное «Работы» пропадает на этом экране. | «Конспект PDF / Задачи PDF» — главные действия, filename в необязательных сведениях с переносом; единая навигация/возврат. Не встраивать новый PDF-движок. |
| P1 | Выполнение работы | В примере с длинным названием поле ответа начинается на y≈931px после готовности MathJax. До условия идут логотип, разделы, возврат, большой заголовок, версия, статус, инструкция и повтор позиции задания. | Компактный контекст работы, статус сохранения рядом, один номер позиции; условие и ответ выше. В B тот же ответ на y≈513px. Это измерение конкретного примера, не гарантия для длинного условия. |
| P2 | Список работ | Длинные предложения о тесте, фото и проверке усложняют просмотр. Семантика в коде корректная: три независимые метрики, действие зависит от состояния. | Полное название + коротко подписанные тест/решения/проверка. Вся строка открывает работу; дополнительных конфликтующих кнопок внутри нет. |
| P2 | Фото решения | Нативный выбор и текущая очередь уже есть; mobile drag-hint скрыт, ввод не требует drag. Основной недостаток — экран доходит до фото через высокую шапку. | Поднять рабочее содержимое; оставить один «Добавить фото», лимиты и очередь. Не обещать встроенный сканер или поддержку HEIC. |
| P2 | Подтверждение завершения | При 18 пропусках текущий диалог содержит длинный список текстовых пунктов. Переход к пропуску и различие теста/фото уже реализованы. | Компактные номера пропусков, ясный итог, безопасный возврат; завершение остаётся отдельным подтверждением. |

Не найдено оснований менять политику ответов, оценивания, файлов или автосохранения. Проверены только представительные состояния; реальный iPhone/PWA, клавиатура, камера, PDF и поворот требуют физической приёмки.

## Исследованные варианты материалов

| Вариант | Устройство | Цена / сильная сторона |
| --- | --- | --- |
| A · Ясный каталог | Существующий верхний уровень «Материалы / Работы»; поиск; открытые разделы; полное название; отдельное занятие с крупными файловыми действиями. | Спокойный список, мало новых правил. До PDF два нажатия вместо прямого одного. При очень большом каталоге длиннее прокрутка. |
| B · Быстрые файлы | Нижняя навигация; раскрываемые разделы; явные отдельные действия PDF/задач под названием. | PDF открывается одним нажатием; строки выше, помещается меньше занятий. Нижняя навигация — гипотеза для сравнения, не автоматический выбор «потому что iPhone». |
| C · По разделам | Сначала список разделов с количеством занятий → занятия → файл. Поиск обходит лишний переход. | Короткий первый экран для большой библиотеки; больше переходов, нельзя сразу просмотреть все занятия. |

Пользователь согласовал **A для материалов**, **B для режима выполнения**: компактная рабочая шапка и доступные снизу переключение/карта заданий. Необязательно переносить глобальные разделы вниз вместе с локальной панелью работы: это разные уровни навигации. В C открыта сетка всех номеров — полезное сравнение, но 30 кнопок отодвигают условие; поэтому это не основной кандидат.

При реализации выбранного варианта сохранить: read-only ключи ученика; подтверждённое автосохранение и ошибки; независимость фото/теста; safe-leave и повторный вход; совместимость старой позиции; опубликованные PDF/баллы; настоящую навигацию и восстановление grade/search/list scroll. Прототип не заменяет эти механизмы. После внедрения удалить весь временный контур, команду/config и кеш.

## Учительские материалы — вторым этапом

Подтверждённая проблема из [teacher-аудита](2026-10-30-teacher-mobile-audit.md): inspector оказывается под 24 занятиями. Для него подходит тот же list-detail, но с teacher-действиями внутри выбранного занятия. Не удалять создание/загрузку только на основании предположения, что с телефона ими не пользуются; основные действия сделать доступными, вторичные раскрывать по запросу. Отдельный teacher-прототип в этот ученический пакет не включён.
