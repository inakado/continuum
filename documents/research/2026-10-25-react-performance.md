Не запускались install/hooks/CI setup и автоисправления. CLI и сетевые функции сверены с [официальной справкой](https://www.react.doctor/docs/reference/cli-reference).

### Ненужные модули общих контрактов

Web alias уже направлял `@continuum/shared` на ESM source, а не CJS dist. Поэтому переписывать backend/shared сборку не требовалось. Однако root barrel сохранял инициализацию всех схем и локального Markdown parser даже на login, которому нужен только небольшой поднабор для очистки прежнего черновика.

`packages/shared/package.json` получил `sideEffects: false`. Проверенные runtime-модули shared содержат локальные схемы, policy и локально настроенный экземпляр `Marked`, без глобальной регистрации/внешней инициализации. Метаданные позволяют bundler исключить целиком неиспользуемые модули; используемые parser extensions, проверки и схемы сохраняются. CJS exports API не изменены и проверены загрузкой в Docker.

По analyzer атрибуция клиентского кода login уменьшилась на 59 474 байта, `marked` — с 39 175 до 0, shared — с 26 961 до 6 972. Это атрибуция модулей, не HTTP-transfer. Для реальных chunks отдельно собраны **обычные** production builds без profiling/debug; мемоизированная шапка одинакова в обеих сборках, менялась только metadata shared:

Полный scan: 254 файла, `complete: true`, `skippedChecks: []`; **89 diagnostics: 1 error и 88 warnings в 46 файлах**. После двух performance-изменений число было таким же: Doctor не измеряет устранённые перерисовки или байты общих модулей. Последующая адресная правка ниже уменьшила итог до 0 errors / 88 warnings. Score API отключён, оценки нет.

| Замечания | Проверка и решение |
|---|---|
| Mutation invalidation — 17; complexity — 14 | Очереди ответов, адресные cache updates, обработчики caller и безопасные повторы нельзя менять автоматически. Complexity уже имеет отдельный инженерный backlog; это не доказательство задержки. |
| Array index keys / includes/find / default `[]` / Intl | Статические узлы Markdown, небольшие наборы вариантов и ранний выход эффекта отличаются от переставляемого списка. В измеренных сценариях не выявлены дорогие вычисления, ради которых нужна переделка. |

## Проверка error после performance-прохода

По отдельному поручению 25.10.2026 ошибка воспроизведена на границе компонента `RevokeAssignmentDialog`: данные read-hook управляются тестом, React реально выполняет `startTransition` и прерывает subtree через `Suspense`. Это воспроизведение React lifecycle, не наблюдение инцидента на production.

Исходно диалог уже показывал загрузку. Следующий render прочитал preview A (20 учеников/hash A), но не дошёл до commit из-за Suspense. После отмены этого render появился актуальный preview B (21/hash B); прежний ref всё равно содержал A, поэтому тест видел устаревшие 20 вместо 21. На исходном коде регрессия падает именно на этом различии. Серверный CAS при несовпадении состава вернул бы конфликт; тест не демонстрирует удаление чужого класса или обход защиты сервера.

Снимок перенесён в `useState` с фиксацией через `useEffect` после commit. Пока снимок не зафиксирован, destructive button отключена. Прерванный render не запускает effect и не оставляет снимок; после первого успешного commit фоновые изменения по-прежнему не заменяют подтверждение. Это соответствует [семантике effects после commit](https://react.dev/reference/react/useEffect).

Новая регрессия проверяет A (прерван) → B (зафиксирован) → C (фоновое изменение до 22/hash C): показывается B, запрос содержит hash B. Прежние тесты с настоящим QueryClient проверяют загрузку/фокус, freeze при refetch + 409, двойное подтверждение и запрет закрытия во время записи. Все **4 теста диалога** проходят; полный web-suite **227/227**, boundaries, typecheck и обычный production build проходят.

Повтор React Doctor 0.9.18 с прежними флагами: **0 errors, 88 warnings**, complete scan, без suppressions. Отчёт: `output/perf-react/react-doctor-snapshot-fixed.json`.

Локальный браузер: существующий teacher report, открытие и отмена диалога без записи; отмена в начальном фокусе, подтверждение доступно после загрузки. Desktop 1280×900 и mobile 390×844: диалог 358 px, ширина документа 390 px. Клики удаления не выполнялись; browser writes блокировались, их счётчик 0. Одноразовые скриншоты проверены и удалены при финальной очистке 25.10.2026. CSS, API, БД и production не менялись этой правкой.
