# Фото решений: компоненты и UX

Проверено 28.10.2026 по первичным источникам. Это обоснование первого пакета UX-16, без переноса всей дизайн-системы.

## Проверенные практики и адаптация

- **IBM Carbon, File uploader** ([guidelines](https://www.carbondesignsystem.com/building-blocks/core/components/file-uploader/guidelines), обновлены 30.09.2026; [React Storybook](https://react.carbondesignsystem.com/)): вертикальный список файлов, название, состояния загрузки/завершения, ошибка рядом с файлом; кнопка/drag area выровнены с файлами. В Continuum остаются текущий file input и drop area; очередь показывает «В очереди / Загружается / Загружено / Не загружено», принятые файлы отдельно доступны в галерее. Нет фиктивного процента без измерения передачи и отдельного modal uploader.
- **IBM Carbon, Data table** ([guidelines](https://www.carbondesignsystem.com/building-blocks/core/components/data-table/guidelines), обновлены 30.09.2026): поиск/фильтры относятся к toolbar таблицы, плотность едина, подробности раскрываются по запросу. В нашем отчёте ещё один существующий native `WorkSelect` рядом с классом, поиском и тестом; не отдельные карточки или новая вкладка. Статус фото не подменяет завершение теста.
- **Google Classroom, teacher work** ([официальная справка](https://support.google.com/edu/classroom/answer/9157286?hl=en)): teacher может фильтровать список по состояниям сдачи/проверки. Наши точные группы «нет / частично / все / ожидают проверки / опубликованы» — адаптация к смешанной работе, а не буквальное копирование названий Classroom. Дополнительные LMS-основания — [исследование пилота](2026-10-28-lms-ux-evidence.md).
- **TanStack Query** ([useQuery](https://tanstack.com/query/latest/docs/framework/react/reference/useQuery), [window focus](https://tanstack.com/query/latest/docs/framework/react/guides/window-focus-refetching)): `refetchInterval`, отсутствие background interval и повторное чтение при возврате; существующие данные доступны во время обновления/ошибки. В открытой teacher-панели интервал 10 секунд, ручное обновление и сохранение выбранного фото. После размонтирования polling прекращается; WebSocket и собственный таймер не нужны.

## Ограничения интеграции

Новые библиотеки не добавлены. Сохранены Medeo, стальной акцент, тонкие разделители и текстовые состояния, читаемые без цвета. Фильтры вычисляются по уже полученной серверной проекции, без новых API. Очередь не сохраняет File в localStorage и не обещает восстановить ещё не принятый файл после выгрузки вкладки. Повтор использует прежний photo ID и актуальную ревизию; принятые файлы не отправляются повторно. Проверка читаемости и полноты решения остаётся задачей проверяющего.

## Проверка CI, связанная с пакетом

[pnpm 10 audit](https://pnpm.io/10.x/cli/audit) и установленный код pnpm 10.11.1 проверены непосредственно: `--ignore` — отдельное действие записи исключения, после которого сканирование не выдаёт полный отчёт. Команда CI — обычный `pnpm audit --audit-level=high`, без `--ignore`, `--ignore-unfixable`, `--ignore-registry-errors` и новых исключений. Старый GHSA, ошибочно записанный в `ignoreCves`, удалён.

У pinned pnpm 10.11.1 есть существенная деталь: в режиме `--json` exit code учитывает все severity, а не только `--audit-level`. Поэтому успешная ветка проверена точной обычной командой CI на локальном registry fixture с только low; код 0 и реальный запрос отчёта. Живой registry с high/critical и недоступный registry дают ненулевой exit. В последующем [security-пакете](../exec-plans/completed/2026-10-28-auth-security-update.md) зависимости обновлены: живые audit/Trivy прошли без исключений; оставшийся low описан в [tracker](../exec-plans/tech-debt-tracker.md).

## Уточнение семантики после просмотра интерфейса

Classroom описывает состояния work/submission/graded; Canvas отдельно определяет submission и способ передачи file upload. Это основание говорить в отчёте о решениях/развёрнутой части, а фотографию называть только в операции с конкретным вложением. Наши русские формулировки — адаптация предметного языка платформы, а не буквальный перевод продуктовых labels.

В отчёте и списке ученика используется «Развёрнутая часть», в строке преподавателя — «N из M заданий», статус проверки — «Проверено». Фильтры: «Нет решений / Часть решений / Все решения / Ожидают проверки / Проверены». Панель — «Имя · Решения», действие — «Обновить решения». Постоянное объяснение про количество файлов/задач и интервал polling убраны; ошибка обновления остаётся видимой, старые данные сохраняются.

[GetBEM naming](https://getbem.com/naming/) рекомендует самостоятельные блоки, элементы `block__element` и семантические имена. Применено локально к report: `report`, `report__solutions`, `report__open`; layout больше не привязан к русскому `data-label="Решения"`. CSS Modules сохранены; массовой смены архитектуры стилей нет. БЭМ организует код, а ясность текста обеспечивают термины предметной области.
