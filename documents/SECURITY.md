# SECURITY

Статус: действующие security-инварианты; фактические гарантии подтверждаются кодом и тестами.

## Scope

- Better Auth sessions;
- RBAC;
- доступ ученика к возрастным группам;
- object storage, защищённая загрузка и presigned view URLs;
- безопасная публикация PDF, изображений, Excalidraw-сцен и интерактивных пакетов;
- изоляция исполняемого HTML.
- назначенные версии, собственные ответы учеников и закрытые ключи автопроверки.

## Инварианты

### Auth

- Публичная регистрация и email-login отключены.
- Session identifier хранится только в `HttpOnly` cookie.
- Production требует `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL` и точный trusted origin.
- Logout и смена пароля отзывают активные сессии.
- Глобальный auth guard защищает routes по умолчанию; public routes помечаются явно.

### Authorization

- Роль `admin` предусмотрена для управления преподавателями; сейчас provision доступен через серверный инструмент, самостоятельный admin UI/HTTP ещё не подключён.
- `teacher` управляет учениками, доступами и материалами.
- `student` читает только опубликованные материалы выданных ему возрастных групп.
- Проверка доступа выполняется в API для catalog, lesson, asset и direct-link flows.
- Классы и ученики общие для teacher-аккаунтов: создание, перевод, удаление и сброс доступны каждому преподавателю. Student/admin не получают эти teacher endpoints. Банк, материалы и конструкторы работ сохраняют прежнее владение.
- Случайные начальные пароли не сохраняются в БД, логах и browser storage; ответы создания/сброса имеют `Cache-Control: no-store`. Повтор операции не раскрывает исходные пароли.
- Сброс пароля отзывает активные сессии ученика. Удаление учётной записи требует отдельного подтверждения в UI; удаление класса по умолчанию сохраняет учеников.
- Исправление ФИО (`PATCH /teacher/students/:id/names`) доступно только преподавателям, требует trusted Origin и строгого body с ожидаемыми прежними значениями. Запись транзакционная с блокировкой пользователя; конфликт не перезаписывает чужую правку. Логин, пароль, сессии, связи и исторические снимки назначений не изменяются.

### Assets

- Bucket не является публичным.
- API проверяет роль, ownership и назначение до приёма файла или выдачи presigned view URL.
- Upload policy ограничивает тип, размер и ключ объекта; запрос требует точного `Content-Length` и проверяется после сохранения в S3.
- PDF, изображения, Excalidraw JSON/preview и interactive packages имеют разные policies.
- Asset key хранится в доменной модели; storage URL не сохраняется.
- Удаление PDF/занятия/раздела библиотеки требует teacher-сессию, ownership, допустимый Origin и строгий список `expectedIds`; чужая сущность возвращает 404. Общая база учеников не расширяет доступ к материалам коллеги.
- Файл S3 удаляется только после commit удаления последней ссылки. Неудачная очистка остаётся в `LibraryAssetDeletion` для повтора. Новые view URL после удаления не выдаются; ранее полученная ссылка может оставаться действительной до физической очистки, скачанные копии не отзываются.

### Банк заданий

- `DELETE /teacher/assessment-bank/tasks/:id` и `POST /teacher/assessment-bank/tasks/:id/restore` требуют владельца, teacher-сессию, допустимый Origin и строгие version/lifecycle-контракты. Удаление/восстановление сериализованы с импортом и изменением состава работ блокировкой преподавателя. Restore связан с конкретной `deletionRevision`: безопасный повтор не восстанавливает более позднее удаление и не перезаписывает изменённый импорт (409). Это скрытие из банка, не уничтожение исторических версий и рисунков; явный просмотр версии по-прежнему проверяет владельца. Удалённое задание нельзя заново добавить в работу до восстановления. Уведомления отмены живут в памяти teacher-экрана, не в URL или browser storage.

- Все `/teacher/assessment-bank` routes требуют teacher-сессию и проверяют владельца задания/импорта; ученического API банка пока нет. Ключи, разборы, экспорт и рисунки не доступны другим преподавателям или ученикам.
- ZIP читается с лимитом compressed/unpacked bytes, числа файлов и размера каждой записи. Traversal, абсолютные пути, symlinks, специальные/зашифрованные файлы, дубли путей и неиспользуемые записи запрещены. Тип и размеры рисунков проверяются по содержимому.
- JSON строгий; Markdown преобразуется в безопасное дерево без raw HTML, внешних рисунков и произвольных URL. Формулы ограничены по размеру и командам; серверный TeX не исполняется. Политики — `assessment-policy.ts` и shared parser.
- Запись импорта владеет S3 keys до начала загрузки; неполную загрузку подтвердить нельзя. Очистка не удаляет рисунки исторических версий. При ошибке очистки запись остаётся для повтора; отдельного фонового очистителя нет.
- Подтверждение под блокировкой владельца атомарно проверяет baseline и сохраняет результат для безопасного повтора. Предпросмотр истекает через 30 минут.
- Рисунки проксируются авторизованным API по ID и версии, а не произвольному storage key. Все ответы банка используют `Cache-Control: no-store`. Для browser mutations проверяется Origin; отсутствие Origin допускает локальный CLI с действующей сессией.

### Конструктор работ

- Контекст отчёта выполнения не сохраняет ученические ответы/результаты в browser storage. В URL разрешены только UUID назначения класса, состояние и страница; поиск ученика туда не переносится. Строка поиска до 200 символов хранится в `sessionStorage` текущей вкладки под ключом преподавателя и версии, очищается при logout (включая ошибку sign-out). Другому аккаунту она не восстанавливается. Это незашифрованное хранилище профиля браузера, не защита от человека с доступом к тому же профилю; при запрете storage поиск продолжает работать без сохранения между загрузками.

- Все `/teacher/assessment-works` routes требуют teacher-сессию и проверяют владельца работы. Ссылки на задания разрешаются только внутри его банка. Чужая работа отвечает 404, ученик не получает учительский DTO с ключами и снимками.
- Все ответы имеют `Cache-Control: no-store`; browser mutations проверяют Origin. До 500 уникальных ссылок и размер полей валидируются shared-схемой, суммы баллов вычисляет API.
- Row lock, `expectedRevision` и хеш последнего `requestId` защищают от конкурентной перезаписи и изменённого повтора. Фиксация версии атомарна и повторяема по ревизии.
- Исторические условия и рисунки не заменяются новой версией банка. Будущая очистка банка должна учитывать ссылки сохранённых работ.
- «Просмотр работы» скрывает ключи в учительском UI, но не превращает teacher DTO в безопасный ученический API. Ученический контур имеет отдельный whitelist DTO.

### Назначения и ответы

- Teacher API проверяет владельца работы/версии и классов; student API — `studentId` исходного получателя. Текущий класс и `AccessGrant` библиотеки не заменяют эту проверку. Прямое чтение чужой попытки или её рисунка возвращает 404.
- Назначение фиксирует версию и получателей атомарно. Serializable-транзакция, блокировка работы, проверка ревизии/состава и постоянная запись результата `requestId` защищают от повторов, скрытой смены получателей и двойной попытки. Уникальность `versionId + studentId` действует через переводы.
- Ученический DTO содержит только условия, публичные варианты/позиции, разрешённые рисунки и собственные ответы. Ключи, исходные S3 keys, источники, эталоны и разборы не выдаются, включая завершённую работу. Teacher execution DTO содержит статусы/итоги, но не весь JSON ответов.
- Картинки читаются из неизменяемого снимка после проверки получателя, а не по произвольному storage key. Все ответы — `no-store`; browser mutations используют общий `assertWriteOrigin`.
- Ответ проверяется строгой Zod-схемой, типом задания и допустимыми IDs. Row lock попытки, ревизия и хеш повторяемого запроса исключают незаметную конкурентную запись. Завершение считает баллы на сервере и фиксирует ответы той же транзакцией; после него запись запрещена. Повтор завершения не запускает новую попытку.
- При удалении аккаунта или класса FK обнуляется, но snapshot имени/класса, ответы и результаты остаются у исходного преподавателя. Новый аккаунт не получает старую попытку по совпадению имени или логина.
- Новые ответы не записываются в localStorage; настройка локального черновика удалена. Для уже существующих записей сохранено безопасное восстановление с проверкой владельца, получателя, версии, срока и базовых значений; конфликт не применяется автоматически. Это прежнее незашифрованное хранилище профиля браузера, а не защита от другого человека с доступом к этому профилю. Logout очищает записи и query cache; смена аккаунта очищает чужие записи. Истёкшие удаляются при следующем обращении приложения.
- При истечении сессии редактор уже открытой работы может оставаться в памяти вкладки для восстановления входа. Запись/чтение по-прежнему требуют авторизации API. Вход в этой форме ограничен прежним логином и проверяет тот же `user.id`; смена пользователя размонтирует прежний редактор. Наличие данных в UI или черновике не заменяет проверку прав API на каждом запросе. `returnTo` после входа допускает только внутреннюю student work route.

### Interactive packages

- Интерактивный пакет не вставляется через `dangerouslySetInnerHTML`.
- Player использует отдельный origin или изоляцию, эквивалентную opaque origin.
- Iframe получает минимальный `sandbox`; `allow-same-origin` не добавляется без отдельного security review.
- Пакет не получает cookie, auth headers или Better Auth session.
- Package manifest, entry point, content hash, file count и общий размер проверяются до публикации.
- Связь с платформой возможна только через версионированный allowlist `postMessage`-сообщений.

### Excalidraw

- Scene JSON считается пользовательским файлом и проверяется по size/content-type policy.
- Student read-path использует статический preview.
- Raw scene доступна только авторизованному teacher authoring flow.

## Сохранность данных

- Явный отзыв назначения отличается от архива и удаления класса: owner-преподаватель подтверждает необратимое удаление всех ответов/фото/проверок/результатов одного исходного назначения, в том числе начатого/завершённого. Strict body/Origin/recipient hash и row locks ограничивают scope; другие классы, сама работа и банк не удаляются. После commit удалённый recipient не авторизует student/reviewer read/write. Фото/PDF-ключи сохраняются в outbox до успешного удаления S3, без публичных ссылок; technical receipt не содержит ученических результатов. Повтор старого назначения после отзыва получает конфликт. Уже скачанные файлы и прежние резервные копии не отзываются.

- Архивирование/восстановление и удаление работы доступны только владельцу-преподавателю, с trusted Origin и строгими shared-контрактами. `canDelete` — только UI-признак; удаление под row lock повторно проверяет назначения всех версий. Назначенная работа не удаляется даже при гонке, архивирование не отзывает доступ учеников. Удаление сохраняет tombstone ID и недоступность write/read/assign путей; повтор create/copy не создаёт запись заново. Контент банка, независимые копии и S3 не удаляются этим действием. Нет обещания физического стирания данных.

- Копирование работы доступно только её владельцу-преподавателю с trusted Origin и строгим body. Сериализация преподавателя → источника согласована с изменением состава/удалением банка; конфликт ревизии или ID не меняет оригинал. Новые ссылки создаются только на доступные неудалённые задания своего банка; пропуски явно считаются. Ученические результаты и назначения не переносятся. Повтор после сетевого обрыва не создаёт новую копию и не повторяет исключение задач; чужой исходный объект не раскрывается.

- Текущие аккаунты, доступы и файлы сохраняются; новые классы добавляются миграциями без reset БД и bucket.
- Исторический destructive cutover не является штатным способом выпуска. Production меняется только по отдельной команде с проверкой login, RBAC и asset access.
- Явное удаление выбранного класса/ученика через авторизованный API не означает разрешения на общую очистку данных.

## Фотографии решений

- `extended` не принимает клиентские баллы/ключи/критерии. Разрешение на загрузку проверяется по получателю, типу задачи в закреплённом снимке и начатой работе; завершение тестовой части независимо.
- Закрытые JPEG/PNG/WebP (до 10 МиБ, 40 мегапикселей, 10 полученных фото на задачу) выдаются через authenticated API с `Cache-Control: no-store`. Проверяются MIME, фактический формат и размеры; SVG/HTML/HEIC/PDF не принимаются. Object keys генерирует сервер из UUID, имя пользовательского файла не используется. Полный антивирус/перекодирование изображения не реализованы.
- Читать может владелец-ученик или преподаватель исходной работы; роль admin/чужой преподаватель/чужой ученик не получает доступ. UI-скрытие не является защитой: проверка выполняется и для каждого URL изображения.
- Перед S3 PUT сохраняется запись pending-владения. Фото становится активным только после полной записи и транзакционной проверки revision/`lockedAt`. Публикация проверки использует тот же row lock `assessment_recipients`, исключая подтверждение загрузки по другой ревизии.
- Tombstone немедленно закрывает удалённый/заменённый файл для чтения. Cleanup удаляет объект, но сохраняет метаданные повторов. Pending старше часа помечаются удалёнными перед очисткой; подтверждённые фото не очищаются по TTL. Opportunistic cleanup запускается при следующей операции ученика, фонового обхода неиспользуемых назначений пока нет.
- Фотографии могут содержать персональные данные/EXIF. Сервер не отправляет их внешней нейросети и не сохраняет в localStorage. Разрешённый локальный проверяющий получает их через отдельный API; передачу облачному провайдеру и сроки хранения локальных копий согласует преподаватель.

## API локального проверяющего

- Reviewer bearer-ключ не создаёт session и не открывает обычный teacher/student API; cookie не даёт reviewer-доступ. Hashing Better Auth включён, HTTP-управление плагином закрыто; выдача только broker с текущим паролем teacher.
- Ключи устройств отдельные и принадлежат создавшему преподавателю, TTL 30 дней, до 20 действующих, секрет однократный. Ключ даёт чтение/черновики/публикацию только для текущего состава выбранных классов и явных учеников. Другие получатели той же работы, управление аккаунтами/банком/классами не открываются. Состав проверяется также для фото, PDF, записей и квитанций; транзакция блокирует пользователя/профиль ученика перед повторной проверкой.
- Пустая область доступа запрещена и не означает «все». Миграция отзывает старые assignment-scoped ключи, не преобразует их в широкое разрешение. Удалённые/неактивные ученики закрыты; перевод прекращает классовый доступ, но не явный персональный. Отзыв/expiry/деактивация teacher повторно проверяются при записи.
- Черновики и публикации проверяют source/review/published ревизии под блокировками. Exact-list публикация атомарна и блокирует только соответствующие фото. Receipt хранится с записью, повтор не обходит актуальные права. Неопубликованные баллы/PDF ученику не выдаются.
- PDF закрытый, до 20 МиБ фактических байтов, проверяются MIME/header/EOF. Не гарантируются AV или полная безопасность содержимого PDF; выдача attachment. Исторические PDF не перезаписываются. Автоматической очистки неиспользованных отчётов нет.
- Ключ локального клиента находится в macOS Keychain, не argv/.env/чат/Git; HTTPS, запрет redirects, ограниченные пути и hash скачанных фото. Keychain не является изоляцией от процесса того же OS-пользователя.
- Публикацию разрешает команда человека локальному агенту, но сервер не проверяет переписку. Дополнительного веб-подтверждения нет; скомпрометированный publish-key технически может публиковать в разрешённых назначениях.
- Плагин ограничивает 120 запросов/мин на ключ; приложение — 30 записей/мин на ключ, 600 всех/150 записей на пользователя. Агрегаты приложения process-local; несколько replicas требуют общего limiter. Подробности и инструкция: [REVIEWER-CLIENT](REVIEWER-CLIENT.md).
