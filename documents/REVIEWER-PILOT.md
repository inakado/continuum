# Пилот проверки расчётных задач

Назначение: единая схема оценивания и PDF-образец для локального агента. Это пилот на восьми расчётных задачах работы «Кинематика РПД и РУД»; автономный запуск и публикация ученикам ещё не включены. Подключение и защищённые API-команды описаны в [REVIEWER-CLIENT](REVIEWER-CLIENT.md).

## Источник и область применения

Основа — предоставленное преподавателем пособие ФИПИ «Методические материалы … ЕГЭ 2026. Физика», раздел 2.2, печатные страницы 11–13. Схема предназначена для расчётных задач 22/23. Текущие №23–30 работы имеют в источнике тип 22 и максимум 2 балла. Задачи с максимумом 3/4, качественные задачи и неизвестные источники этой схемой не проверяются автоматически.

`rubrics/ege-physics-calculation-2-2026.json` хранит область, правила, страницы и SHA-256 пособия. `references/kinematics-v1.json` хранит восемь проверенных решений, источник и SHA-256 каждого условия из подготовленного пакета. Эталон общий для задачи, а не создаётся заново для каждого ученика. Текущий Reviewer API отдаёт условие, фото, номер и максимум, но не эталон/профиль критериев: в пилоте используется локальная библиотека. Одного сходного названия для её выбора недостаточно.

## Как получается оценка

Агент фиксирует записи на фото и признаки: физическая основа, пояснения обозначений, математика, ответ с единицами, отсутствие лишних неотделённых записей и продвижение к решению. Для каждого нужны цитата/место на фото и объяснение. Балл вычисляет `evaluation.mjs`; модель не передаёт произвольный `points`.

- **2** — необходимые законы верны, пояснений достаточно, необходимые преобразования/численные расчёты полны и верны, ответ с единицами верен, лишних неотделённых записей нет.
- **1** — физическая основа полная, но есть недостаток в обозначениях, математике, ответе/единицах или лишние записи. При неверном/отсутствующем ответе должен быть ход решения, направленный к ответу. Ветвление соответствует алгоритму на с. 13.
- **0** — необходимые законы неполны/неверны либо условия частичного балла не выполнены. Одна случайная верная формула или только верное число не дают полного решения.
- **Без оценки (`null`)** — запись не читается или остаётся существенная неопределённость. Это ручная проверка, а не 0.

Альтернативный верный метод принимается по своим необходимым законам. «Дано», дословное совпадение с эталоном, пояснения стандартных символов и рисунок без соответствующего требования не навязываются. Несколько дефектов из перечня для 1 балла не складываются как независимые штрафы. Соседняя задача на том же фото не считается лишней записью данного решения, если явно отделена.

`EvaluationSchema` связывает результат с solutionId, sourceRevision, referenceId и хешем условия. `bindReview` останавливает несовпадение задачи/эталона/максимума. Эта формализация не доказывает правильность распознавания и физических выводов модели: первый корпус требует проверки преподавателем. Тесты на примерах пособия проверяют схему баллов, а не качество машинного зрения.

## Разбор и оформление

Структура хранится как JSON. `render-review.mjs` формирует TeX и PDF через установленный XeLaTeX (Node.js 24+, Arial, стандартные TeX-пакеты). Пользовательские строки экранируются; формулы проходят allowlist команд, ссылки и изображения в тексте отчёта запрещены. Shell escape отключён. Временные TeX/aux/log удаляются после сборки, существующий PDF не перезаписывается.

PDF содержит номер/источник, итог, краткий вывод, ключевые записи ученика, обоснование оценки и возможное решение. Блок исправлений появляется только при наличии замечаний. Технические ID, необязательные легенды, ФИО и копии всех исходных фото в образец не включаются. Статус образца указывается при передаче файла, а не служебной надписью внутри PDF. В отчёте остаётся бренд; верхняя подпись предмета/разбора и нижние служебные подписи не выводятся. В эталоне применяются общепринятые обозначения, согласованные с записями ученика. Шаблон согласуется перед включением пакетного выпуска.

HTML-просмотр позже может строиться из того же JSON. Вводить его вместо уже поддержанного PDF на первом шаге не требуется. TeX — инструмент вёрстки PDF, а не отдельный пользовательский формат.

## Локальные файлы

Рабочий набор находится вне Git в `~/Library/Application Support/Continuum Reviewer/data/`. Папки — 0700, файлы — 0600. Первый образец использует один набор фото; повтор не создаёт очередную копию. Новая ревизия фото требует отдельной папки и новой проверки.

`cleanup-reviewed.mjs` удаляет локальные фото, рисунки, PDF, `evaluation.json` с разбором ученика и остатки управляемых TeX-сборок **только после подтверждённой публикации** точной review/sourceRevision. Сохранения черновика недостаточно. `publish --input` запускает очистку автоматически; `publish --request` получает серверную квитанцию и повторяет незавершённую очистку без новой публикации.

Допускаются только помеченные `managed.json` папки `data/<profile>/<site-hash>/<solutionId>/<jobId>` внутри Application Support. `download` создаёт маркер; `upload-draft` регистрирует PDF/операцию в той же папке и хеш `evaluation.json`. Проверяются сайт/API prefix, ID/revision, reportId, баллы, хеши оставшихся файлов и реальные пути, включая symlink-границы. Другие сайты, задачи и более новые непубликованные редакции не очищаются. Посторонние заметки не удаляются. Малые source/operation/managed/receipt JSON сохраняют условия, контрольные суммы и идентификаторы повторов, без фото/PDF/текста ученического разбора. Серверные оригиналы не затрагиваются.

Если исход публикации неизвестен или локальные файлы изменились, рабочий набор сохраняется; результат команды содержит `cleanup.retained`. Квитанция записывается до удаления, после обрыва очистку можно повторить. Загрузка фото и сборка PDF запрещены внутри Git-репозитория, даже в ignored-каталоге или через symlink. TeX/aux/log удаляются сразу после сборки через finally, включая ошибку компиляции. До согласования первого образца публикация результатов не выполняется, текущий единственный набор сохраняется вне проекта. Большой автоматически растущий кеш не вводится.

Проверки модулей: `node --test scripts/reviewer/*.test.mjs`. PDF дополнительно проверяется рендером страниц, текстовым слоем и математикой; тесты кода этого не заменяют.
